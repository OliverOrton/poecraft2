# Solver research and planning standards

For substantive research, planning and implementation. [AGENTS](../../AGENTS.md)
remains the shared operating-rules owner. A small fix needs neither a new
programme nor a research packet. Read linked material only when relevant.

## Bootstrap and authority

Generally use one fresh Pro planning session per substantial programme, followed
by a fresh Codex execution session. Context-limit or usage handoffs may continue
the same programme; they do not reset scope, experiments or spent budgets.

Start from AGENTS, [current status](current-status.md), [HANDOFF](../../HANDOFF.md)
and the selected programme. Read the active milestone's source and necessary
mathematical premises next, not the archive in chronological order. A document
already supplied with verified current contents need not be fetched again.

Pin the full available main SHA before planning and recheck before delivery.
Codex also records local HEAD, relevant working-tree changes and applicable
nested instructions. Remote main, a cached remote-tracking ref, local HEAD and
an unpushed change are different things. Do not reset or overwrite work to make
them agree. Explain unavailable local artifacts or remote verification.

Oliver selects the work and resolves ambiguous mechanics. Source establishes
implemented behavior; relevant native checks and immutable receipts establish
what was tested under which conditions. Mathematical chapters own arguments;
claims own propositions and their histories. The status page is a reviewed
navigation summary, not executable or proof authority. A disagreement is an
explicit audit item, not permission to choose the most convenient account.

## Exactness and problem identity

Keep native modeling, fixed-policy evaluation, feasible upper bounds, global
MDP lowers, auxiliary optima, heuristic values and optimality closure distinct.
A checked graph is not necessarily optimal. A fixed-policy lower is not a lower
on the MDP optimum. A stable restricted solve cannot close omitted actions.
A zero-only profile cannot promote positive working values into global lower
evidence or claim general exact closure merely because a test matches an optimum.

Bind every accepted policy to the original root, terminal semantics, tier and
threshold requirements, native data, prices and complete permitted programme
scope. Keep all positive probability, mandatory setup/cleanup, paid recovery,
observed-choice timing and properness obligations. Unknown continuations remain
unknown. Approximate features may guide Finder proposals; they never merge
native states, cached laws, certificates or probabilities without a valid native
contract. Preserve the documented numerical acceptance and coefficient scope.

Coverage with extras allowed and a clean target are different problems.
Explicit occupancy is the same target only after a stated equivalence check.
Changing goal, prices, roots, scope or capacity cannot be advertised as a
same-problem solver improvement.

## Generality and solver lanes

Derive applicability from native descriptors, legality, state/control context
and programme contracts. No production dispatch keyed to a benchmark, base
name, saved graph, fixture hash or historical state ID. Named fixtures are
legitimate tests, not an implementation strategy.

Current owns its declared search/proof capabilities. Finder proposes and checks
controllers without optimality authority. A shared helper is not automatically
an improvement to both. For each substantial change, state Current, Finder and
runtime applicability: actual consumer, required evidence, unsupported cases,
private/default/public activation. Preserve each lane's controls. A hybrid
requires an explicit compatible checked-artifact handoff; shared construction
or a mode label alone is not a qualified hybrid.

## Select work and experiments

Before implementation, state the question, current evidence, smallest causal
witness, existing owner, scope, exclusions and decision the result will inform.
Distinguish a proposal, implemented code, a reached consumer, qualification,
economic improvement and product activation. Revisit a negative only with a
new premise; preserve its exact tested scope and reopening condition.

A programme defines mandatory deliverables, conditional branches, engineering
acceptance, economic targets, stop rules and aggregate experiment allowance.
Known implementation work is not rediscovered as a blocker. Genuine semantic
counterexamples stop dependent work; independent safe work may continue. An
uncompetitive valid candidate differs from a capped or unconstructed candidate.
A substitute milestone is explicitly reported, not counted as the original.

Predeclare the cohort, actual exposure and comparison identity: source/build,
data, root/goal, prices, action/programme scope, proof profile, grammar, ranking,
attempt limits, runtime/stepping, host and aggregate/checker limits. Use the
existing resolver, corpus/Lab/reporting owners. Keep native fixed-eight,
adaptive worker, private flags and public defaults separate. A rebuilt WASM
bundle proves neither activation nor measured product benefit.

Measure the declared outcome: exact closure with its evidence, or best checked
original-root policy by time/resource budget. Also retain periods without a
policy, failures, censoring and unresolved work. Do not backdate sparse samples,
sum overlapping timers, call counts unique states, or interpret component
speedups as whole-solve wins. Timing claims need suitable matched confirmation;
reused graphs are not independent trials. Consult [benchmarking](benchmarking.md)
for the detailed comparison contract.

## Conserve model and runtime usage

Read compact status and source excerpts first; expand only to resolve a named
question. Do not repeatedly rediscover tools, reread identical files, dump huge
reports into context, or reconstruct months of history. Preserve full premises
and counterexamples when mathematics requires them; brevity cannot remove a
correctness dependency.

Reuse completed compatible evidence and existing supervision. Batch independent
reads and declared runs; execute timed cases serially. Use blocking/event-driven
execution or the longest supported waits. A yielded process handle is not a new
run. Never replace native cancellation/watchdog polling with occasional model
turns, and never build a second polling or comparison service. Client timeout
values and model names are not universal constants: verify the installed
capability when needed and record limits honestly. Detailed commands and waiting
rules belong to [tooling](../foundation/tooling.md).

Use focused checks while developing and layer-appropriate final validation, not
full suites at every phase. No Simulator for unchanged strategies. When fresh
execution qualification is genuinely required, follow AGENTS' approved trial
count and report censoring. Keep token-saving distinct from suppressing necessary
native checks. No arbitrary minimum run duration is a success criterion.

## Handoff and closeout

Use one living programme record and a short HANDOFF. Preserve accepted arguments
in their canonical chapters as work lands; link original evidence once. Classify
material inputs as incorporated, duplicate, contradicted, scoped-negative,
open, unavailable or out of scope. Repetition across chats is not corroboration.

Before handing off, record source/local state, actual completed and unrun work,
process handles, artifact locations/identities, spent budget, the next concrete
step and its gate. Before closing, update affected current-status rows and
canonical owners, record private/public and native/WASM qualification separately,
and leave the next programme recommended—not implicitly authorized. Use the
[existing handoff template](../_templates/solver-research-handoff.md) only as needed.
