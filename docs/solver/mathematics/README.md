## The whole argument

The target is the declared native problem, not whichever rows have been generated.
A returned strategy supplies an upper only under its executable, proper, priced,
entry-specific and numerical contract. A lower needs an optimistic relation that
covers every permitted alternative and every represented source member. Compatible
bounds can establish a gap or exact closure only under the stated endpoint and
scope conditions.

| Boundary | Sufficient mathematical reason | Native correspondence still required |
|---|---|---|
| Native behavior to semantic state | Retain every future-observable distinction | Exact item/control identity, goal predicate and choice timing |
| Semantic states to shared representation | Exact equivalence or explicit optimistic domination | Complete member/action coverage, not one representative |
| Policy to upper | Proper finite-cost execution of the evaluated graph | Full routes, outcomes, prices, artifact and entry identity |
| Optimistic model to lower | All-action inequalities and a valid stopping argument | Native coefficients, event/member coverage and independent boundaries |
| Bounds to retirement | A competitor cannot improve a compatible proper incumbent | Same source/scope/generation and the actual strict tie rule |
| Interrupted work to retained evidence | Previously established premises remain true | No stale rows, conflicting snapshots or unavailable resource ownership |
| Complete proof to exact publication | Compatible lower/upper and complete target accounting | Actual proof source, evaluated artifact and numerical contract |

owners. This chapter explains their obligations. It does not replace that source
map or make a documentation status into runtime authority.

## Three different kinds of conclusion

**Validity:** why a bound or strategy is justified under explicit assumptions.
**Progress:** which finiteness, properness and service assumptions imply eventual
completion. **Efficiency:** what a comparable experiment measured. A valid lower
can be weak; a sound algorithm can be expensive; a resource refusal does not
refute its mathematics.

A derivation may be newly reconstructed rather than the historical reason code
was written. A recorded experiment was performed by the source named in its
artifact, not automatically rerun by this document's author. A conditional
mathematical acceptance is not proof that every native application satisfies its
premises.

[Open obligations](../research.md#open-obligations) name those remaining bridges.
The backbone integration itself is complete; it did not settle all public-mode
nontermination semantics, all-member native relations, the entire program grammar,
an all-requests convergence theorem, or every numerical endpoint.

## Where knowledge lives

The ledger owns immutable proposition identity, statement, preconditions and
history. The linked chapter owns the derivation. Original archives own experiments
and source-era explanations. Current mechanism pages own implementation contracts.
Generated views own quantitative presentation from declared input evidence.

Removing an implementation does not remove its useful counterexample. Keeping a
counterexample does not require keeping an unused implementation in the build.
No new handwritten current-status table is needed.

The distinctions used repeatedly are fixed-policy value versus optimum; native
lower versus coefficient feasibility; exact equivalence versus optimistic
abstraction; admissibility versus current-model feasibility; a valid result versus
useful progress; and an auxiliary-policy ceiling versus a native executable upper.

## Task-sensitive review

For a lower change, use [lower-bounds.md](lower-bounds.md), the affected claim and
its producer/checker/consumer. For compilation, use [the policy argument](policies.md#compilation).

[search-and-resumption.md](search-and-resumption.md).

The research exchange and existing commands are documented in
[research](../research.md#handoff) and [benchmarking](../benchmarking.md#research-series).

its actual argument and disposition, not only an implementation instruction.
