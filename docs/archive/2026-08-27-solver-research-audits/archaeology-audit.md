## Evidence and authority rules

I use these labels throughout:

* **M — measured:** directly recorded by an experiment, result file, fixture, or current implementation.
* **I — inferred:** conclusion from the measured lineage and current source ownership.
* **P — proposed:** appears only after the archaeology matrices.

The archive is historical evidence, not current sequencing authority. The current roadmap is explicitly deferred, and archived “next step” language is superseded by current stable contracts and the handoff.

Three present-day authority constraints materially affect every reopening decision:

1. A finite public upper belongs to the **independently evaluated emitted strategy graph**, not to a coarse value, candidate policy, or historical artifact.
2. While incremental action generation remains open, its restricted optimum is not a global lower.
3. A development checkpoint is iteration infrastructure, not proof authority. The current format captures a completed coarse graph and reruns Bellman, strict refinement, compilation, and evaluation.

Current source ownership is now reasonably well separated. The important owners for this audit are:

* coarse transitions: `engine/src/solver_calc.cpp`, `solver_reforge.cpp`;
* action-envelope scheduling: `solver_action_envelope_ledger.hpp`, `solver_solve_expand.cpp`, `solver_solve_incremental.cpp`;
* carrier ordering and anytime scheduling: `solver_solve_priority.cpp`, `solver_anytime_scheduler.hpp`;
* lower proofs: `solver_solve_bounds.cpp`, `solver_solve_carrier_pattern.cpp`, `solver_solve_operator_proof.cpp`, `solver_solve_envelope_proof.cpp`, `solver_proof_pattern_manager.hpp`;
* strict closure: `solver_refinement_*`, `solver_policy_refinement.cpp`, `solver_policy_oracle_*.inc`;
* executable publication: `solver_solve_constructive.cpp`, `solver_solve_audit.cpp`, `solver_compile.cpp`, `solver_eval*.cpp`;
* replay: `solver_development_checkpoint.cpp`, cache compatibility in `solver_solve_expand.cpp`, and the native C API in `solver_api.cpp`.

Where an experiment restored or deleted its prototype, the tables say so and list the present source owner rather than implying that the old code survives.

### Four-plus closure conclusion

The historical phrase “state explosion” is too coarse to be useful now.

The sequence was:

1. first-row state growth;
2. then root-action scheduling;
3. then selected strict-row construction;
4. then repeated strict reconstruction;
5. then persistent quotient growth;
6. and finally retained strict proof/quotient memory.

The current PDR boundary is **not** the July broad Chaos graph, **not** global Fracture observation, **not** automatic-action omission, and **not** repeated strict-session reconstruction. Those premises have been changed or superseded.

# 7. Five most promising genuinely changed premises

## 1. The native experimentation substrate is already present

Earlier plans treated native iteration, durable incomplete runs, and replay as future infrastructure. At this ref:

* native build/test iteration is established;
* the corpus runner is a real resumable, memory-aware local queue;
* partial trajectories survive watchdog cleanup;
* completed coarse graphs can cross processes with strict identity checks.

The remaining native/headless work is therefore mostly orchestration and the deeper replay seam, not a fresh solver harness.

## 2. The PDR wall moved from exact-row work to retained strict-proof memory

This is the strongest changed premise.

The current witness no longer dies primarily in a 50M broad-row computation. Cooperative V3 rows and frontier-yield repair reduced strict work to 3,507,568 and exposed 846,846,750 bytes of proof store plus quotient ownership before the 1 GiB stop.

That makes old broad-row tuning, cap increases, and availability-frontier retries poor archaeological fits for the current wall.

## 3. Persistent strict/quotient ownership exists

The negative carrier-row replay experiment correctly showed that caching exact rows across rebuilt generations was expensive and ineffective. The later persistent quotient session changed the premise by eliminating the rebuild itself:

* one strict session;
* zero full restarts;
* localized insertion and invalidation;
* 60.4% fewer open alternatives.

The remaining problem is retained live ownership, not the absence of an incremental strict architecture.

## 4. Retention-aware lower proofs now have a measured successful consumer

The pre-expansion goal-mask MDP, generic descriptors, transferred coarse bounds, and probability-only partitions all failed to separate useful work. Action-specific patterns paired with an exact proper local upper retired 79,799 obligations without changing the incumbent.

That result changes the lower-bound question from:

> “Can a richer abstract lower raise the root number?”

to:

> “Can an exact action-specific successor relaxation close or retire the currently dominant obligations?”

The latter has already worked on one owner case.

## 5. Executable subgoal planning now has trustworthy components

The first carrier planner failed because an attractive abstract policy could not be compiled with conserved probability mass. Since the earliest options proposals, the codebase has acquired:

* exact carrier ladders;
* joint completed-row proper policies;
* immutable candidate retention;
* typed carrier/action projections;
* a monotone incumbent portfolio;
* authoritative independent compilation and exact evaluation.

That makes an exact-row-backed options planner genuinely different from the failed coarse planner. It does **not** make abstract carrier policies safe by themselves.

# 8. Candidates that should remain closed

The following conclusions survived later architectural changes:

* **Original pre-expansion probability lower:** closed. It omitted blocker and preservation state that was behavior-bearing.
* **Generic unresolved descriptor:** closed. Huge descriptor coverage yielded zero strict separations.
* **Success-only partial broad-row upper:** closed. It produced zero proved goal mass at the actual boundary.
* **Shared cross-action reforge DAG:** closed. Exact parity did not reduce scalar lane work and made runs slower and larger.
* **Cross-generation carrier-row replay:** closed. It retained nearly 7× the memory while leaving the dominant repeated work.
* **Global carrier comparator and generic anytime scheduler profile:** closed. Both failed matched general controls despite attractive target-case results.
* **Original executable carrier planner:** closed. Its coarse policies were not mass-conserving executable artifacts.
* **Same-side exact closure:** closed because it is completed, not because it failed.
* **Fracture-local coarse parent:** closed because it qualified and is already part of the architectural lineage.
* **Learned transition models or direct opaque graph generation:** remain rejected by the project’s own ML architecture; the native engine and independent publication path must remain authoritative.

# Bottom line

The archaeology does **not** support returning to broad-kernel compaction, generic carrier descriptors, global scheduling heuristics, or historical strategy injection.

The strongest current sequence supported by changed premises is:

1. establish a faithful scheduler-aware or first-strict-partition replay seam;
2. use it to measure the PDR strict proof/quotient memory owner that the stopped experiment never reached;
3. separately test action-specific retention proofs against those dominant obligations;
4. treat executable carrier/options planning as an exact-row composition problem with compilation and evaluation inside the planning boundary;
5. build the native experiment interface around the already-retained runner rather than around the web application.

Learned guidance remains plausible, but it is downstream of the executable classical planner and benchmark, not a substitute for resolving the present proof and policy-authority boundaries.
