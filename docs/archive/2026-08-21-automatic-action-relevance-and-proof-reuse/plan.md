# Automatic Action Relevance And Proof Reuse

**Status: stopped precisely on 2026-08-21 at the declared native-primary
boundary.** See the [result](result.md).

Parent: [stopped four-T1 result](../2026-08-21-four-t1-automatic-envelope-qualification/result.md)

## Objective

Reduce the exact automatic-action envelope before and during strict closure
without removing any mechanically legal potentially cheaper strategy. Reject
an action early only through impossible applicability, an unchanged complete
kernel, exact price dominance, or a generation-valid Bellman bound. Reuse one
proof across carrier/action obligations only when their complete exact
behavior and continuation authority agree.

The checked target is the Allflame four-natural-T1 Conquest Lamellar case.
Five-T1 recovery, new mechanics, heuristic action removal, compiler-only graph
compaction, cap-only increases, and weakened publication are out of scope.

## Gate 0 — Existing Authority And Baseline

- Audit previous Eldritch, protected-side, temporary-bench, Imprint, kernel-
  reuse, and rejected batching work before editing.
- Freeze action counts and costs by phase and kind. Distinguish registry
  filtering, carrier synthesis, exact-kernel rejection, sparse-row collapse,
  Bellman classification, and strict proof.
- Preserve the current result: 717/717 upper passes start; the raw executable
  upper is `3759.5969190423507`; 17,584 obligations remain open; and one
  Imprint carrier defers at the 256-program search allowance.

## Gate 1 — Construction-Purpose Rejection

- Retain the existing protected-side authority: a satisfied goal must exist
  on the protected side, the other side must contain a reachable missing
  target, and the protected complete kernel must differ from the unprotected
  follow-up. Do not duplicate or weaken it.
- For parent-context Eldritch intents, apply the same generic price, duplicate-
  kernel, and incumbent-dominance checks already used by other automatic
  options. Reject setup/final programs whose complete exact behavior is
  neutral or exactly price-dominated.
- Treat useful occupancy/blocking state as relevant whenever it changes the
  complete exact kernel; do not equate “not a goal modifier” with “useless.”

## Gate 2 — Imprint Eligibility And Search

- Before word search, reject a checkpoint carrier only when no supported
  priced primitive can create a risky improvement relative to restore, or an
  existing exact price bound closes the grammar.
- Replace repeated action-word enumeration with a cooperative price-ordered
  search over unique exact checkpoint/support kernels. Keep the cheapest
  representative for equal behavior and preserve primitive multiplicities,
  influence legality, resource accounting, price-bound closure, cancellation,
  and owned-memory checks.
- The real state-928 witness must close or stop on a new measured boundary;
  simply raising `max_imprint_program_work` is not acceptance.

Audit correction: the implementation already searches collision-checked
unique exact support kernels and maintains a componentwise primitive-count
Pareto frontier. The proposed replacement was therefore not implemented.
Gate 2 instead retained an explicit work-frontier witness; state 928 remains
open at the existing 256-program work boundary.

## Gate 3 — Cross-Carrier Proof Reuse

- Define a collision-checked equivalence signature over the complete sparse
  row behavior, immediate resource vector, owner-relative self semantics,
  relevant carrier observation, and successor continuation projection.
- Share Bellman classification across equivalent obligations. One improving
  or non-improving verdict may fan out only while its lower/upper generation
  and continuation authority remain identical; otherwise split/re-evaluate.
- Preserve deterministic first-row authority for exact ties and retain every
  distinct cheaper variant.

Audit correction: one strict obligation already covers every exact carrier in
its quotient cell, while certified rows and payloads already use collision-
checked semantic identities. Cross-cell reuse cannot be justified merely by
action identity because continuation projections differ. No broader reuse was
retained.

## Gate 4 — Bound-Directed Early Rejection

- Reuse the certified restricted/executable upper already owned by the
  incremental scheduler. Reject a remaining row when its optimistic exact
  lower Q is no better than that carrier upper.
- Version conditional verdicts by the lower/upper generation. Reconsider them
  after any admitted row, bound change, or new successor expansion.
- Scheduling priority may improve responsiveness but cannot substitute for
  closing every retained proof class.

## Gate 5 — Qualification

- Run the native build and focused automatic-action, S8.3, policy-refinement,
  and solver controls once after implementation.
- Run one checked 300-second native four-T1 primary. Compare action counts by
  phase, open proof classes, upper/lower authority, strict dimensions, maximum
  public step, memory, and termination.
- If and only if native closure succeeds, independently evaluate the compiled
  policy, run 10,000 simulator trials, rebuild release WASM, and run
  proportional downstream acceptance. Otherwise stop, update the result and
  `HANDOFF.md`, and do not run the full pipeline.

Gate 5 hit that stop condition. The checked retained-source primary expired at
300.25 seconds with the same `3759.5969190423507` executable upper, zero
global lower, and 17,584 open actions. Release WASM, primary verification,
web acceptance, and the full pipeline were not run.
