# Persistent Strict Frontier Growth

**Status: stopped on 2026-08-21.** The carrier-row replay experiment was
measured and removed after failing Gate 3. See [result.md](result.md).

Parent: [Verified Interim Upper Publication](../2026-08-21-verified-interim-upper-publication/result.md)

## Objective

Stop paying exact mechanic work again when competitive strict successors grow
the quotient frontier. Preserve every current proof boundary: complete exact
carrier coverage, collision-checked action identity, split-only partition
generation, target/source invalidation, current-Q alternative classification,
proper executable publication, and independent compiled evaluation.

The checked target is the Allflame four-natural-T1 Conquest Lamellar case. It
currently rebuilds approximately 5,820-, 5,924-, and 5,961-state strict passes,
shows a verified `3745.7295960574743` upper, and expires after five minutes with
17,584 automatic alternatives still open.

## Gate 0 — Existing Authority And Baseline

- Audit the original competitive-frontier closure, proof-carrying quotient,
  lazy-alternative, and later proof-reuse work before editing.
- Distinguish reusable exact carrier/action mechanics from non-reusable cell
  projection, partition, Bellman values, proof generations, and verdicts.
- Freeze the current 300-second trace, strict pass sizes, action counts, upper,
  lower, memory, and public-step behavior.

Audit result: a frontier restart retains only exported frontier seeds and the
compiled assertion. The strict oracle, completed carrier-local alternative
rows, partition, Bellman graph, and proof store are reconstructed. Existing
cell-wide proof reuse is already collision-safe within one pass. Retaining the
oracle alone is insufficient because completed compact rows deliberately
release their underlying mechanic-kernel storage.

## Gate 1 — Exact Carrier-Row Replay

- Retain a work-local row only after one exact carrier/action evaluation
  completes. Key it by the full exact source identity and full alternative
  action identity; collision-check the retained source and all replay payload.
- Store physical successor `AbstractState` values and exact probabilities, not
  pass-local strict locators or quotient cell ids.
- On a later frontier pass, re-intern the physical successors into the new
  strict child, then run canonical row ordering, cell projection, coverage,
  partition, Bellman installation, proof generation, and Q comparison again.
- Keep the cache inside the existing solver memory ledger. Cache refusal or
  eviction is an optimization miss, never proof authority or a solve failure.

## Gate 2 — Generation And Coverage Regressions

- Prove replay rejects a source or action identity mismatch.
- Prove successor locators are rebound in the new strict context and the same
  row cannot bypass carrier-wide equality or merged-observation checks.
- Prove a cell split or Q-generation change rebuilds the proof/verdict even
  when its carrier mechanics replay.
- Preserve cooperative stepping, cancellation, and monotone verified upper
  publication.

## Gate 3 — Native Qualification

- Run one native build and the focused quotient/refinement/solver suites after
  implementation.
- Run one checked 300-second native primary. Compare time to first strict
  upper, frontier-pass count and dimensions, fresh versus replayed carrier
  rows, open alternatives, largest public step, memory, and termination.
- Reject the change if replay does not materially reduce repeated exact work,
  increases the public-step boundary, loses action/proof accounting, changes a
  verified exact row, or merely shifts the stop to memory.

## Gate 4 — Conditional Downstream Acceptance

- If native behavior is retained, rebuild release WASM and run proportional
  non-visual WASM/web acceptance.
- Run 10,000 primary simulations only if the solve finishes and emits a final
  compiled strategy. Do not verify an unfinished progress-only incumbent.
- Do not run the full repository pipeline unless this boundary reaches a
  stable merge-ready result that crosses the declared acceptance threshold.

## Non-Goals

- No action-family removal, heuristic legality, price change, cap-only
  increase, lower-bound promotion, compiler compaction, or strategy-schema
  change.
- No state-928 Imprint grammar rewrite or five-T1 recovery in this boundary.
- No cross-solve/reprice cache and no reuse across different goals, economies,
  option sets, artifacts, or solver requests.

## Stop Conditions

- A replay payload contains a quotient cell id, pass-local strict locator, or
  conditional Bellman verdict.
- A row replays without full source/action collision validation.
- Partition, coverage, or proof generation is reused across a frontier split.
- The checked primary still repeats essentially the same exact carrier work
  with no material wall/work reduction; record the next precise owner instead
  of layering another cache.

## Gate Result

The final stop condition fired. Collision-checked replay of completed positive
and negative carrier/action rows preserved exact successor identity across
strict contexts, but it did not materially reduce the checked work boundary.
The corrected five-minute run reached the same upper and almost identical
final-work count, while time to the first strict upper regressed and estimated
peak ownership increased by nearly 600 MiB. The implementation was removed.

The next precise owner is not another retained-row cache. It is in-place
extension of one live strict oracle, locator set, partition, Bellman graph, and
proof store when a competitive successor appears, with localized coverage
growth, split-only generations, and affected-proof revocation.
