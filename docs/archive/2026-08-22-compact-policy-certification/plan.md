## Objective

Make exact certification of the checked four-T1 solver's cheaper selected core
policy materially smaller or faster without weakening executable-policy
publication. The Imprint-disabled control selects an abstract policy at
`2889.7687877196995` chaos, but its direct compiled assertion formerly reached
the Calculator's 5,000-state optional-refinement boundary before proving
proper, zero-off-policy execution. Calculator therefore published the
independently verified `3759.9822404728984` fallback.

## Fixed boundaries

- Do not publish the direct policy unless compiled exact evaluation completes,
  proves proper execution, has zero off-policy mass, and has complete pricing.
  A solver/exact cost mismatch remains a bounded result and cannot be called
  exact.
- Do not solve the milestone by only raising the optional-refinement boundary.
  The accepted implementation must also reduce work or representation and
  must use measured closure size, time, and memory to justify any new product
  allowance.
- Preserve the completed carrier-local Imprint refusal behavior and the normal
  enabled Calculator scope.
- Preserve engine ownership of observations, transitions, and mechanics.
- Do not broaden this milestone into five-T1 recovery, action admission,
  strategy UI, or visual review.
- Do not run the full repository pipeline. Run the final changed native layer,
  rebuild release WASM if browser-visible native behavior changes, and run the
  downstream non-visual web checks once at acceptance.

## Baseline witness

Use the pinned Allflame four-natural-T1 Conquest Lamellar request with only
`consider_imprint_programs: false` for the direct-certification measurement.
The accepted predecessor report records:

- selected coarse cost/lower: `2889.7687877196995`;
- published verified fallback: `3759.9822404728984`;
- selected coarse states/actions: 7,152 / 28;
- direct assertion graph: 3,208 nodes / 7,139 edges, including 1,800 policy
  routers and 1,356 policy regions;
- exact evaluator stop: 4,990 discovered pairs at the 5,000-state boundary;
- observation/compatibility counterexamples: 914;
- pair discovery stopped before partition or component solve.

## Work plan

1. Characterize pair discovery by compiled node kind, observation class,
   operation row, and repeated successor/route shape. Confirm whether growth is
   caused by compiler duplication, evaluator key over-discrimination, or
   genuinely distinct item/action behavior.
2. Identify one behavior-preserving compaction with an explicit equivalence
   argument. Prefer existing canonical identities, shared route signatures,
   stable kernels, or quotient keys over a new heuristic.
3. Add a focused regression that fails on the redundant representation and
   proves identical selected actions, transition probabilities, terminal mass,
   and expected cost after compaction.
4. Measure the direct graph at 5,000, 100,000, and the standalone evaluator
   ceiling. If it completes within the existing main-solve state envelope and
   memory cap, set the product allowance from that measured closure rather
   than an arbitrary number.
5. When direct exact evaluation produces a cheaper executable bounded upper,
   publish it without a redundant strict-lift traversal. Then run exact graph
   evaluation plus 10,000 simulator trials and rerun the enabled primary,
   Warlord, and Imprint retry controls proportionally.
