# Exact Hinekora Lock information state: persistent previews, conditional laws and paid renewal

Research and planning packet, 5 October 2026. Lane: locks. No implementation or runtime qualification is claimed.

Reviewed mathematical amendment: finite per-epoch outcome support does not imply finite belief/history closure across persistent hidden epochs. L1 explicitly selects finite latent-product evaluation. Refused observation preserves the prior selected request, and refused application retains live foresight. These are report qualifications, not measured product defects; no production change or runtime execution accompanies them.

## Decision in brief

Preserve the released Emulator lifecycle and its explicit approximation label. Design a distinct native information-state contract for solver use. A paid Lock persists while multiple normalized requests are inspected; inspection is free and stable; a successful action consumes the entire Lock; declining, destroying a handle, reloading, clearing a marker or inspecting again cannot produce a new outcome. The authorized solver removal operation costs **one Divine Orb** and must represent an actual item modification before another paid Lock. Its item transition must be specified, not replaced by a free return to the old item.

The exact design is conditional on a **joint outcome law**, an observation/disclosure contract and a renewal contract. The existing native marginal for each currency and the current independent-cache simulation do not identify that joint law. Treating them as exact would invent cross-action independence. A finite joint model is implementable and exactly checkable within its declared model; its agreement with the game is a separate owner/native correspondence obligation. No game-exact adaptive Lock policy can currently be admitted from the examined evidence.

The smallest decisive counterexample has two requests, each with success probability one-half. If their previews coincide, the specified inspect-both/accept-any-good controller succeeds in a Lock round with probability one-half; with independent previews it succeeds with probability three-quarters; with complementary previews it succeeds with probability one. These models have identical individual currency marginals. With synthetic one-Divine Lock, removal and selected-action costs, the controller's paid renewal costs are respectively **4, 8/3 and 2 Divine**. These are exact calculations for synthetic controllers, not measured PoE values or optimality claims.

Recommended next milestone: specify the native conditional-law and paid-removal interfaces, then falsify a tiny finite checker against correlated and complementary tables. Keep the checker separate from proposal search. L1 selects a finite latent–item–controller product with all persistent hidden context included; finite belief/history closure must not be inferred from finite items, requests, latent states or controller memory. Start with a finite authored controller and at most two requests, followed by a private Finder consumer and, separately, a Current upper-policy consumer. Use a zero global lower for any expanded nonnegative-cost scope unless a new lower proof is supplied. Full-scope closure, product activation and game coupling identification remain later gates.

## 2. Mechanics established, semantics unmeasured

### 2.1 Lifecycle that the solver must preserve — S

The modern apply operation chooses no currency. It reserves the finite normalized native allowlist domain before observation. The domain includes existing ordinary supported currencies, runtime Essence configurations, distinct Influence Exalt codes and Eldritch Ember/Ichor tiers 1–4. Aliases resolve to the same ActionParameters. This is a descriptor/domain rule, not a base-name recipe.

Each reservation contains a complete native item preview and ActionOutcome. Application samples a private copied RNG stream and commits its state only after successful overall creation. Inapplicable/refused entries publish no applied result and restore that entry's RNG position. Observation returns the existing reservation; it does not draw, modify the live item or charge currency. It also sets the selected request, so the UI's selected commit must retain that control state. Observing a second request does not retire the first reservation. Ordinary application of a supported modern request uses its reservation even when another request was most recently selected. Selected commit requires a selection and consumes the whole foresight. [S04–S06]

An applied currency consumes foresight even when its visible output equals its input. A refused action preserves it. A successful allowed modifying operation, including existing deterministic Scour/remove-crafted paths, ends it. Raw editor invalidation ends the handle but does not necessarily authorize a fresh Lock on an unchanged item; the no-refresh tombstone is material. Destruction/release are resource-lifetime operations, not paid removal mechanics. The native identity comparison includes numerical rolls, metadata and item fields but excludes ABI padding. A copied marked item cannot acquire the original context/address identity. [S04–S05, S11]

Checkpoints preserve reservations, including unseen outcomes, and validate runtime, base, level, count law and configuration before atomic replacement. They serialize full outcomes, not RNG seed/state. They are Emulator replay records, not certificates of probability, reachability or solver observations. Legacy fixed-request checkpoints continue to accept only their original normalized observation; modern approximate snapshots are not silently migrated to exact game models. [S03–S05]

The actual UI pays a Lock on apply, records each preview at zero cost and pays the selected currency on its applied action. The controls explicitly disclose approximate independent cached previews. Missing UI prices can remain visibly unpriced; an exact cost-complete solver upper cannot silently inherit that permissive display behavior. [S06]

## 3. Proposed exact semantic model — P with conditional derivation D

### 3.1 State and probability authority

Fix the original semantic request I: physical root, native goal/terminal predicate, rarity/tier/threshold/cleanup requirements, permitted primitive/programme scope, frozen runtime/data/law, observation timing, complete prices and numerical contract. Invocation limits are a separate identity B. A Lock extension changes programme and information scope; it is not an ordinary same-scope solve unless I explicitly includes it.

Let x contain every native item/control/resource field relevant to legality, probabilities, goals and future costs. Let A(x) be the finite set of normalized preview requests selected by the permitted native scope. Introduce a latent state z and an owner-approved law mu_I(z | x, h), where h denotes any persistent hidden context required by the model. For each request a, the contract supplies:

- applied/refused status and the complete committed item/result F_a(x,z);
- the public observation O_a(x,z), possibly less informative than F_a;
- actual resource consumption C_a(x,z), charged on application;
- successor hidden context and ordinary continuation law after consumption;
- the paid-removal transition R(x,z,dx',dh'), with one Divine consumption;
- the next-Lock law after the real removal/consumption successor.

The outcome vector (F_a : a in A) is a convenient latent representation; it does not claim a physical vector is generated by the game. A finite probability table, a finite shared-latent construction, or an exact conditional oracle can implement the same contract. Each has to reproduce all relevant observations, commits and future conditional laws, not merely its individual marginals.

The controller's information state is (I, x, phase, E, H, b, selected, m). Here phase distinguishes unlocked/live/ended-with-no-refresh states; E is epoch/provenance identity; H records normalized observed requests and public results; b is the posterior on latent/persistent hidden state; selected records selected-commit control; m is authored program memory. The implementation may derive b from an exact H and model identity instead of storing floating vectors. Equal item bytes and equal selected request do not imply equal b. If epochs are exchangeable after a proved reset, absolute epoch numbers can be removed from mathematical state while retaining transport provenance; that removal needs a relation, not a hash match.

On consumption or paid removal, retire the old epoch's reservations but retain any posterior information relevant to persistent hidden context. The notation U below denotes an unlocked **information state**, not necessarily just an ordinary item x. Only a proved reset/Markov correspondence permits dropping the old history and using the existing item-only continuation value. Otherwise the hidden-context belief remains part of the next ordinary-action and next-Lock law. A consumed Lock is a lifecycle fact, not a proof that all probabilistic dependence has vanished.

**Nonanticipativity:** the policy may use x, its actual observations H and program memory. It may not branch on unseen reservations, hidden z, internal RNG state or an unobserved preview merely because the evaluator has those data. Correlation may justify an inference about another outcome under a selected model; this is still a conditional calculation from H, not direct access to hidden storage.

The belief-state construction is consistent with Kaelbling, Littman and Cassandra's POMDP state estimator and policy-tree account: probability over hidden state summarizes history when the observation/transition model is correct. Their discounted optimality results are not imported as an SSP closure theorem. [Primary paper, sections 3.2–3.4 and 4.1](https://people.csail.mit.edu/lpk/papers/aij98-pomdp.pdf). The finite SSP and paid-controller arguments below are derived explicitly and use the repository's properness contract.

### 3.2 Observation and commitment rows

For a new request a and public result o, define

    p(o | b,a) = sum_z b(z) 1[O_a(x,z)=o]
    b'(z) = b(z) 1[O_a(x,z)=o] / p(o | b,a), when p(o | b,a)>0.

If observations themselves are stochastic, replace the indicator by the approved observation likelihood. Repeated observation of an already known deterministic request preserves the public result, posterior and physical/epoch state, at zero cost and with no draw; a successful modern observation still selects that normalized request, so the full control row is an identity only when it was already selected. A refused observation is not a new success sample. If refusal can depend on hidden state, its visible status is an observation symbol with its true probability; it cannot be removed and the remaining mass normalized. Public refusal status/history and native selected-request mutation are separate: the current native observation path returns on unsupported/inapplicable requests before changing f.action, f.preview, f.outcome or f.selected. A successful modern observation selects a; refusal retains the prior selection, including an unselected state. [S05, lines 373–379]

A commit of a uses its conditional outcome law given b. With full public preview F_a already observed, the item/result is deterministic. If a is not observed or the public map hides relevant fields, commit uses the conditional distribution rather than a clairvoyantly selected value. Successful application ends the entire live Lock, charges that action, and enters its real continuation. Refusal preserves the live epoch. A policy that repeatedly commits an inapplicable action forever is an improper zero-cost loop, not an executable finite upper.

Let U denote an unlocked cost-to-go and W a live-Lock cost-to-go for an allowed proper policy class. Schematically,

    selected'(a,o) = a for a successful applied modern preview;
                      previous selected for a refused observation
    Q_observe(a) = sum_o p(o|b,a)
                   W(x,H+a:o,b',selected'(a,o),m')
    Q_commit(a)  = sum_z b(z) [
                   1[application applied] * (C_a + U(real consumed successor))
                 + 1[application refused] * W(real live refusal successor) ]
    Q_remove     = price(one Divine) + E_b[U(real modified successor)]
    Q_apply_lock = price(one Lock) + E[W(new paid epoch)]

These are semantic equations, not new implemented solver rows. Successor information states are conditioned on the publicly returned result, never on privileged knowledge of the individual summand z; latent atoms with the same public result contribute to the same posterior successor. The refusal successor keeps the physical item, live epoch, reservations and selected request; any publicly returned status may update controller history/posterior/memory according to its exact disclosure contract. Current refused observation/application consumes no currency. Explicit native selected commit with a valid selected applied reservation uses that reservation; a missing selection refuses, and ordinary requested currency application can also refuse. Neither refusal enters U or consumes the Lock. Unknown continuation values remain unknown. A root scalar from a checked unrelated policy is not an entry value for every consumed/removal outcome. Costs for setup, cleanup, replacement resources, remnant crafts, failed routes and any return to the original root belong in U or the explicit program, and cannot disappear inside an option summary. [S05, lines 272–277 and 478–495; S09; R02]

The displayed Q_remove row assumes the selected paid removal successfully performs its modifying transition. A removal contract with refusal/failure outcomes needs the same explicit live/ended successor split and its actual event charges; it cannot send refused mass to U. Likewise Q_apply_lock assumes admitted successful application: an inapplicable creation keeps its prior state with no Lock consumed under the current native lifecycle. These success-row assumptions do not erase any required refusal branch from a complete checker.

An observed cached goal is not a terminal item. Success is the original native goal applied at the actual execution/terminal boundary. Any live-flag or leftover-resource terminal requirement must be retained from I; do not invent an additional cleanup requirement or silently omit one. A root already satisfying its native goal need not buy a Lock. An imported live paid root needs its actual observation history and probability authority; the cost already paid is sunk only for a clearly labelled remaining-cost request. Original-root total cost must include acquisition of that Lock.

### 3.3 Why this is a sufficient information state — D1

Premises: the law contract includes all hidden context affecting future observations, actions and epochs; the public history is complete; request normalization is stable; transitions and prices are fixed under I; and native legality/terminal truth are preserved.

Proof sketch: histories with the same x, phase, b, selected and m have the same conditional law for every permitted next observation and commit. Their costs, legal decisions and public successor information states therefore agree. Conditioning on the next observation updates b by Bayes' rule; consuming/modifying updates the physical/hidden state by the supplied transition. Induct on finite histories to obtain identical public path/cost laws. For proper finite-controller graphs, nonnegative costs and transience then give the same expected total cost. The argument fails if persistent hidden context is omitted or if the controller inspects hidden z.

A smaller exact quotient is possible only if every member has equal terminal truth, action/choice availability, expected cost and probability into every successor equivalence class, including conditional observations and renewal. Matching one currency row or displayed goal mask is insufficient. This is an application of CLM-0005 with a new state domain; it does not establish native admission by itself. [S09–S10]

### 3.4 Finite hidden state does not guarantee finite belief closure — D7

Let a persistent hidden type T be selected once, with equal prior probability on L and H. Conditional on T, successive paid epochs are independent: a round succeeds with probability p_L=1/4 or p_H=3/4. Use one item/retry context, one normalized request, binary preview results and a finite controller that commits success and otherwise pays removal and retries. Every failure returns to the same visible priced item, but the hidden type remains fixed. This is an exact synthetic model, not a game mechanism or a native run.

After n consecutive failed epochs, Bayes' rule gives

    P(T=H | n failures)
      = (1/2)*(1/4)^n / [(1/2)*(1/4)^n + (1/2)*(3/4)^n]
      = 1/(1+3^n), for n=0,1,2,... .

All these posteriors are distinct, and every finite failure history has positive probability. The predictive next-round success probability is 1/4 + [1/2]/(1+3^n), so merging all histories with the same visible item and controller node also changes the conditional law. The histories are infinite in number even though the item, requests, hidden types, per-epoch outcomes and controller are all finite. Both hidden types have positive success probability, so this example does not depend on an improper trap: it exposes belief-state cardinality, separately from D5's persistent always-bad-type counterexample.

A history/belief enumerator therefore needs a proved finite reachable posterior closure or a valid finite behavioral quotient. Finiteness of the underlying hidden Markov model or controller does not provide that proof. Rounding probabilities, resetting the prior after paid removal, or merging identical displayed items is not an exact closure argument. With no finite closure proof, exploration must stop at its declared cap and refuse complete exact certification while retaining unexplored positive-mass continuations.

By contrast, this fixed finite controller can be evaluated on the finite hidden product: retain T, the current epoch's finite latent outcome, physical/lifecycle state and finite public controller memory. A new epoch samples its conditional law given the retained T; it does not draw T again. Summing the two original type-weighted path laws evaluates the same observable controller without creating one state for every posterior. This is the selected L1 construction, conditional on a complete finite Markov latent contract. A controller that needs an unbounded posterior or failure-count decision state does not acquire finite memory by this construction and is outside L1 unless independently reduced.

## 4. Full inspection, counterexamples and paid renewal — D

### 4.1 Finite free inspection can precede a decision — D2

Premises: A is finite; every supported preview is free, stable and available throughout the live epoch; observing changes neither physical outcome reservations, allowed decision set, costs nor hidden dynamics; the controller can remember the observed results; and no external deadline/discount/inspection resource enters the objective. Selected-commit state can be restored by reobserving the desired request at zero cost.

Under these premises, a controller that observes all requests before committing/removing can emulate any controller that stops earlier: it ignores additional information and makes the same choice. It uses at most |A| new observations plus a possible selection observation, so this preliminary phase is finite. Complete inspection therefore does not worsen the optimum over the same proper policy scope. At full disclosure its local decision is

    E_mu[ min { C_a + U(F_a) for legal applied a;
                 price(one Divine) + U(R(x,z)) } ].

Use conditional expected U terms if the observation map is incomplete or removal has extra randomness. This formula still needs the **joint** mu and compatible statewise continuation authority. It does not move a minimum outside an expectation, declare a whole solver optimum, or turn a displayed snapshot into a probability measure. Existing Emulator eager reservation demonstrates lifecycle engineering; it does not supply the missing exact mu.

Observation order need not affect probability when stable complete outcomes are revealed under a fixed joint law. A canonical unordered history can then avoid factorial duplication; the selected request remains separate control. If observation order changes exposure, law, legal actions or resources, this reduction is invalid. The current API's normalization and persistence tests provide scoped evidence for the approximate model, not a universal game theorem. [S05–S06, S11]

### 4.2 Two-request marginal counterexample — D3

Let Y_A,Y_B in {0,1} indicate success of two requests from a fixed item. Each request has marginal probability one-half. Inspect both. Commit a successful request if either is good; otherwise pay removal, restore the same *semantic* retry state and buy a new Lock. Commit price is the same for A and B.

| Coupling | Positive joint atoms and probabilities | P(any good) | P(B good | A bad) |
|---|---|---:|---:|
| Coincident | 00: 1/2; 11: 1/2 | 1/2 | 0 |
| Independent | 00,01,10,11: 1/4 each | 3/4 | 1/2 |
| Complementary | 01: 1/2; 10: 1/2 | 1 | 1 |

Every ordinary marginal calculator returns the same A and B success odds in all three cases. A checker that resamples B independently after A is bad constructs a different controller law in the coincident/complementary cases. The table is an algebraic falsification witness; no game trial was run.

For arbitrary marginal success probabilities p_A,p_B, elementary event inclusion gives

    max(p_A,p_B) <= P(A good or B good) <= min(1,p_A+p_B).

Both endpoints can occur under valid couplings. Marginals alone identify an interval, not the exact benefit of inspect-and-select. A guessed common uniform inverse-CDF construction merely chooses one coupling; different action orderings/encodings can choose different couplings with the same marginals. It is a model proposal, not native evidence.

### 4.3 Pairwise evidence is insufficient for three requests — D4

Two laws assign probability one-quarter to each listed triple:

- even-parity law: 000, 011, 101, 110;
- odd-parity law: 001, 010, 100, 111.

Both have one-half marginals and independent pairwise distributions for every pair. Yet P(any good) is three-quarters in the first law and one in the second. After observing A=B=0, the C outcome is 0 in the first and 1 in the second. Thus a successful two-request validation or measured pairwise correlation cannot certify unrestricted three-request preview scope. A finite restricted policy may be checked under its compatible projected joint law; broadening its request scope requires the higher-order law or an exact conditional contract.

### 4.4 Renewal must pay removal and the next Lock — D5

For the specified controller, assume each failed round's real paid-removal transition returns to the same priced semantic state, clears the old foresight, and the next paid round has the same success law independent of prior observations conditional on that state. Let L be Lock price, D the authorized one-Divine removal price, C the selected success commit price, p>0 the probability that the round accepts a success. Then

    J = L + p*C + (1-p)*(D+J)
      = C + (L + (1-p)*D)/p.

Expected resources are one/p Locks, (1-p)/p paid removals and one selected successful action. Their price-weighted sum equals J. With L=D=C=1 Divine, the previous table gives J=4, 8/3 and 2. The independent case's expected counts are 4/3 Locks, 1/3 removals and one action. A free-decline model would omit D and give a different problem. Observing repeatedly without modification would not create an independent trial at all.

This recurrence is **not** valid merely because the affixes look unchanged. The modifying action may alter quality, implicit context, flags, rarity or future legality. If the successor is x' rather than an exact equivalent x, keep a vector recurrence over x' and hidden context. If removal can fail/refuse, retain its complete outcome support and live-lock state. If it needs setup/cleanup in addition to the selected one-Divine cost, retain those obligations or obtain an explicit all-in cost contract; never add speculative costs as facts.

A second failure of the recurrence arises even with correct per-round marginals: let a hidden persistent coin be selected once, with every future Lock good on one face and bad on the other. Each epoch viewed without history has marginal p=1/2, but after a bad observation the success probability remains zero forever. The repeating controller is improper on probability one-half. Treating each new Lock as an independent coin fabricates almost-sure success and finite expected cost. The renewal interface must therefore describe what actually resets hidden context. [S09 paid retry; D1]

### 4.5 Zero-cost observation loops and SSP authority — D6

A policy that observes the same bad preview forever incurs no further cost and never reaches the goal. In a raw accumulated-cost objective that can appear cheaper than a proper finish policy. It cannot furnish an executable upper under the repository's proper-policy convention. Finite observation acyclicity/rank removes this trap locally; the whole controller still needs entry-scoped transience after paid renewals and all other actions.

Bertsekas explicitly distinguishes unconstrained and proper-policy optima for nonnegative SSP costs; Bellman solutions and iteration alone can select different notions. [Primary paper, abstract and stated scope](https://arxiv.org/abs/1711.10129v2). Here the sufficient finite-checking criterion is direct: every positive reachable non-goal bottom SCC must be absent; finite costs plus a finite transient nonterminal chain yield J=(I-Q)^(-1)r. Nontermination is reported, not normalized away. [S09–S10]

A replay reservation vector is one draw, not a law. Storing more samples or fitting empirical frequencies does not establish exact probabilities. A sampled factorization is a hypothesis. Matching the primitive marginal also does not establish a conditional law for an action selected after another preview.

The narrow single-request route is useful only with its stated continuation/reset contract. It must not reject a bad A, then execute unobserved B under B's unconditional marginal: B may be correlated with the observed A. Nor may it invoke an ordinary tail whose future randomness shares omitted hidden state. It can be genuinely coupling-oblivious within an epoch by committing its preselected action regardless of observation, but that usually pays for information it never uses and supplies no demonstrated economic advantage.

For robust analysis, keep one coherent hidden joint model across a round and the declared context across epochs. Independently maximizing an adverse conditional at every history may combine rows that no single joint model can realize. Iyengar's robust-DP results require a rectangularity property for their dynamic-programming extension. [Primary publisher abstract](https://pubsonline.informs.org/doi/10.1287/moor.1040.0129). This is a warning about applicability, not a claimed solution of the present undiscounted partially observable SSP. A deliberately enlarged rectangular adversary may supply conservative worst-case information if proved, but its optimum is not the fixed-mechanism exact optimum.

## 7. Complexity and resource costs

Let k be the number of normalized requests in the chosen policy scope; d_a the number of public outcomes for request a; K the maximum number of positive per-epoch latent atoms conditional on persistent context; T the number of finite persistent hidden-context states; n the number of reachable physical/control contexts; and M the number of finite controller memory states, excluding an independently represented observed-request mask and selected-request register. T and K refer to the full Markov latent contract, not an estimated posterior grid.

- A dense complete outcome table may have K as large as the product of request-specific full outcome counts. Full numerical rolls multiply those counts; projecting to structural outcomes needs a native quotient proof. Table storage is O(K*k*B_item), where B_item is the chosen full outcome payload size, not one bit per success.
- Within **one fixed live epoch**, under stable order-independent observations, the number of partial public assignment patterns is at most the product over a of (1+d_a), before excluding zero-support patterns. For k binary observations this is 3^k. This is a per-epoch observation-record bound, not a global belief/history-state bound: inherited beliefs at the start of an epoch can be infinitely many when hidden context persists (D7). If order matters within an epoch, histories can additionally contain permutations; retaining order by default avoids a false quotient but can create factorial duplication.
- The selected finite latent checker has a conservative product-state bound O(n*T*K*M*(k+1)*2^k) when persistent context, current latent atom, selected/unselected register and seen mask are represented separately. If K already counts persistent h, omit T; if M already includes selection or mask, do not charge those factors twice. This bound assumes complete finite latent/control closure and bounded public memory; it does not count beliefs or cover an unbounded-history controller. Many admitted instances are much smaller, but no measured native compression is claimed.
- Finite hidden-state size does not bound the number of posterior states across arbitrarily many paid epochs. A belief-graph complexity bound needs a separately proved finite closure/quotient or a finite horizon with a retained priced continuation at that boundary. An exploration cap supplies a resource bound and a possible refusal, not exact global posterior closure.
- Naively filtering K atoms per observation state costs O(K) per row; preindexed partitions can reuse filtering with additional storage. Conditional-oracle inference may save storage but must expose its actual support-generation and inference work. A factor graph or decision diagram is exact only if its factors are correct and all inference is complete; it is not a generic polynomial-time promise.
- A fixed graph with V states and E edges admits linear-time graph/SCC classification in O(V+E). Dense elimination is O(V^3) arithmetic and O(V^2) memory; existing sparse/iterative owners have actual convergence/numerical/cap obligations, not a blanket linear-time solve guarantee. Rational bit growth matters for exact reference arithmetic.
- Searching all observation policies is much harder than checking one. A naive horizon-h policy-tree count satisfies a recurrence bounded by T_h <= a*T_(h-1)^d for a actions and d observation symbols, already exposing rapid combinatorial growth. The finite free-inspection theorem can collapse a local round, not all physical states, ordinary tails or unknown joint laws.
- The current Emulator stores O(k) sampled reservations for one epoch rather than K possibilities. This engineering economy is precisely why its checkpoint is a replay sample rather than a law certificate. Lifting each stored sample into an exact distribution would replace missing probability authority with fabricated mass.

Resource ownership must include resident joint data, conditional indices, live scratch, numeric solve buffers, graph output and retained fallback simultaneously. Streaming latent atoms can reduce table residence but may force repeated conditional work; forgetting unseen samples on reload changes semantics. External host read-only work must respect the specified gaming windows. No local work or run budget has been spent on a Lock runtime here.
