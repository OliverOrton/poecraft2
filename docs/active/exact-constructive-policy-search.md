# Exact Constructive Policy Search

**Status: C0-C3 retained; C4 has a finite natural three-T1 foothold and exact
closure remains open.**

Parent: [Active work](README.md)

## Objective

Make broad real-item solves practical by pairing the existing admissible
focused lower search with generic executable policy uppers. The current
exploratory target is an empty rare item-level-86 Dire Pelt requiring three
ordinary-pool T1 rolls:

- rarity: `ItemFoundRarityIncreasePrefix3`;
- maximum life: `IncreasedLife9`; and
- life regeneration: `LifeRegeneration9`.

None is supplied directly by a bench action or essence in the admitted
envelope. The complete Calculator-derived envelope contains 23 priced actions,
with no bench actions or essences. The prior crafted-cold-resistance target is
retained only as historical regression coverage.

The constructive policy is an incumbent, never an action restriction. Exact
optimality may be reported only when the global admissible lower and executable
upper meet under every admitted action. This exploratory session is successful
with a finite upper, exact bracket, progressive-fracture evidence, cooperative
bounded execution, and a measured next bottleneck; full convergence remains
the later C5 boundary.

## Fixed boundaries

- Derive policies from goal slots, engine-owned legality/producibility, exact
  primitive kernels, and current prices. Do not hard-code the Dire Pelt, named
  modifiers, or one craft route.
- Compile completed policy behavior back to ordinary primitives. A feasible
  policy may be measured before closure but must not be labelled exact-optimal.
- Preserve all 23 admitted actions, price ties, mechanic behavior, and
  all-actions exactness. Approximate compaction is forbidden.
- Keep production caps unchanged until structural evidence identifies one
  specific remaining cap with measured payoff.
- Keep price-scoped dominance separate from price-independent kernel/state
  equivalence. A partial price-bound graph is not a reprice cache.
- Keep expensive constructive, strict-cover, and refinement work cooperative
  and externally watchdog experimental runs.
- Run routine acceptance only at C5. Development uses focused native tests and
  bounded diagnostics.

## Phases

- **C0 - gates and witnesses:** retain cap-stop records and native exact-policy,

- **C1 - generic constructive upper:** build exact renewable/finish chunks and
  compose real Restart/setup behavior.
- **C2 - upper-guided focus:** install feasible frontier fallbacks and expand by

- **C3 - admission amortization:** reuse exact collision-checked templates and

- **C4 - measured natural-target proof:** establish a finite primitive renewal

- **C5 - acceptance:** require exact convergence, compilation, exact compiled
  evaluation, 10,000-run verification, native gates, WASM rebuild, non-visual

## Current C4 implementation

Primitive destructive renewal is now supported without a deterministic finish
action. It uses already admitted primitive rows, exact goal probability, legal
retry checks, and complete collision-checked preserved-base reforge signatures.
The executable anchor is the actual Restart fresh normal carrier plus a
materialized rare setup; all other actions remain in the solver.

The engine-selected bootstrap for the real target repeats the Life + Quality
fossil. Its exact values are:

- renewal/start upper: `4893.92255176662`;
- Restart anchor upper: `4893.5021285362827`.

Progressive fracture is also generic. It groups roll outcomes by exact
`(satisfied goal subset, explicit-mod count)`, selects an acquisition class by
exact probability, evaluates the engine-owned fracture kernel, retains only a
useful fractured target, rerolls through exact post-fracture renewal modes, and
uses real Restart on rejected branches. For the real target it selected class
mask `1`, six explicit mods, probability `0.09005427939272441`, and one
post-fracture renewal mode. Its exact standalone start upper is
`4116.0146281888519`, a reduction of about 15.9% from the bootstrap.

## Measured bracket

The unchanged-production-cap diagnostic stopped on exactly 11,000,000
reforge-work units and proves:

`261.05161071365512 <= V* <= 4104.7066630770487`.

The solver improved the explicit progressive incumbent slightly while
optimizing the expanded partial policy. It discovered 127,661 states, expanded
544, retained 9,631 rows and 430,232 transitions, and left 127,117 states on
the frontier. Solve time was 50.779 s, the longest cooperative step was
10.623 s, and selected-owned memory was 89,274,767 live / 155,223,616 peak
bytes. No benchmark child remained after bounded runs.

The cap-3 timing audit attributes 20.927 s to constructive-policy search,
0.460 s to the strict clean-goal cover, and 0.622 s to expansion. The deeper
run's first expansion was 1.508 s, including 0.626 s of automatic admission.
Fossil, Harvest, and currency reforge kernels dominate raw outcome work, but
action admission is not the exactness gap.

The finite incumbent changes infinity into a useful focus signal and lowers
the executable upper, but it has not materially advanced the lower: 541
additional expansions raised it by only `0.11330375945527`. Raising a cap is
therefore not justified. The next exact work is to strengthen rare-state
goal-progress lower certificates around permanently fractured satisfied
subsets, blocker/group identity, and Exalt/Harvest/destructive routing, while
broadening progressive acquisition/post-fracture modes. Constructive-policy
work should become resumable before another deeper diagnostic.
