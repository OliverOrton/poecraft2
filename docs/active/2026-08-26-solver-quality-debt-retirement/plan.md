## Objective

Recover practical exact-item strategy quality by determining, in order,
whether the product solver is failing to admit a useful strategy, value it
consistently, promote it as an executable incumbent, or prune work around it.
Retire the surrounding debt only where current product-profile evidence shows
that it owns cost, quality, closure, memory, or cross-run drift.

This boundary is deliberately upper-first. A stronger lower cannot separate
operators from an absent or very weak executable incumbent, while current
acceptance already contains broad-solver versus exact-evaluator value and
refinement failures that can distort policy selection before publication.

## Retained authority

- Calculator/general benchmark solves default generated Imprint programs off.
- Exact terminal success contains only the requested explicit affixes.
- Calculator disables voluntary economic Restart and enables the authored
  goal-progress reforge restriction and high-impact executable-upper path.
- Independently evaluated compiled strategies own finite publication uppers.
- An open requested action envelope publishes only an independently global
  proof lower.
- Publication must remain safe when direct reconciliation or strict refinement
  fails. This milestone improves the cause; it does not weaken the fallback.
- Compiled-strategy verification uses 10,000 runs when a gate requires sampled
  verification.

## Gate 0 — Current Calculator-profile nested ladder

Create a versioned diagnostic corpus that uses one native-owned Calculator
product profile and generated Imprint programs off. It must include:

- clean exact 1, 2, 3, 4, and 5-goal ladders on the Eldritch-eligible Conquest
  Lamellar;
- the same feasible nested ladder on at least one non-Eldritch base;
- one non-armour diversity base where compatible goal families exist; and
- partial 3-to-4, 3-to-5, and 4-to-5 starts for the named Conquest goal.

Each case records requested action scope, admitted/deferred families, first and
best verified incumbent trajectories, independently global lower trajectory,
restricted search value, exact-evaluator value, refinement status, graph/work,
memory, stop cause, and wall time. Censored five-goal cases are valid evidence;
they must not be represented as exact failures.

Run native cases concurrently only through isolated benchmark processes with
an explicit aggregate host-memory limit. A fast single-case reproduction path
must remain available for debugging.

Gate 0 passes when the corpus is reproducible, identifies the exact current
four-goal and five-goal quality boundaries, and distinguishes no admission,
no incumbent, valuation mismatch, failed promotion, proof weakness, and
resource stop.

## Gate 1 — Broad-to-exact refinement attribution

Use the shortest ladder witness that reproduces one of:

- direct exact cost mismatch;
- exact mass-conservation failure;
- `proof envelope lost its selected quotient state`; or
- unavailable `ModifierExclusionSignature` refinement.

Add behavior-neutral provenance only where existing reports cannot identify:

- the selected broad state and row;
- the exact carrier states represented by that quotient state;
- which required refinement feature split the partition;
- whether the selected child was never constructed, merged under an
  insufficient key, removed, or became unreachable; and
- the first policy node/action where broad and exact Q authority diverge.

Gate 1 passes with a deterministic failing native witness and one root cause,
not merely a later exception string. Telemetry must not change values, hashes,
selected actions, caps, or termination.

## Gate 2 — On-demand semantic refinement repair

Repair the proven Gate 1 cause locally. The preferred shape is grow-in-place or
CEGAR-style refinement of only the selected/reachable proof envelope. Do not
add `ModifierExclusionSignature` or another high-cardinality identity to every
broad product state.

Required controls:

- the witness reconciles or fails for a more precise, truthful reason;
- strict-child expansion preserves complete probability and selected-state
  reachability;
- small exact oracles retain values, hashes, actions, and termination;
- state, pair, and owned-byte growth is attributed and bounded; and
- safe bounded publication remains unchanged for genuinely unrefinable cases.

After repair, rerun Gate 0 before proceeding. If exact evaluation improves a
policy but broad Bellman selection still cannot consume the result, record
that as Gate 4 input rather than broadening refinement authority.

## Gate 3 — Bounded action-scope and intermediate-utility audit

Audit only cases where Gate 0/2 show that a useful family is absent or delayed.
For Fossils, record the bounded beam's admitted and omitted loadouts, prices,
goal reach, side/blocker effects, and whether an omitted candidate improves an
executable upper under exact evaluation. For Essence, Harvest, Influence,
Bench, Eldritch, Fracture, and Veiled automatic programs, distinguish:

- mechanically inapplicable;
- outside the explicit product goal envelope;
- direct-goal irrelevant but potentially useful intermediate action;
- admitted but never evaluated;
- evaluated and refuted; and
- selected/promoted.

Counterfactual widening must be case-local and bounded. Promote a scope change
only when it produces a proper independently evaluated improvement on a ladder
case without unacceptable control/resource regression. Exactness claims remain
explicitly scoped to the resulting requested envelope.

## Gate 4 — Executable-upper consumption

does not retain or exploit. Add the narrowest consumer necessary to place that
candidate in `IncumbentPortfolio` and use it for comparison/pruning.

Preserve mask round-robin diversity and the qualified legacy scheduler order.
Do not re-enable the rejected global scheduler profile. Any new typed lane gets

and clean five-T1 plus partial/Bow/control qualification.

## Gate 5 — Lower-bound coverage after an early upper

Only after the target cases possess a useful verified upper, measure which
lower gaps prevent operator pruning or gap-directed scheduling. In order:

1. extend non-clean terminal-debt continuation beyond the current zero or
   first-price grant where an admissible carrier pattern proves it;
2. anchor strict patterns on qualifying rare successors without imposing a
   fixed goal order;
3. model Eldritch automatic side options completely enough to remove the
   current conservative guard; and
4. add only lower improvements that reach a consumer: operator pruning,
   fringe priority, envelope retirement, or gap termination.

Every increase carries an admissibility proof and a small exact oracle. Merely
raising the displayed lower is insufficient. Record
`state_incumbent_operator_lower` and action-envelope reduction as leading
consumer evidence.

## Gate 6 — One product-profile authority

Define a versioned native Calculator solve profile owning Imprint, Restart,
goal-progress gating, high-impact upper work, gap defaults, and relevant caps.
The Calculator, native benchmark, release-WASM benchmark, and diagnostic corpus
must select it by identity rather than recreating inverse low-level defaults.
Dedicated mechanic controls may override named fields and must report the
override.

This is a cross-layer solver option contract: inspect and update the C ABI,
WASM facade, worker protocol, benchmark parser, fixtures, and stable docs as
required by the change-impact map. Rebuild release WASM before final web tests.

## Gate 7 — Measured debt retirement and ownership refactor

Retire only debt touched by preceding gates:

- remove or isolate planner/scheduler skeletons with no qualified consumer;
- split refinement discovery, exact reconciliation, and publication ownership
  where their coupling caused the Gate 1 defect;
- separate durable action-family capability from dated qualification labels;
- consider a live-memory-budgeted automatic-admission cache only if profiling
  proves repeated context construction material; and
- consolidate reforge evaluator/cap vocabulary only where current product and
  diagnostic authority can be preserved.

Large-file reduction is not itself an acceptance target. Refactors must follow
cohesive ownership and preserve behavior unless an earlier gate explicitly
qualified a change.
