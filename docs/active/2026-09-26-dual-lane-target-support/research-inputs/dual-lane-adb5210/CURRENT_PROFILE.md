# Current: target-neutral bounded discovery without proof leakage

## Why this profile is selected

The previous audit intentionally left R refused because it had not qualified every target-dependent proof and original-root checking path. That was safe but left the central experiment unanswered. This programme first qualifies shared policy checking, then introduces one deliberately limited Current profile. It does **not** attempt to transplant all of Current's clean-specific positive lower models to R in the same chunk.

Design name: `TargetNeutralZero` / proposed benchmark flag `--native-goal-proof target-neutral-zero`. These names are not implemented on adb5210. The existing `--native-goal-terminal legacy-clean|explicit-clean|coverage-only` remains the target selector. Public v1 and default Current do not change.

## Authority of the new profile

With complete nonnegative original prices, zero is a valid global optimum lower for either target. The profile publishes that lower and checked executable policy uppers. It is **bounded-only by selected capability**: no general exact-closure, solved-label, action-retirement or gap-stop claim is permitted from equality of speculative values or from an exhausted discovered frontier.

The profile uses the actual Current `SolveWork`, action generation and selected-policy construction. It does not call Finder, seed from a saved controller, or replace Current with a fixed primitive-renewal benchmark.

Actual working values used to build a proposal may be useful without being certified. Mark them as ordering/proposal data, not proof. A mathematically exact evaluation of a coarse selected row is not automatically a native full-MDP bound.

## Required source audit and interception map

Inspect actual callers, not just definitions. The following are known owners, not an exhaustive claim about every caller:

| Owner / value | Required treatment in target-neutral profile |
|---|---|
| `completion_proof_lower_value` / `ProofPatternManager` | Issue zero before preparation/consumption of unavailable components |
| universal, clean, identity-clean, carrier, bounded-gain, terminal-debt patterns | No unqualified positive consumption; zero profile intentionally omits all such positive advice |
| `envelope_bellman_lower`, `strict_clean_goal_cover_cost`, operator lowers | No inherited positive certificates or noncompetitive retirement; unresolved alternatives remain unresolved |
| native retention, phase proposal/restart/coupled tables | No producer construction or cached evidence consumption under the zero profile |
| lower-initialized queues and goal-cover candidate filters | Distinguish nonauthoritative ranking from certified removal; zero/unknown fallback must not mean impossible |
| materialization/candidate early exits using incumbent comparisons | Retain only justified target-correct semantics; heuristic exclusions must not mark proof obligations discharged |
| persistent strict session, ProofStore, solved labels, root interval/status | New profile identity; prohibit unqualified cross-target proof reuse and exact/target-gap promotion |
| current compile/assertion/publication | Full original-target check from U1; earlier good winner survives optional failures |
| options and reforge target-dependent exits | Build from fresh R GoalSpec; qualify native laws and routing under that request, including mandatory internal work |

This is not fulfilled by `reported_lower = 0` at the end. Proof-influenced pruning or an invalid finite upper may already have changed what was constructed. Injecting positive clean potentials and stale proof IDs must demonstrate they cannot affect certified decisions under the new profile.

Refactor only enough to make the profile an explicit owned capability. Prefer the existing typed proof-lower boundary plus necessary direct-reader guards. Do not scatter `if (coverage)` through unrelated mechanics or add a second proof manager. Add the profile identity to persistent/replay compatibility where the existing owner can outlive one call. Treat fresh handle construction as the default; no mid-solve target/profile mutation.

## Preparation and heuristics

Skip unavailable proof preparation so the profile does not spend a large budget computing values it cannot use. Apply this same change to L and R contrast arms. If an existing candidate builder needs a component as a heuristic, expose an explicitly nonauthoritative input or a valid neutral fallback; do not temporarily label it certified just to keep the builder running.

The original admitted native primitive/programme grammar remains fixed. Native state-dependent legality and terminal-dependent option stopping may legitimately differ between targets. Record those differences. Do not silently drop Imprint, side options, actions or modifier members only in R to get a result. If a native family cannot yet be represented under R, retain an explicit programme-scope refusal or identify an honestly labelled common restricted comparison—do not call it the requested full-scope result. Any such additional restriction requires an explicit disposition, not a new automatically chosen campaign.

|---|---|---|---|

| Either | another noncanonical occupancy target | any | Refuse unless explicitly covered by the selected support contract |

The gate must use complete normalized terminal/profile capabilities, not merely `extras == Allow`. More restrictive count goals may preserve some lower inequalities but still invalidate upper or closure constructions. L/E are equivalent only under the already-proved normalization preconditions.

## Native tests before full runs

1. A nontrivial Current coverage solve actually uses `SolveWork` and returns an R-checked graph. The same graph cannot be adopted as L without a valid L check.
2. Clean and coverage cases run under the same target-neutral profile and unchanged action/cost inputs.
3. No clean-specific producer is built or consumed; injected positive values/certificates cannot retire a competitor or raise the published lower.
4. Output remains bounded-only even with no pending work, small residual, a stable policy or equal coarse L/U estimates. `closure_available=false_by_profile` is reported separately from caps.
5. Default clean exact Regalia and ordinary positive proof remain available; the new profile does not leak into default construction.
6. Zero-price actions, improper zero-cost loops, unknown prices, unavailable continuations and cancellation are distinguished. Zero lower never makes an improper controller acceptable.
7. Synchronous, stepped and direct internal construction enforce the same capability. Target/profile identity cannot be changed on an active work object.

## Limits of the resulting comparison

The target-neutral L/R pair measures target effects **under this common discovery profile**, not under all of the original positive proof heuristics. It can reveal state/row growth, incumbent economics and selected-policy checking differences. It does not answer whether the fully optimized coverage-target exact prover would close A4/A5.

Run ordinary clean controls separately to show the profile's own cost. Do not combine two differences (target + disabled proof only in R) and call them a pure semantic effect. Full R positive-bound/closure qualification is a later, target-specific implementation after this evidence.
