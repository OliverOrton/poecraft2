# U0–U5 implementation plan

## Scope and non-negotiable separation

Implement the selected sequence on top of adb5210. Shared checking is the prerequisite for both consumers. Finder and Current consumers are separate required tasks, not competing branches. A Current-specific proof blockage does not cancel Finder work; a Finder grammar limit does not cancel Current work. A shared correctness failure blocks both until resolved.

No public v1/default migration, Finder grammar expansion, ML, GPU, multithreaded solve, new SSP solver, universal goal language, or automatic incumbent-import feature is selected. No rerun of O/S, the August-history census, G0 templates or broad state-role timing audits is selected.

The Current addition is explicitly **bounded-only and diagnostic**. The original exact Current path remains the normal legacy-clean path. Do not claim that the new diagnostic qualifies coverage-target full-MDP closure.

## U0 — Establish the real shared evaluation boundary

Inputs: pinned source, existing E/K receipts, existing native evaluator/compiler/API fixtures.

Tasks:
1. Record clean HEAD/local changes and applicable rules. Preserve root `0` without inspecting it. Reuse the latest history and clean A4/A5 results.
2. Add a small native differentiation fixture: a reached item satisfies the requested family/rarity and has extra affixes. A graph whose effective guard tests coverage should reach its declared success; the same graph submitted against a clean request must not acquire clean-policy authority.
3. Add a graph that observes family B internally but requires only A at success; and an any-k objective whose graph observes all named slots. Record which goal object is the observer universe and which is the requested target.
4. Run the selected exact full-distribution and optimized/gated paths where applicable; retain exact costs, target mass, no-edge/illegal outcomes and a native mismatch witness. A path not supported by the existing API can be tested through its existing native helper seam.
5. Resolve whether a real evaluator correction is needed or whether the gap is primarily original-request acceptance/dispatch. Do not infer either outcome from the helper's variable names.

Exit: a small reproducible native positive and negative, plus an explicit list of affected shortcuts. This is not a benchmark gate requiring economic gain.

## U1 — One request-bound checking contract, two real callers

Implement [SHARED_CHECKING.md](SHARED_CHECKING.md). Prefer narrow changes around existing compiler/evaluator owners. Keep the observer vocabulary separate from the original goal.

Required consumers:
- Current's actual compiled-policy assertion/publication path, including its applicable paired-graph and reuse paths;
- Finder's actual preparation/evaluation/adoption path, including compiler-owned native-program occurrences.

The check binds the full original root, resolved goal/terminal identity, action/program scope, native data/session and actual prices/economy. It establishes target membership for all positive reachable success support through a native observation-complete check or an existing validated compiler guard contract. A report's top-N final classes or one representative cannot prove it.

Preserve generic authored-strategy evaluation semantics: it may still evaluate an author's terminals without claiming they solve a particular Calculator request. The stronger request-bound result is opt-in in that generic API and mandatory for both solver-produced policies.

Exit: both lanes consume target-match evidence; false success, wrong root, wrong target, branch-observer confusion and stale reuse tests pass. No new global mutable goal switch. Clean result costs and properness remain unchanged.

## U2 — Qualify the Finder consumer independently

Admit coverage-only Finder in the existing native-private terminal mode **only after U1**. Keep `conditional-retention`, ranking, candidate generation/attempt limits and checker count unchanged. Do not add a new controller family during the target comparison.

Update synchronous and stepped dispatch. A finished root must return its checked zero-cost controller in the correct target, including an already-covered dirty R root. The same dirty root remains nonterminal in L. Unsupported terminal shapes fail explicitly.

The admission check for Finder depends on fixed-policy checking and supported programme semantics, not Current proof availability. Every reached dependency-only programme entry retains native revalidation. No silent Current bootstrap or fallback.

Exit: at least one nontrivial complete native R policy from the original root, clean rejection of the incompatible artifact, retained clean Finder controls, correct Finish/cancel/replacement lifecycle. A tiny fixture establishes implementation, not full-data economics.

## U3 — Implement a target-neutral Current diagnostic profile

Implement [CURRENT_PROFILE.md](CURRENT_PROFILE.md), using `SolveWork`, not Finder or a new solver. Design name/CLI proposal: `--native-goal-proof target-neutral-zero`; this flag does not yet exist. Keep the existing `--native-goal-terminal` flag.

This profile has one explicit certified lower authority: zero under nonnegative prices. It does not consume unqualified clean-dependent positive lower tables, operator-pruning certificates, solved labels or inherited exactness claims. It preserves complete native candidate laws, checked executable uppers, failure/cap handling and the original admitted action/programme scope. It may still use clearly nonauthoritative search scores.

Audit and intercept real consumers before removing the API refusal. Do not patch a displayed lower after unsafe pruning has already happened. Positive clean proof inputs deliberately injected into tests must be inaccessible, not merely hidden from the report. Explicitly disable the corresponding producer preparation where it is unnecessary; profile identity records the change.

Legacy clean Current uses its existing proof profile and remains the exact-solver control. R + legacy proof remains refused. L and R + target-neutral-zero are admitted only after the complete capability inventory qualifies. The same target-neutral profile applies to both contrast arms.

Exit: a nontrivial synthetic Current L/R pair actually runs through Current, returns correctly checked policies and honest bounded-only statuses. The production R capability is not certified by showing zero works algebraically; all live consumption/shortcut paths must be accounted for. If a specific path cannot be isolated, retain its named refusal and provide the exact source/fixture/dependency design needed to finish it; do not describe U3 or the full programme as complete. U2 may still be retained.

Add one second target context only after a concrete correctness/generalization gap appears; record why it is needed.

No ordinary same-problem comparator bypass for L/R. Use a labelled semantic-contrast report. Record all attempted cases, including no-policy, timeout, before-work refusal and partial progress. See the scorecard for closure availability versus closure not reached.

Rebuild release WASM for shared native changes and qualify the normal public clean flows of **both** modes. Private coverage mode need not be exposed in TypeScript or the UI. Native success is not a browser coverage feature. Preserve the current compact transport and native cancellation semantics.

Exit: per-lane actual capabilities and observations; no easier-target claim recast as a clean improvement.
