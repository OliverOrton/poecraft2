**Status: stopped precisely on 2026-08-21; publication batching was rejected
and a narrower numerical upper-pass lifecycle defect was repaired.**

## Objective

Determine whether the repaired carrier-local automatic action envelope is
slow because its actions are invalidly broad or because the strict closer
publishes too many intermediate policies. Preserve every admitted action and
exact proof obligation unless an existing exact equivalence or dominance
authority proves it redundant. Recover four-T1 exact closure if the measured
publication amplification is the binding defect.

## Gate 0 Evidence

The checked repaired run prepares 135 automatic operators. Across 482 coarse
carriers it admits 2,573 temporary-bench rows, 1,921 Eldritch-side rows, 291
primitive Fracture rows, and 116 protected-side rows. These actions are not a
speculative compiler vocabulary: their complete carrier-local kernels passed
the existing legality, price, relevance, cleanup, and almost-sure termination

The strict scheduler nevertheless retains 16,277 open actions. Its source
loop immediately runs Bellman and independently compiles/evaluates a complete
replacement artifact after the first improving obligation, then restarts the
scheduler. That rule predates this action breadth. Bellman re-optimization is
needed immediately because it supplies the next scheduling upper; replacement
compilation/evaluation is needed only to publish a new rollback-safe upper.
The 300-second trace alternates long local-reoptimization intervals with
repeated compilation and certification while the strict graph and public
upper remain fixed. The old fast result is not a rollback target because it
prepared zero automatic carriers.

## Recorded Result

Gate 1 confirmed that the newly prepared automatic actions are genuine. They
pass the existing carrier-local legality, price, relevance, cleanup, exact-
kernel, and almost-sure termination checks. The old fast result at `c955d02`
did not prepare this envelope, so its runtime is not evidence that the new
actions are invalid.

The Gate 2/3 batching hypothesis was tested and rejected. Full publication
batching exceeded 13.1 million solve steps; a 64-row batch and a Q-generation
trigger were slower; an internal Bellman run after 16 rows created a 56.9-
second atomic step; and deferring only replacement publication delayed the
first strict graph to roughly 180 seconds with a 4.69-second largest public
step. None improved the five-minute boundary. All experimental publication
changes were removed.

The audit instead found a concrete interaction introduced by the repaired
action breadth. A numerical-stability latch inside a temporary focused upper-
policy pass followed the generic whole-solve `Done` path. That stranded the
active incremental pass and silently left later automatic candidates
unevaluated. The retained repair routes this one state through
`finish_focused_upper_solve(false)`: temporary rows and the lower snapshot are
restored, the failed pass is recorded, and the existing scheduler advances.
Generic numerical-stop behavior is unchanged.

The final-source five-minute native run requested and started all 717 upper
passes; 439 were proper and 278 were explicitly rejected. The former 440th-
pass stranding is gone. The run remained responsive (1,407.25 ms largest
public step) and completed successive strict graphs through 5,961 states,
5,927 kernels, and 30,694 transitions before the watchdog. It retained the
same finite raw upper, `3759.5969190423507`, but no lower certificate. The
envelope remains open with 17,584 actions: 13,379 unevaluated and 4,205
unresolved.

The newly reached preparation witness is one magic, one-prefix/one-suffix
Imprint carrier at state 928. Its old generic 256-program work budget is
exhausted after 256 evaluated programs, 169 distribution-dominated programs,
182,778 action-state evaluations, and 2,570,418 merged outcomes. The frontier
still contains 61 words at depth three while the price-derived maximum depth
is 314,904. Raising the cap to 512 or 1,024 merely kept the worker inside this
one carrier longer. Scalar price dominance and price-first word ordering
reduced the sampled frontier but did not close it; those experiments were
also removed.

The next Imprint owner is therefore a unique exact-kernel graph search (for
example a price-ordered shortest-path search over checkpoint/support kernels),
not further flat word enumeration. This alone does not solve the older strict
alternative-closure amplification, so both boundaries must remain visible.
The primary stop condition fired; release WASM, primary verification, and the
full pipeline were not run.

## Stop Conditions

- The checked 300-second native watchdog fires before exact closure.
- Any action is removed without an exact equivalence/dominance proof.
- Batched and sequential Bellman results differ in selected policy or value.
- Replacement compilation/evaluation cannot materialize, reconcile, remain
  proper, or preserve zero off-policy mass.
- A checked resource cap fires or a required focused control regresses.
