# Existing-owner design: verified-base completion service

## 1. The narrow extraction

The main machinery is already in `engine/src/solver_solve_return_bridge.cpp`:
`collect_current_entries`, state-local automatic admission for `temporary_entry`,
`compile_dirty_continuation_strategy_json`, `evaluate_return_graph`, and verified
portfolio adoption. [R7–R10](SOURCES.md)

Do not call `try_dirty_continuation_candidates` wholesale with a fabricated mode.
It also owns root Exalt/Chaos/Essence proposals, dirty growth, Magic acquisition,
count views and unrelated ordering. The new path takes an explicit frozen base and
late-entry-only request. Prefer a small extraction used by both the old execution
path and new diagnostic path; preserve old ordering and ownership in its callers.
If moving coroutine boundaries is unnecessary, retain them and expose only the
minimal parameterized entry selection/constructor seam.

| Responsibility | Existing owner to retain |
|---|---|
| Candidate legality, native modifier universe, prices | Native calculator/registry and automatic admission |
| Actual physical decision entries | Compiler declarations plus independent policy-entry evaluator |
| Private namespace and complete local rows | Current private calculator construction |
| Paid option program and router composition | Existing compiler and graph-local composition contracts |
| Properness, full root cost and reconciliation | Existing independent complete controller evaluation |
| Incumbent availability, lifetime and selection | Existing portfolio/publication owners |
| Scheduling, Finish and cancellation | Existing solve task and request-scoped control path |
| Experiment identity and execution | Existing benchmark/corpus/worker/Lab services |

The real precursor is a compatible verified policy with usable provenance,
available before Finish with measured remaining resources. A graph first checked
after the deadline cannot by itself establish that service opportunity. A
particular earlier Essence attempt is not proposed as the new prerequisite. That
change must still be qualified under original resources; the old gate's absence
alone does not establish new reachability or economic benefit.

## 2. Entry request and binding

An invocation-scoped request needs references/owned inputs for the immutable base
artifact and certificate context, the actual original root, current permitted and
priced vocabulary, and the actual native decision/physical item. Existing typed
identities should be reused, not wrapped in a second generic identity database.

The role binding is descriptive: exact satisfied members, missing slot, side,
fractured/crafted status, counts, blockers, suffix context and chosen operation.
None of these is replaced with a histogram. The native builder resolves concrete
actions and kernels for that item. No literal Fire/Cold/BaseType dispatch is added.

Preserve the current clean eligibility: Rare; one unsatisfied requested goal;
exact goal-only occupied affixes; allowed persistent fracture only; no fractured
junk, offer, checkpoint or unrepresented control; real globally routable primitive
decision with valid compiler declaration. Parent-bound and graph-local provenance
are distinct valid routes, not interchangeable numeric namespaces.

Current code takes the top three by visits times old continuation cost. Reuse that
heuristic initially, with stable native ties, while labelling it as exposure rather
than improvement. Do not introduce a new ranking treatment at the same time. After
constructing a candidate, only complete original-root evaluated cost decides
acceptance.

## 3. Full native completion, not optimistic local stitching

The current clean-entry branch admits complete CannotRoll temporary-bench options
only when the source observation suffices for the entire represented class. It
prices every expected resource, requires complete supported legal kernels, rejects
unhandled observed choices, and keeps non-goal exits as explicit boundaries.

The graph-local route intentionally does not fill those boundaries with local
finite values. It composes the real paid program with the frozen old graph, using
its ordinary routing and declarations, and evaluates that complete recurring graph.
That mechanism should remain the pilot's acceptance route. [R9,R10,R13](SOURCES.md)

Pay special attention to the single-pass compact option constructor. The actual
emitted program/routing is authoritative for the comparison. The normalized
private option's expected cost is not automatically the cost of a once-executed
physical program or of the final recurrent controller. Preserve both representations'
existing compatibility guards and never compare only compiler annotations.

If any positive-probability exit cannot be handled by the old router or an already
supported paid recovery, refuse that candidate with its concrete witness. Do not
use another binding's tail, an old root scalar, a representative class member,
or zero. Broadening recovery is a different proposed programme.

## 4. Scheduling and retained ownership

A safe-point request is scheduled only after the first compatible verified policy
is actually retained, outside an active row transaction, checker or publication
frame that cannot yield its owner. The exact hook is selected by inspecting the
existing current task state, not by assigning phase enums from the diagnostic.

The pilot has one wave per solve and at most three source entries/six complete
composed candidates. Track its base identity and attempted outcome separately
from the old `ordinary_entry_attempted` state so the legacy execution-guided path
is not accidentally suppressed or double-run. Prefer a tagged use of an existing
lifecycle field only when its meaning really covers both sources.

Every partial local/checker result stays unverified. A successful candidate may
replace the incumbent only with a valid graph/certificate/context/value bundle.
If the ordinary solver independently retains a better result while this work is
suspended, the completed candidate competes with that current winner, not merely
with its frozen donor's cost. Finish seals through the current publication owner;
a weaker late completion cannot replace a better verified artifact.

Use an owner scope/tombstone for refused attempts, not an engaged child that keeps
memory and scheduler preference. Preserve original ordinary cursors and finite
wave termination. No invocation of another builder from a telemetry read.

## 5. Resource and invalidation rules

Peak admission includes simultaneous parent storage, any frozen-base copy, private
calculator, staged rows, both graphs during composition, provenance, evaluator,
work frames and allocation overlap. Keep fixed controller preparation genuinely
immutable before reusing its memory audit. Remaining candidate allowance is not an
extra checker cap outside the parent budget.

Charge every actual native operation to the existing cumulative logical/active
work owner. Release does not refund work. Tight-memory and cap-before-commit
fixtures are required, even when the ordinary positive test fits easily.

Bind evidence to graph, root/entry, goal, vocabulary, prices, data, action/control
semantics and required generations. A stale role map or duplicate node text is
not compatibility. Preserve graph-local declarations through real compiler
remapping. Hidden offered choices or mandatory interiors are not new decisions.

## 6. What is intentionally unchanged

The action envelope, native terminal semantics, scalar objective, lower producer,
proof obligations, generated Imprint/Restart settings, tie rules, core row cache,
compact bridge, public ABI and broad execution-guided programme do not change.
A restricted completion search can produce a full-scope feasible policy but cannot
retire omitted actions or certify full-scope optimality.

No general graph mutation engine, policy library, cache framework or `Impl`
reorganization is required. Update only the named existing owners necessary to
obtain the real L1/L2 candidate and then retire duplicated narrow helper logic.
