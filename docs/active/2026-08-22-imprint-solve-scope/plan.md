# Imprint Solve Scope And Controlled Comparison

**Status: active.** Oliver selected this boundary on 2026-08-22.

Parent: [Active work](../README.md)

## Objective

Add an explicit Calculator solve-scope control for automatic Imprint programs,
defaulted on for historical parity, then measure the checked Allflame
four-natural-T1 Conquest Lamellar solve with that family disabled. A result
produced without Imprint must disclose that reduced action envelope; it must
not be presented as an unrestricted optimum.

This boundary does not invent a price-only Imprint dominance rule. It records
the stronger successor: compare checkpoint-and-restore against a proved proper
recovery policy to the same observable Magic-carrier equivalence class,
including the attempt distribution and downstream continuation value.

## Gates

1. **Contract and scope.** Thread `consider_imprint_programs` from Calculator
   through TypeScript, WASM JSON, the C ABI flags, `SolveOptions`, and automatic
   admission. Omitted/default remains `true`; `false` excludes only automatic
   Imprint programs. Product copy and native telemetry disclose the reduced
   action scope.
2. **Focused proof.** Add native/API/WASM-facing contract coverage proving the
   flag defaults on and prevents Imprint discovery without disabling unrelated
   automatic candidates. Add web option/UI contract coverage.
3. **Controlled measurement.** Run the checked native Allflame four-T1 case
   once with the production Calculator options and Imprint enabled, then once
   with only `consider_imprint_programs: false`. Compare wall time, stop cause,
   lower/upper bounds, states, actions, transitions, and selected strategy.
4. **Acceptance and handoff.** Build native once after implementation, rebuild
   release WASM, then run the affected native solver/API tests, `npm test`, and
   `npx tsc --noEmit`. Do not run the full repository pipeline or rendered UI
   review. Record the actual result here or in a sibling `result.md`, update
   `HANDOFF.md`, and make coherent local checkpoint commits.

## Sound follow-up boundary

An Imprint program is not dominated merely because another route can produce
some Magic item cheaply. The comparison needs all of the following:

- a collision-checked observable equivalence class for the saved checkpoint;
- a proper non-Imprint recovery policy from every relevant failure class back
  to that same class;
- expected recovery cost, not only the cheapest primitive price;
- the success/failure distribution of the attempted program and the same
  downstream continuation value; and
- a pointwise or Bellman-valid inequality before pruning.

If ordinary recovery is proved no more expensive in every failure class, the
Imprint restore branch is dominated. If Imprint is cheaper, it remains a
candidate; that fact alone does not prove the whole Imprint program optimal.

## Non-goals

- No cap-only increase or repeat of the stopped terminal-renewal predicates.
- No first-class Imprint kernel/label search in this boundary.
- No changes to Imprint mechanics or prices.
- No full acceptance pipeline.
