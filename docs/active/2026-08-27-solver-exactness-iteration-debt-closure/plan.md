# Solver Exactness, Iteration, And Debt Closure

**Status: active implementation boundary.** Selected by Oliver on 2026-08-27.

Parent: [Active work](../README.md)

## Objective

Complete the remaining solver stabilization backlog as one dependency-ordered
program: cooperative/resumable broad destructive rows, deterministic
development checkpoint/replay, measured strict-proof repair, solver-only state
reduction, telemetry and source modularization, navigable current
documentation, and the outstanding influenced-modifier and low-probability
accuracy audits.

This boundary follows the completed native action-family controls. It may use
those controls diagnostically, but it must not turn a restricted-envelope
result into unrestricted proof authority.

## Owner Rulings And Fixed Boundaries

- Mirrored and Synthesised do not matter to Calculator solver planning.
  The mirror-producing Fossil is never useful to the solver. Preserve engine
  simulation behavior where it remains supported, but do not retain those
  dimensions or that action merely to enlarge the product solver state space.
- Checkpoint/replay is development acceleration only. It is not product cache,
  publication, lower-bound, or exactness authority.
- A partially evaluated row cannot publish, certify, seed Bellman values, or
  consume completed-row authority.
- Replay must refuse stale or mismatched source, format, artifact, goal,
  carrier, action-envelope, price, option, layout, or floating-point identity.
- Preserve deterministic ordering and floating-point accumulation. A resumed
  row must match uninterrupted row bits, transition ordering, work accounting,
  and hashes.
- Do not raise default caps, weaken exact terminal success, remove simulator
  mechanics, or start five-goal tuning to disguise a four-goal proof failure.
- Oliver owns visual review. This boundary includes automated product tests,
  not rendered browser sign-off.

## Gate 1 — Cooperative Resumable Broad Rows

1. Refactor the exact V3 destructive-row recurrence into an explicit retained
   work object with bounded deterministic slices.
2. Suspend inside predecessor indexing, predecessor expansion, candidate
   canonicalization, recurrence accumulation, and successor publication where
   any one phase can exceed the worker-step contract.
3. Keep the existing synchronous calculation API as a completion wrapper for
   callers that do not own cooperative scheduling; strict proof scheduling
   must drive the resumable interface directly.
4. Store partial scratch only in cursor-owned memory and charge it to the
   selected solver-owned byte ledger. Discarded/interrupted cursors remain
   non-authoritative.
5. Add exact uninterrupted-versus-resumed oracles, multiple suspension-point
   tests, cap/cancellation tests, and deterministic telemetry for slices,
   resumes, maximum slice wall, retained bytes, and completion.

## Gate 2 — Development Checkpoint/Replay

1. Add a versioned native development checkpoint at:
   - completed coarse graph plus selected/verified incumbent immediately
     before strict refinement; and
   - the first closed strict partition plus obligation ledger, retained row
     kernels, and resumable row cursors.
2. Bind source/format, compiler and floating-point contract, canonical and
   compiled artifact identity, goal/start carrier, economy/prices, candidate
   and generated action scope, solve profile/overrides, layouts, stable
   state/action identities, and completeness checksums.
3. Expose save/load only through the native benchmark/development harness.
   Refuse every mismatch explicitly; never silently rebuild part of a claimed
   replay.
4. Prove clean replay reproduces values, rows, transitions, work accounting,
   policy/graph hashes, and exact evaluation. Prove corruption and identity
   mismatches refuse.

## Gate 3 — Solver State Reduction

1. Census reachable states, transitions, kernels, obligations, and selected
   policy mass for Mirrored, Synthesised, Corrupted, Split, influence,
   Eldritch, Fracture, crafted/Veiled/protection, and retry-basin dimensions.
2. Remove Mirrored/Synthesised from product-solver projection and reject their
   irrelevant producing action from product admission, while retaining native
   simulator behavior.
3. Remove or early-terminalize any additional dimension only with a proved
   action-observation and terminal-semantics argument. Keep uncertain
   dimensions and record the measured reason.
4. Require state/row reduction or a clear zero-cost conclusion; do not call a
   source deletion a solver improvement without a consumer.

## Gate 4 — Strict-Proof Attribution And Repair

1. Use replay plus engine-owned family controls to identify the actions,
   carriers, kernels, and row phases owning the PDR amplification. Do not run a
   broad corpus matrix.
2. Explain the 299,394 obligations, the rows that consumed the second 50M
   allowance, and why current admissible patterns retire none.
3. Implement only the narrowest proved repair supported by evidence: exact
   applicability/dominance rejection, successor-complete carrier/action lower,
   collision-checked kernel reuse, or recurrence reuse.
4. Acceptance requires a measured proof consumer—retired obligations, less
   exact work/memory, policy improvement, or closure—not merely a larger
   displayed lower.

## Gate 5 — Telemetry And Source Modularity

1. Introduce typed phase records and two intentional telemetry levels:
   compact default and full evidence. Compact retains stop, bounds, incumbent,
   action envelope, dominant work/memory owner, resumable-row state, replay
   provenance, and maximum slice.
2. Split serialization from collection and divide oversized solver owners only
   at lifecycle/authority boundaries established by Gates 1–4.
3. Preserve semantic full telemetry, deterministic hashes, linkage, caps, and
   internal ownership. Do not combine mechanical moves with a new proof rule.
