# Selected N0–N4 milestones

## Objective

Find a complete cheaper original-root controller by repairing a real incumbent
planner decision in its actual native context, then qualify one bounded ordinary
service path if the economics support it. The closed L0 family is not resumed.
No weight equivalence, cost penalty, new mechanic or full solver rewrite is selected.

## N0 — Restore evidence, then separate safety from recipe shape

Use the saved A5 `default_finish` report and source-bound native graph. Do not run
another four-minute control merely because it is convenient. Resolve the existing
A5 `refused_unsupported_action` outcome separately from its verified policy and
entry-query statuses. Import prior donor provenance through its native retained
artifact/producer or recover it at the existing verification safe point if local
outputs do not preserve it; never reconstruct trusted provenance from bare JSON.

Project existing entry data or invoke one saved-donor evaluator query when the
required physical distribution was not saved. For each compiler declaration,
record primitive versus whole program, actual native family, why it was outside
the old selector, and whether it is a genuine replaceable boundary. Query up to
64 declared sources in one bounded evaluator pass, using existing inherited
entry/state/memory limits. If capacity requires a smaller request set, predeclare
it using the available whole-operation totals and record omitted declarations.
Do not silently materialize every mandatory interior or evaluate the entire donor
once per node.

For reached entries record exact identities and independent reason flags:
- no valid declaration / option interior / stale metadata;
- hidden active checkpoint or offer;
- invalid native item, missing action/price/refinement contract;
- no compatible global route or continuation;
- persistent context (actual Eldritch tiers/influence/flags); rarity;
- exact requested-goal debt; extra/below-tier/crafted/fractured affixes;
- old-family-only exclusions versus actual proposed-family failure.

Keep an ordered first-failure category AND independent reason bits when cheaply
available. One cannot reconstruct all rejection causes from first-failure counts.
Never interpret absence of the old recipe's clean shape as lack of a safe source.

**Exit:** one or more actual safe source entries and the relevant native alternative
vocabulary, or a precise native-observation/control obstruction. Obtain the required
facts from the existing graph/query before asking for unrelated full solves.

## N1 — Select one economic local family from actual sources

Use at most three physical source entries from at most two supported native families.
Freeze selection before construction. Prioritize actual recurring immediate spend
or a named preserve/cleanup capacity event using existing evaluation output. For a
proper macro-boundary partition, expected decision visits times complete mandatory
macro cost is additive; do not sum overlapping macro and primitive attributions.
If the macro cost is unavailable, report it, and use an explicitly heuristic stable
ordering rather than making up zero. Visits times remaining cost is exposure only.

Retain the native goal roles, side occupancy and tier/blocker observations. Candidate
families may preserve the source's existing Eldritch state and act on its native
eligible side, or pay for cleanup/capacity from a dirty source. Do not assume one
of these is optimal or that they are equivalent. Bind actual action/program IDs
from the admitted original scope. A user-excluded action does not become available
because it is useful in the saved strategy.

Inspect completed ordinary rows/options first. Do not build the identical selected
controller again and call it a novel candidate. Existing exact kernel/spec equality
stays active. Use a family distinct by complete behavior rather than a different
label. None of the historic graphs is an ordinary search seed.

## N2 — Build a bounded exact local repair with real tails

Start with one full native planner decision. When its setup or repair is useful
only with follow-through, allow a second complete decision in the same selected
family. This is a proposal-search depth, not two primitive clicks and not the
user's crafting-action budget. State-local candidate enumeration remains bounded
through existing owners; no all-actions global tree is selected.

At each exposed decision retain the choice to follow the old verified controller
when that continuation is actually compatible. Every positive-probability exit
must reach a native goal, a specifically checked old tail, or the next complete
local decision. Unknown tails remain unknown. Existing arbitrary-entry checking
may certify a newly encountered old route; cap/refusal does not mean infinity as
an economic fact. Do not repeatedly query an unchanged uncovered tail.

Prefer existing whole-option and general dirty-composition paths. Preserve setup,
cleanup, cost, failure outcomes and complete native routing. No candidate-specific
state or value crosses a calculator namespace by numeric handle alone.

Keep the intended interpretation explicit:
- a finite staged prefix then permanently old policy needs real stage/mode control;
- a stationary local patch reentered by the global router is recurrent and has
  different equations.
The finite-lookahead estimate is not the value of a reentered patch. A conflicting
stage-dependent choice cannot silently collapse onto one physical state. Use the
interpretation the existing compiler can faithfully express; a narrow owner-local
extension is permitted if needed by a demonstrated candidate, not a new graph DSL.
Whole-root independent evaluation decides acceptance in either case.

Initially at most six distinct complete original-root candidate checks. Count all
preparation and failed/partial work under the original limits too; these six are
not permission for unbounded uncounted prechecks. Preserve the frozen base artifact
through all attempts. Candidate shortlists are heuristic restrictions, not action
retirement. Every complete graph is compared to the strongest compatible existing
unattended result, not only a weak donor.

**Exit:** a strict verified improvement, or actual complete candidate costs/refusals.
If two substantively different supported variants fail without a new causal premise,
stop and retain their exact boundary. Do not return to the old clean-entry-only gate.

## N3 — One live service wave, only after useful economics

Initially default-off, invocation-scoped native activation. Reach it at an existing
safe point after compatible verification; do not activate execution-count guidance,
all dirty root trials or an earlier Essence prerequisite solely to reach this family.
The existing phase/task owner must retain one donor and at most one wave. No new
scheduler, portfolio or attempted-flag that suppresses unrelated legacy work.

The live candidate has to fit parent + donor + local calculators + graphs + checker
+ scratch + coroutine frames simultaneously. Standalone results with the parent
released are fixture results, not proof of live admission. Preserve original total
logical debit, deadlines and irreversible cap outcomes. Cancellation/Finish stops
speculation, releases true resources, and returns the cheapest currently owned
compatible verified result. Compare against the current winner at adoption.

Qualify an off/on native pair only after focused tests. Then source-matched actual
compact Calculator for a product claim. Preserve the early A5 policy, A4, Regalia,
and affected legacy wide paths through fixtures rather than an automatic wide run.
Use one needed counterbalanced repeat for a material/noisy timing effect.

**Success:** any strict fully evaluated cheaper policy is an economic finding.
The material goal is 20% below the strongest current unattended A5 baseline, not a
correctness threshold. Smaller improvements receive an explicit cost/benefit and
activation decision. A current-run compatible witness, all-in resource admission,
second structural context and affected controls are needed for a default change.
No gain means no forced default activation.

## N4 — Integration, independent outcomes and stop

Publish separate dispositions for actual-source coverage, candidate completeness,
economic result, live service, product activation, correctness/properness, resources,
latency and full-scope exactness. Follow [DOCS_AND_RESEARCH.md](DOCS_AND_RESEARCH.md).
Do not label a class query or a support-only interface as a policy improvement.

Do not automatically continue into exact symmetry, response caching, new lower
relations, source-estimate correction, user action budgets or structural cleanup.
