**Status:** proposed bounded diagnostics, not implementation authority. Pin: `4594e44b6b851511ae5471e52f232bce57d16856`. The single execution request is [PLAN_AND_CODEX_PROMPT.md](PLAN_AND_CODEX_PROMPT.md); this file elaborates its M5 and preserves later questions without selecting all of them.

## 1. Shared experiment discipline

Start from the current committed Ring/Amulet candidate or compiler-probe artifacts. Read the full request/treatment/evaluator identity; a supplied graph is allowed for this fixed-policy experiment, never as an undisclosed seed in a product solve. Keep the original modifier universe, clean goal, exact item and control entry, prices, scope, complete physical outcomes, resource limits and checker tolerances. Do not transplant state/operator IDs across fresh contexts.

Use at most one candidate family per arm initially and reuse compatible evidence. The purpose is to avoid another long search programme before knowing whether either optimization has a useful domain. Native information that is absent from compact reports can be collected by one narrow probe, not a cross-base census. Do not derive speedup from graph size alone.

The two arms measure different potential work savings. A can avoid building distinctions. B can reuse already-built and justified interior response. They may ultimately complement one another, but that is not a reason to implement both now.

## 2. Arm A — contract-derived representation requirements

### The discriminating question

Do the native backward observation contracts identify distinctions paid for by today's candidate layout that the actual selected controller never needs, **after** accounting for future legality, rewards, goal truth, routing, surviving modifiers and every compared alternative?

### Smallest useful procedure

Recover one real compiler-declared entry and complete local programme/continuation candidate. Identify the existing refined selected-action contracts and observation vocabulary. Propagate requirements backward to a fixed point, retaining selector preimages and persistent context. An absent contract is unknown, not permission to drop a distinction.

Export a compact ledger with each discriminator's reason: current action, downstream survival, bench conflict, goal or below-tier distinction, router predicate, persistent offer/checkpoint, compared-alternative requirement, or unproved dependency. Compare:

| Projection | What it answers |
|---|---|
| Current private reduced layout | Actual baseline paid representation |
| Existing conversion-only omission control, where applicable | Reproduces the already-known reduction, not a new result |
| Per-control-node required observations | Potential selected-controller reduction |
| Union required by the present single-layout constructor | Reduction the current architecture can actually use without a new multi-layout owner |

Report original/new junk classes, member distinctions, applicable predicate sets, and which initially removable distinctions return after closure. Do not spend time constructing broad rows if the usable union is unchanged.

If the union is smaller and native contracts support it, one isolated row/option probe may compare support size, logical work, elapsed time and memory under the same physical entry. This is a diagnostic using an existing constructor, not permission to land a general candidate-layout adapter. Any emitted diagnostic controller still receives full original-root evaluation. Keep first-policy and scheduling preservation as requirements for a later implementation experiment.

### Stop and successor gate

Stop if no distinction disappears, the existing constructor cannot express the narrower requirements, bench/routing requirements restore the partition, or a member-domain counterexample breaks equivalence. Do not replace a negative global-union result with a misleading per-node class count.

Select an adapter successor only with a native-valid reduced representation and evidence that the associated construction/checking is a meaningful current cost. A smaller layout on an irrelevant candidate is not enough. Its first tests must include mixed bench conflicts, overlapping goal membership, locks surviving the operation, hidden contexts, clean-goal cleanup, and an alternative that needs an observation ignored by the selected action.

## 3. Arm B — changed-controller response reuse

### The discriminating question

Do actual related candidates share a sufficiently large **semantic** interior, and a sufficiently small response boundary, that retaining its checked response costs less than cold evaluation over the comparisons the current bounded wave will actually perform?

### Smallest useful procedure

For the current base controller and one actual changed candidate, align item/control states and native laws only where that alignment is justified. Count unknown mapping separately. A shared node label or identical JSON substring is not a semantic identity.

Name the boundary induced by changed selected decisions, changed guards/routing, all relevant new entries and changed observations. Record what must be invalidated transitively. Estimate or materialize only the minimum sparse response needed to the real boundary. Retain goal, failure and unsupported categories separately; do not convert an unsupported branch into a terminal value of zero.

Measure these costs separately:

| Cost | Why it matters |
|---|---|
| Native pair/row discovery | May dominate and be unaffected by reusing a numerical factorization |
| Observation/refinement construction | A new global predicate can invalidate old cells |
| SCC/linear-system preparation and solving | Candidate target for a response or factorization reuse |
| Graph/entry matching and invalidation | Reuse is not free |
| Response/fill storage and coexistence with old/new graphs | Must fit the original aggregate/evaluator allowance |
| Required validation, including full cold check during qualification | Must remain visible in all-in experiment cost |

The estimated batch is the actual bounded wave, not hundreds of imaginary future queries. For m comparisons, compare response build plus matching/update/solve/validation against m cold evaluations. Do not explicitly build a dense inverse in native code. A sparse interior can have a dense boundary response.

### Stop and successor gate

Stop if most native pairs remain unproved, a router/observation change invalidates most of the interior, boundary fill is large, or saved work is smaller than response construction/accounting. A large unchanged graph-byte fraction is not an advancement condition.

Select an evaluator-owned response prototype only when the measured relevant phase is dominant, mapping is defensible, the boundary fits, and conservative all-in cost predicts a benefit for the actual comparison count. Keep the full original-root native evaluator as the pilot's authority and report reuse-only versus full-qualification time separately. No new issuer or permanent recipe cache follows from this gate.

## 4. Selection record

Produce one table for both arms: request/graph identity, supported domain, removed/reused work, unaccounted domain, memory cost, observed versus estimated time, first invalidating counterexample, and go/no-go reason. Choose one next implementation experiment or neither. ## 5. Other useful questions, explicitly not active runtime work

### Recurrence-aware ranking

After eligibility and response coverage are established, compare the existing exposure score with complete local advantage/feedback correction. Keep entries, counts, prices, candidate budget and service cadence equal. One node can affect many physical rows. Unknown tails are unknown. The complete returned original-cost graph, not a larger predicted saving, is the outcome. No extra wave is justified solely because a score changed.

### Source/native discrepancy

Use existing same-controller data first. For a fully aligned source vector, the root error is the occupancy-weighted residual. If only K is aligned, use the stopped first-hit formula in [MATHEMATICS.md](MATHEMATICS.md), keeping hᵀV_U explicit. If the root itself is unaligned, say so. The 4,186-fold scalar ratio does not diagnose numerical error, and an artificially completed vector does not explain the source calculation. This diagnostic is a possible by-product of a successful response alignment, not a separate long campaign.

### Structural lower refinement

Freeze the actual cheapest optimistic controller and identify one incompatible persistent witness or outside-domain relaxation. A synthetically impossible switch from mode x to y is a falsification model, not proof of a native defect. Any valid coupling must contain projections of all relevant proper native policies and charge original cost once. A stronger local lower that leaves the same cheap root route unchanged is not the desired result. Do not add another producer by momentum.

### Fixed-policy value enclosures and action-duration reporting

Preserve the known transience/residual and joint-duration mathematics with explicit native coefficient/rounding obligations. Neither an interval enclosing one policy nor a completion CDF supplies all-action optimality. An expected-action penalty is not a deadline guarantee. Start later from a fixed verified graph and an explicit accuracy/cost contract; do not introduce a new public objective without a separate selection.

## 6. Research novelty posture

Schur complements, performance difference, occupation measures, fixed-point certificates and selected-policy equivalence are established. The possible contribution is the native, budget-accounted integration of compiler-defined control interfaces, observation requirements and incremental checking in an implicit SSP, with clear separation of proposal, executable-policy and lower-proof authority. It requires a sound correspondence and useful measurements; this preflight is not novelty certification.
