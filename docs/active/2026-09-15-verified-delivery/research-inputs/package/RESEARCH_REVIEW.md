Preserve the useful anytime-delivery work; elevate initialization from a disclosed limitation to a measured repair target; establish which runtime actually exposes each successful candidate owner; then use the new compiler-defined boundaries to choose a representation or evaluation-reuse experiment.

## 5. The observation/reuse competition must start before algebraic implementation

The prior Ring record is highly discriminating. A generic composition added ten global observation sets (40 versus 30), then remained in pair discovery at about 178170 states. A narrow guard/program representation avoided those extra observations; a separate repeated-memory-audit problem was also repaired. This implicates **model construction and bookkeeping**, not necessarily solving the already-constructed linear system. [R8]

That is why this review gives the representation diagnostic first preference when the two gates tie. A fast response solve cannot by itself avoid reconstructing a huge native pair graph. An evaluator response artifact only helps if it replaces substantial repeated work whose native dependencies can be identified without doing that work again.

### A. Contract-driven representation

Use `contract_observations`, `preserved_requirement`, selector preimages and the existing ordered-program/flow machinery. Include current goal tests, rewards, primitive legality, routing and persistent memory; propagate over cycles to a fixed point. Preserve all current observations unless a checked implication or sound contract removes them. [R9]

There is a crucial boundary beyond the upload's fixed-controller proposal: **a partition sound for one selected policy is not automatically sound for its alternatives.** Either freeze a complete selected controller/programme, or retain the union of requirements for every alternative the candidate search will compare. A new alternative that needs a previously forgotten distinction requires refinement or a new local context before its law is used.

Current `CalcContext` remains a global layout for its local action set. Reusing a control-indexed requirement analysis might still give the same union and no reduction. Report that negative. Do not call a future per-node quotient implemented because a smaller theoretical requirement set exists.

The first diagnostic compares the current reduced layout, the historical conversion-only restriction where applicable, and a contract-derived requirement closure on one actual candidate. Count discarded distinctions, their reasons, restored legality observations and any resulting native successor support. Use a fresh physical entry and native context, never copied IDs. No expensive solve when the discriminator count is unchanged.

### B. Evaluator-owned response reuse

The Schur/first-exit algebra is valid, and substantial prior art exists. The paper by Gainer, Hahn and Schewe explicitly distinguishes stable and volatile states and their dependencies. The new native contribution would be a useful, budgeted correspondence and reuse implementation—not the identity itself. [P1; R10]

Measure semantic pair/row overlap, the changed boundary, incoming/outgoing links, observation signatures, sparse fill and the existing checker phase times. Textually equal node names are not equivalence. A new guard at an old global router can change routing or the observation layout across most of the old controller.

Preserve the interior response `T=(I-Q_II)^(-1)Q_IB`, its goal/failure exits and price-independent resource/count response. Recompute boundary entrance law and cost when the boundary changes. If a new candidate changes the interior's exit law, reward or observed state domain, invalidate the response. Use sparse solves, not an explicit dense inverse.

The break-even test is total construction, correspondence, response storage, invalidation and solve cost versus cold checking over the **small number of comparisons actually permitted by the top-three/one-wave search**. Do not assume an unbounded sequence of future variants amortizes a cache that is not useful for this run. Retain full independent evaluation for acceptance during a pilot. Avoid claiming total runtime savings when cold verification still dominates.

## 6. Recurrence-sensitive economics is sound research, not a ready scorer replacement

The inspected score `expected_visits × continuation_value` is repeated exposure to future spend, not a recoverable-spend decomposition. It can double count tails: a length-ten unit-cost chain costs ten, while those products sum to 55. A heuristic may use that score; it is not a correctness defect. Eligibility dominates before ranking: excluded contexts never reach the score. [R3; U2 F3/§4.2]

For a single native row change on a common proper domain, the exact inverse-update formula adds a recurrence denominator. For multiple changed rows it becomes a small boundary linear system. Both are detailed in MATHEMATICS. A patch spanning several native item/control pairs is not a single row merely because it changes one compiled node or one option call.

Do not run this ranking experiment in the immediate programme. First obtain compatible complete tails or useful response information without exhausting the budget. Then compare with identical eligibility, entry quota, candidate construction and original prices. Missing tails stay unknown; a proposal-only score never becomes an upper, prune or probability.

## 7. A sharper discrepancy diagnostic without invented source values

The Conquest source value is about **4186.71 times** the native controller value. This is not evidence of a floating-point failure. The complete-controller identity `V-v=(I-Q)^(-1)(c+Qv-v)` provides a way to attribute discrepancy *when the source vector can genuinely be mapped onto the native controller*. [R7, R11; U2 F6]

The new derivation in this package handles incomplete alignment explicitly. Partition the native controller into mapped `K` and unaligned `U`, with the root in K. Let

`a = c_K + Q_KK v_K - v_K`, `d_K^T = e_s^T(I-Q_KK)^(-1)`, `h^T = d_K^T Q_KU`.

Then

`V(s)-v_K(s) = d_K^T a + h^T V_U`.

The second term is a **named first-hit continuation remainder**, not zero. It can be bounded only with compatible native endpoint evidence, or left symbolic. This lets a diagnostic show precisely what is explained and where the mapping stops instead of fitting a root-ratio correction. The formula is algebraically valid for any finite chosen `v_K`; claiming it explains *source* semantics additionally requires a faithful source/control mapping.

A mapping-coverage or compact residual projection may be captured when the same preflight data already supports it; no separate discrepancy campaign is selected. Building a new estimator or lifting unsupported source values is not selected.

## 8. Other research is retained, with separate stop conditions

**Structural lower refinement.** A more accurate solve cannot exceed the same optimistic model's optimum. The uploaded persistent-mode counterexample is sound: independently choosing the cheap member at each phase yields two, while preserving a mode yields 101. It is not a discovered native defect. Preserve it in the lower chapter as a diagnostic pattern. A future investigation must identify one real incompatible optimistic witness and justify a coupling relation covering all native policies, with costs charged once. No new lower implementation now. [U2 §5; P3]

**Transience/error witness.** For finite nonnegative Q, `w >= 1+Qw` gives a transience bound; a native-safe residual enclosure yields a fixed-policy interval. The project already contains related residual mathematics. Native coefficient provenance and outward-safe checking—not the inequality—are the missing correspondence. A fixed-policy lower endpoint is not an MDP-optimum lower. No acceptance/tolerance change now. [R11; P4]

**Action-budget reporting.** The first useful feature remains fixed-policy completion probabilities, not a silently changed cost objective. Duration and exit context must be joint information; expected counts and endpoint marginal probabilities do not determine a deadline law. Zero-primitive routing also needs correct closure. Preserve the generating-function argument and exact counterexamples; no hard-budget optimizer in this programme. [U2 §7; P5]
