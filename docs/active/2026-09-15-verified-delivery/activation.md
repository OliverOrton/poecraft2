All paths use the actual registered, permitted, priced action scope. Calculator
captures the envelope and pins prices before constructing the priced candidate
goal; neither UI checkboxes nor a node label authorize a native action. Product
profile enables high-impact upper scheduling and goal-progress gating, disables
ordinary economic restart and Imprint programmes, and retains explicit overrides.

Root proposal service requires high-impact uppers, exact root, no ordinary
economic restart and the ordinary root-item contract. The legacy entry query
requires an independently evaluated retained controller and compiler parent
bindings. It requests Exalt/Annul/Scour; execution modes additionally request
primitive Alteration/Augment. Mandatory option interiors do not become decisions.
Magic acquisition requires one goal fracture, no mutable progress, no fractured
junk or other persistent context, and an actual global primitive boundary.

The later ordinary wave occurs once after a full protected Essence proposal
**attempt reaches its post-service boundary**, including its count/cost views.
The boundary also follows a refused attempt; it is not itself successful
verification. Mode, no pending blocker refinement, no Finish/resource stop, a
root-only winner and matching compiler graph-local provenance are additional
guards. Entry evaluation requires unchanged authority, complete graph checking,
root reconciliation and global routing with no checkpoint/offer. Clean proposals
require Rare, one missing goal, exact goal-only occupancy and a primitive decision.
Only the three largest visit-times-tail exposures are shortlisted; that score is
not additive spend or predicted savings. Actual proposal service is counted later.

Progress exposes configured state/row/transition caps and checker overrides (zero
means inherited). Candidate states/pairs/transitions inherit discovery/row/edge
limits; memory is the minimum of remaining aggregate bytes and explicit checker
cap, or the return owner's historical 1 GiB ceiling. Default profile stays 1 GiB,
200k discovered states, 1.215M rows, 10M transitions and 50M shared work. The wide
lane is separately 8 GiB aggregate, 4 GiB checker, 400M work at its frozen manifest.

`legacy_entry_query` and `ordinary_entry_query` count only declarations/entries
already visited by the existing bounded query. No-authored and unsupported counts
refer to declaration inspection. Hidden-context/unavailable-tail precede physical
clean eligibility; clean rarity/occupancy/goal-debt rejection does not say a legacy
Magic/dirty family was rejected. Shortlist/service/not-serviced are clean proposals.
Missing prerequisite counts query calls refused by its outer guard; an uncalled
ordinary query stays zero, with protected-Essence/ordinary-attempt flags disclosing
its unmet service opportunity. Refused/capped queries are separate. These fixed
counters add no census, admission, scoring or probability authority.

A possible successor is a default-off **cost-only** capability experiment with a
real precursor controller, an explicit post-precursor service slot and separate
browser resource qualification. Merely remapping the public flag to count mode,
inserting Ring's weight or deleting eligibility guards does not meet that gate.
