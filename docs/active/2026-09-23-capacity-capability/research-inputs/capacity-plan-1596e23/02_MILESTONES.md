## P1 — Choose exactly one mechanism using the witness

| Branch | Required evidence | Selected implementation boundary | Refuse this branch when |
|---|---|---|---|
| A: optional-work resource deferral | One optional transaction refuses; rollback is valid; different useful work fits the remaining budget | Existing action/admission/refinement owner records a resource-blocked obligation and continues other eligible work | Memory is actually consumed by mandatory retained state; cumulative work is exhausted; rollback cannot preserve existing state |
| B: storage/lifetime correction | A specific simultaneous duplicate, stale conservative charge, or reconstructible retained payload explains the refusal | Correct that owner's lifecycle, exact payload sharing, or bounded cache retention | Savings require losing graph/proof identity, undercounting live memory, copying private IDs, or broad unqualified eviction |
| C: fresh private candidate representation | The first expensive law is inflated by an identified removable observer; a native-defined restricted policy family has complete dependencies and a genuinely smaller fresh layout | Reuse the existing private candidate builder for one measured family/subset, with whole native checking | Same-layout subset is unchanged; complete member mapping fails; required routing/bench observations restore the distinctions; checker/parent overlap still cannot fit |
| D: no bounded native repair yet | None of A–C has a supported witness | Retain useful diagnostics, report the exact representation/service prerequisite | Do not replace this outcome with a capacity increase, new solver, guessed score, or repeated earlier seed variant |

**Default preference when supported:** A first, because avoiding one oversized optional transaction may expose an already available useful controller without building a new representation. B wins when actual erroneous/duplicate ownership is demonstrated. C is justified only by actual discriminator and support reduction, not the old general abstraction proposal. This ordering is a research judgment, not an assertion about the currently unknown Ring cap owner.

The existing Imprint-specific resource-deferred path is a source precedent for A. It is not a drop-in implementation for memory, other actions or selected policy tails. State-local preparation currently throws for other resource-deferred cases. Review the exact owner and all downstream completion flags before generalizing anything.

## P2 — Implement the bounded native treatment

### A: resource-block one optional task, not the entire proof obligation

Use the existing action/admission/refinement structures. Preserve a work item's exact source namespace, operation/program identity and reason for deferral. Keep completed rows immutable. An interrupted distribution is not cacheable as a normal complete row; all mass remains represented either by a completed native law or an explicitly open obligation.

Distinguish a rejected prospective memory reservation from a hard global budget exhaustion. After valid rollback, other work may proceed only within the existing aggregate cap. Preserve the first-refusal history even when final termination later occurs by ordinary Finish. Do not clear cumulative work, allow an allocation beyond the limit, or pretend the family is legally inapplicable.

Bound retries by relevant semantic or headroom change and existing opportunity scheduling. General row growth, clock ticks and repeated status reads cannot repeatedly rearm the same failing transaction. Record a terminal unresolved disposition if no remaining useful work fits. No new permanent queue or full-state resource scheduler.

If a verified artifact exists, keep it throughout. If it does not, use the existing first-policy and bounded-finalization paths; do not announce an upper or Finish availability from a proposal. A deferred action cannot supply an optimality proof or be treated as absent when computing a lower.

### B: charge real simultaneous storage and remove only redundant ownership

First characterize the allocation inventory and its aliases. Existing exact transition payload sharing is the baseline. Consolidate only a demonstrated duplicate or release only a payload whose owner permits reconstruction without changing its semantic identifiers. Keep distinct row/work obligations even when immutable storage is shared.

Test old/new capacity overlap, active coroutine frames, detached verification, compiler/evaluator copies and failure paths. Reconcile both fast and audited estimates. An ownership-accounting bug requires a correctness fix; a deliberately conservative reservation requires a justified new admission bound, not relabeling it as a leak.

### C: restrict candidate search, not the full request's proof scope

Select a small family/subset from native legality, transition and program-dependency contracts. Do not choose from a base name, archived graph IDs, only incumbent use, or apparent goal-count progress. Reuse `CalcContext` and existing private continuation construction; preserve the original modifier universe and exact entry.

Compare full layout, same-layout subset, and fresh subset. Include all fixed/conditional dependencies and downstream routing observations. Check whole old-class member mappings, not representatives. Old states, values and row IDs remain in their original namespaces. A small private constructor followed by a huge native checker is not an end-to-end win: parent, child, compiler and checker must fit concurrently inside the same total budget.

Only complete proper emitted controllers can replace the incumbent after independent original-root checking. Omitted private actions remain full-request proof obligations. No general dynamic quotient or second observation-liveness engine is selected.
