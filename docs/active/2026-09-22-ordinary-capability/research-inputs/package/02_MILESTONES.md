# Selected C0–C4 programme

## Outcome and comparison order

The main objective is **lower original-price expected Chaos in ordinary product
search after the first verified policy**, with immutable complete artifacts and
unchanged target/capacity contracts. This supersedes the previous next-step idea
of automatically staging the replay-partition owner.

The primary case is current CB02 Conquest-four. Historical native reference:
3746.1319409485764 Chaos; historical browser reference: 5218.040949685988. Full
recovery would be about 28.21% below the historical browser controller, but the
actual treatment percentage is always measured against C0's fresh baseline.
A reference already attained at C0 is not a new result.

## C0 — Current product baseline, bounded initial scope

1. Check HEAD/dirty state and current CI. Both reviewed push workflows passed;
   do not relitigate T0 without a new failing witness.
2. Add `default_finish` (or an equally explicit name) to the existing Calculator
   probe. It must NOT click Finish upon first verification. Leave the existing
   `finish` and cancellation modes unchanged. Add a small test proving the
   unattended branch issues no manual intent and respects the original deadline.
3. Resolve the frozen CB02 request from the existing core manifest. Read actual
   run options/actions/prices/caps from native and worker traces, not filenames.
   No screenshots or hand-recreated item. Run one current source-matched native
   control and one actual Calculator+worker unattended control, serially, using
   normal batching and the existing supervisor. Reuse a truly compatible receipt
   instead if it already answers the same final-quality question.
4. Record the first verified artifact and every distinct later verified improvement
   observed by the existing event/portfolio owner; completion time, source estimate
   role and candidate identity; final checked graph/cost/count and stop cause.
   Keep observation gaps explicit. Do not serialize every row/round.

The reference graph may be independently inspected and used in isolated evaluator
fixtures. It is never a product search seed, dependency database or hand-authored
solution injected into the run.

**Gate:** one compact identity-qualified baseline verdict. If the current product
already achieves the reference, go to the bounded resolved-gap rule below rather
than claim a recovered capability. If real native and Calculator problem inputs
differ, first make the experiment honest. Do not call an action-capacity or guidance
change a platform-only comparison.

### Resolved-gap rule (prevents chasing an obsolete problem)

When current CB02 is already at/below the reference, preserve that finding. One
bounded successor diagnosis is allowed: compare its earliest complete promising
candidate and verified improvement timing under the same request, or inspect one
existing ordinary non-armour case for the **same already-identified selection/
completion limitation**. Select the exact case and target before timing treatment.
No native gap or denied opportunity found means stop with “no capability repair
justified on this evidence,” not a partition rewrite, an arbitrary larger goal,
or a whole Ring public-activation programme. Oliver receives the result and next
choice. This is a stop contingency, not the default deliverable.

## C1 — Locate the first missing useful stage, not merely divergent counters

Use C0's graphs and existing events. At most three justified current-run candidate
probes may receive separate bounded full checking for diagnosis; their work must
be included in diagnostic cost, and an external probe is not a discovery success.
Do not replay arbitrary private IDs into another calculator.

Map relevant physical item/control decisions and native capabilities in the
reference and fresh returned policies. Start with the post-acquisition contexts
suggested by the fingerprints, but test that inference against actual routing.
Do not interpret aggregate old spend as causal savings or frontier size as closure.

Assign the first blocker to exactly evidenced stages:

| Evidence | Interpretation / permitted next branch |
|---|---|
| Request or action scope differs | Correct experiment identity; no automatic public-mode activation |
| Distinct complete candidate rejected by source-cost screen | Test independent native cost; select Branch A only if beneficial |
| Complete promising candidate waits for safe checking/service | Branch A using existing candidate owner |
| Native permitted row exists but required positive exits lack a route | Branch B: one complete continuation family using existing owners |
| Candidate cannot be represented at its real decision boundary | Name missing observation/provenance; narrow repair only if native contract proves it |
| Complete candidate hits a real checker cap | Disclose cap and scope; preserve refusal, do not raise allowance |
| Candidate verified cheaper but not returned | Repair narrow existing adoption/selection route; do not add more search |
| Complete native comparison is more expensive | Economic negative for that candidate; do not call it incomplete |

Required witness fields: request/run/candidate identities, source value and its
role, actual selected support closure, missing typed dependencies, native entry
and routing, estimate-screen outcome, earliest service opportunity, actual service,
full check outcome and publication result. Add only missing bounded fields at the
existing observation points. No permanent ledger or new monitoring service.

**Gate:** a falsifiable causal statement and the smallest affected owner. The
300-ms synchronous replay partition is not selected simply because it is present.
A new correctness/memory defect at the selected boundary is repaired before
capability work; unrelated debt stays queued.

## C2 — Implement one bounded original-cost intervention

### Branch A: materialization/checking after an incumbent

Preferred when C1 finds a complete candidate or a source-ranking false negative.
Use the existing selected-policy capture, portfolio and cooperative assertion.
Retain the first verified artifact; only complete independently evaluated native
original-root output may replace it.

Allow at most **one additional exceptional whole-root candidate check per run** in
the initial treatment, over and above the normal existing path. This is an explicit
experimental bound, not a new completeness claim. The candidate must be current-
run, structurally distinct in selected semantic decisions/support, complete, legal,
priced, compatible and admitted within existing resources. Arbitrary row-count
increments, another round or unchanged source estimates do not rearm the slot.
A candidate rejected or capped remains a recorded result; do not recheck it on
unchanged inputs. Source-score relaxation affects proposals only, never full-scope
retirement or lower/upper acceptance.

Do not promise “check all complete policies.” The extra check must be selected by
the diagnosed opportunity using the existing deterministic candidate order or a
separately declared single selection change. Retain bounded work/task ownership,
ordinary discovery service and Finish/cancel behaviour. No one-unit evaluator
returns; no whole policy copy every tick; no new public guidance weight.

### Branch B: complete one useful native continuation family

Use when the candidate never becomes complete, not as a fallback speculative
rewrite after Branch A fails. Reuse the joint-continuation or private-return owner
appropriate to the diagnosed namespace. Preserve the real physical entry and
observation timing. Generate native actions/program dependencies by contract,
not by copying the reference graph or checking base/goal/node IDs.

Coherent setup/attempt/cleanup or multiple changed rows may need joint completion:
a locally unprofitable first action can enable a cheaper full continuation. Use
complete positive-mass exits, existing native recovery, and compatible old tails
only where their actual entry domain is certified. Unknown tails are not zero or
old-root values. Complete the native composed graph and independently evaluate it
from the original request before retention. No automatic all-family expansion.

One candidate family and one existing work owner are selected. At most two
substantive implementation variants without a new causal premise; then stop and
report the limiting contract. No second search engine, observer framework, response
cache or duplicated checker.

### Publication-only exception

If the cheaper current-run graph is already fully checked but lost at selection,
repair the existing owner directly. Preserve graph/certificate/context/value as one
bundle, exact versus bounded status, ties and original-root authority. This is a
capability-delivery result rather than new candidate synthesis.

## C3 — Demonstrate useful and generic capability

Primary full recovery: ordinary unattended Calculator/worker returns C <= reference
plus the established tolerance, on the unchanged four-minute product profile.
Alternative material partial: at least **20% cheaper** than the fresh baseline;
report residual gap, do not call full recovery. Smaller genuine gains receive their
actual number. These thresholds are proposed milestone choices, not forecasts.

A native-only recovery, a saved-graph evaluator pass, a diagnostic mode result, a
probe verification after watchdog, or a cap increase is not the product success.
If the endpoint already matched at baseline, a predeclared >=10% earlier time to
the same useful cost target can qualify separately with counterbalanced timing,
but not as new strategy quality or a reason to move Finish earlier.

Generalization requires a native renamed/permuted identity fixture and a second
structural case exercising the chosen entry/closure/admission rule. If the feature
is intrinsically restricted to a native action's availability, test both a second
supported context and a native-ineligible non-armour control. A non-applicable
control is not a second base cost win. No base-name, fixture hash or archived-node
switch in production. A generic admission change additionally needs an affected
real non-armour preservation control when practical.

Protect C5's first usable policy and final original-cost result, exact Regalia, and
the selected owner's other qualified paths. Test actual Finish during the new
optional work, tiny positive trap, changing observations/prices/generations,
incomplete/capped candidates, and stale-root-only tails. All stored work counts
and total memory remain charged. A repeatable >10% first-policy delay on the C5
control is an investigation/rejection trigger, not a universal statistical theorem.
The existing 250-ms residual failure stays visible; do not introduce another large
unbounded unit or conceal a materially worse release/control interval.

## C4 — Canonical knowledge, scoped release and stop

Record separately: current baseline, causal witness, added candidate coverage,
verified original-cost improvement, runtime/profile activation, first policy,
final result, proof status, and all response gates including inherited failures.
Integrate accepted reasoning at the canonical owners named in the documentation
plan. Retain negative variants and graph identities once. Pass focused tests before
long integration; no unchanged-controller simulations or all-corpus repetition.

If two substantive variants fail and no new premise exists, deliver the negative
and stop. Do not expand into partition staging, a public Ring lift, numerical
closure, dynamic quotienting, hard action budgets or another global sweep.
