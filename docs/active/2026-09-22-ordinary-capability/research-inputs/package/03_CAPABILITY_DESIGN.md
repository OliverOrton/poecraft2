# Existing-owner design and specific research hypotheses

This is a design selection framework tied to inspected current source, not a claim
that a particular branch is already the cause of the C4 gap. See [SOURCES.md](SOURCES.md)
R9–R14 and the [milestone gates](02_MILESTONES.md).

## 1. Distinguish the three objects being compared

1. **Selected source policy:** rows, source values and observations in a calculator
   or restricted solve snapshot. It can be stable without being a verified physical
   policy or a globally valid lower.
2. **Materialized native controller:** a complete candidate graph with original
   entry, native operations, observations and actual control routing. It is still
   unverified until the existing assertion/evaluator accepts it.
3. **Verified retained artifact:** executable proper original-root graph, full
   certificate/context and evaluated cost under the existing numerical contract.
   It may be root-only relative to the parent solver.

A rejection at one boundary must not be described as a mathematical rejection at
another. A candidate completion could be absent even though the primitive is in
the registry. A feasible saved graph proves neither current discovery nor admission
within the internal candidate allowance.

## 3. A source-screening witness is not a guessed “fix”

The diagnostic should capture one complete current-run snapshot at a normal safe
candidate boundary, together with the exact source role/value and gate result.
Check it using the existing native original-root assertion with original prices
and the declared allowance. Include every outcome and hidden-control requirement.

If the snapshot is not complete, that result selects the support question—not a
bypass into a partial check. If the graph is valid but expensive, the heuristic did
not miss an improvement for that graph. If it is cheaper but its source score was
worse than the incumbent, it is a real counterexample to using that score as an
exhaustive candidate filter, though the old filter may still have been reasonable
bounded-search guidance.

The source code's early comparison may avoid costly duplicate graphs. Preserve
that normal optimization for identical selected semantics; the proposed exception
is bounded, keyed to a distinct complete opportunity, and accepted only by the
native evaluator. Do not claim every changed selected-row vector deserves service.
Before assigning a numerical meaning, confirm source and compiled graph represent
the same policy; strict lift may reoptimize, as the last Fracture investigation
already demonstrated.

A source value that is an exact native candidate cost or independently valid lower
can support the appropriate rejection. An upper estimate above the incumbent or
an unrelated workspace value cannot prove rejection; see the mathematical notes.
No scalar conversion learned from the earlier large Conquest ratio is selected.

## 4. Diagnose service on the actual native semantic object

For each relevant opportunity record:
- run target, selected-graph/support identity, candidate owner and generation;
- exact physical entry or member-domain proof, node/observation/controller context;
- source value role, current verified root cost and reason for withholding capture;
- completion of selected rows, required choices and all positive exits;
- readiness, service and termination events with source/observation clocks;
- checker allowance and aggregate remaining capacity, refusal stage, evaluated
  original-root cost and selected output identity.

These fields extend bounded existing samples, not a new per-state census. Querying
must be passive and charged. A root expectation times occupancy is an exposure
heuristic; do not label it savings or additive spend. The first difference between
source and returned graph may be an earlier condition/decision, not the action with
the largest aggregate cost.

## 5. Complete families rather than selectively hopeful branches

Reference inspection may suggest a native setup/attempt/cleanup pattern, e.g.
side-specific finishing after retained progress. Runtime construction must derive
its permitted parameters and entry restrictions from native action/refinement
contracts and actual request scope. The archived graph is a comparison artifact,
not a template read by the product at runtime.

All failed attempts, destructive effects, setup prices, cleanup, and possible
returns remain in the composed law. Goal-progress count is not clean success.
An old controller can provide a tail only on its certified physical/control domain;
matching rarity or a goal mask is insufficient. A finite root certificate does
not price another item. Complete independent flattened evaluation remains the
acceptance owner even if a stopped-law model orders the proposal.

The mathematical complementarity example explains why an action that does not
immediately lower the root cost can still be part of a useful family. It does not
justify exploring every setup or retiring goal-neutral actions. The programme
selects one measured capability and leaves ungenerated competitors open for proof.

## 6. Structural boundary and debt budget

Allowed: unattended probe mode, a necessary passive rejection reason, semantic
identity admission, one correctly owned pending dependency/candidate, or a precise
native observation repair required by the selected branch.

Not selected: staging `refine_closed_probabilistic_partition_replay`, replacing the
compiler, a universal writer/task helper, moving all anonymous headers, changing
proof ledgers' authority, raising memory/state caps, changing WASM optimization,
adding a new native mode to every public request, or reopening negative response/
representation experiments without new evidence.

If the verified cheaper candidate specifically cannot complete because of the
known partition cap/indivisible work, record that witness. Only then propose the
smallest separately identifiable blocking repair. Do not preauthorize a shared
partition rewrite merely because its old 300-ms gate is still red.
