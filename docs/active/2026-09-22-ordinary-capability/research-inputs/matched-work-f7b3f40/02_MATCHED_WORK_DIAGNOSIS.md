# Controlled diagnosis: same target, explicit call policy, measured useful work

## Start from a falsifiable three-way distinction

1. **Different search trace:** caller boundaries cause different row/service selection, reoptimization, candidate attempts or starvation.
2. **Comparable committed trace, different active work cost:** the same relevant native operations are repeated or take longer on the product runtime.
3. **Comparable native work, expensive surrounding activity:** bridge conversion, observation, rendering hooks, event-loop waits or persistence consume the wall window.

Mixtures are possible. Repeated rows, observations and elapsed samples alone do not discriminate them.

## Minimal initial arms

Resolve inputs using the existing runner/Calculator owners. Use the repaired f7b source and original product allowances. Reuse compatible raw evidence first; the older C0 trace is a locator, not a current timing control after another change.

| Arm | Runtime | Requested native work ceiling | Host behaviour |
|---|---|---|---|
| N8 | Existing native benchmark | Fixed 8 | Existing native supervision |
| WA | Actual Calculator worker | Existing adaptive 1–8 | Unchanged ordinary event loop/reporting/default Finish |
| W8 | Same Calculator worker/module | Explicit diagnostic fixed 8 | Same ordinary event loop/reporting/default Finish |

Initially collect **WA and W8 serially**, using current native evidence when identity and required trace coverage permit; run a fresh N8 only for a missing compatible comparison. Use the actual `default_finish` probe mode. Do not perform a 3×3 quantum grid or run wide dirty modes.

`chunkSize: 8` is a ceiling in current worker code, not fixed-eight service. The special fixed-1024 qualification route is not a stand-in. Add at most one test-only, invocation-bound work-policy control to the existing worker/probe; defaults remain unchanged. No per-unit `yieldEveryStep`, suppressed cancellation, virtual free setup, longer deadline or manual early Finish. Record requested **and actual** native units/early returns where available. A native call may execute less than its requested ceiling.

Do not change candidate seeds, lower producers, action prices, program scope, reforge budgets, progress capture and call policy together. A diagnostic fixed-eight win is evidence to select a treatment, not automatic permission to ship it.

## Compact trace required

Retain the full resolved target and execution configuration, actual source/build/data hashes, Node/V8 versions, normal release settings, clocks, deadlines and host admission. Within the interval around C0's 24844-to-42681 rows (or its current semantic counterpart), record:

- owner/stage and committed-generation boundaries;
- selected candidate/row/service identity, completion/refusal reasons and pending support;
- cumulative real native logical work, selected-row changes, important numerical restarts and candidate-check attempts;
- native call count and quantum histogram, total native-call wall, bridge/progress wall and worker elapsed;
- known complete coverage versus open obligations and the final selected graph;
- trace coverage/omissions, not just a final ring-buffer suffix.

Use existing counters and events first. Capture a bounded rolling summary or drain existing sequences into the test process at coarse intervals if needed. Do not log every transition, serialize a complete report each event, or double-count nested timers. A hash is a useful localization signal, not proof of semantic equality. Expand one divergent block to native action/source/row descriptors only when needed. Foreign state IDs and equal row counts are not cross-layout identity.

Wall decompositions must cover one clock/interval. Native-call wall includes the binding call as actually timed; subtract only non-overlapping measured pieces. Scheduling/wait time is not automatically pure overhead: it may be required for controls. CPU profiling and cold/warm probes are diagnostic, not acceptance timings.

## Decision rules

**W8 reaches the cheaper graph and WA does not:** identify the first consequential change in useful work/service. Decide whether a stable product call policy is sufficient and safe across controls, or whether one internal service decision should be tied to a complete semantic epoch instead of host-call frequency. Do not declare all solver steps grouping-invariant. Preserve prompt cancellation and bounded native continuations.

**WA and W8 follow comparable operations but both miss:** measure the dominating native owner/host interval. Select one repeated-work or active-time repair only when its cost is demonstrated. Do not add a response cache or representation adapter from general plausibility. The final result still needs ordinary complete evaluation.

**W8 changes the trace but loses or stalls:** reject that call policy. A changed row count or faster initial verification is not compensation for a worse final original-cost strategy. Analyze at most one observed internal cadence issue; no blind quantum tuning.

**Candidate exists, fully checked but not returned:** use current artifact/selection evidence to repair the specific delivery failure. Do not reopen generic publication ownership or use an unverified estimate as the candidate.

**No current gap:** report that without inventing a new target. Stop or present one separately scoped next capability recommendation; do not enlarge this programme automatically.

**Actual native probability/price/goal mismatch:** stop the performance branch and preserve the smallest correctness witness. Neither alternate floating-point tolerance nor a source value substitute is authorized.

## Change selection and stop

One generic implementation branch, at most two substantive failed variants without a new causal premise. Counting ordinary build mistakes as an experiment is unnecessary; repeating a failed scheduling premise under a new parameter is not new evidence. Preserve failed records, restore rejected treatments and keep the Fracture correspondence repair.

Acceptance is actual ordinary product quality under the original wall/work/resource scope, not a diagnostic mode alone. Improved per-work efficiency and improved complete-candidate coverage can each be causal routes, but must be labelled separately.
