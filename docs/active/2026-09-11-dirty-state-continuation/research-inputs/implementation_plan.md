## 2. The source-grounded hypotheses

### H1: first-policy convenience is biasing later opportunity

`select_joint_policy_seed_row()` uses terminal debt and missing-route count for first-policy construction. For the distinct-goal, same-rarity fixtures with m required goals, g present satisfying mods and k total affixes, nonterminal debt is `max(1, m+k-2g)`. Primitive redraw progress from an empty Rare requires `2g > k`.

For Ring's two goals, a four-affix outcome containing BOTH goals merely ties the root debt. No four-to-six-affix outcome can strictly improve it. Amulet's two-of-three in four affixes also ties; three goals in six affixes ties. Pending-route count additionally precedes price/progress lexicographically. These are real preferences, not action bans or admissible estimates. The first-policy rule is not itself the post-incumbent numerical objective.

**Test:** does this preference determine which useful dirty continuations are never completed, or does the real failure occur after they are offered? Preserve the fast initial policy; show the precise causal seam before changing it. First-policy convenience must not become a permanent restriction that all useful intermediate items must remain clean or reduce debt immediately.

### H2: broad candidates are unavailable because checker resources are inherited incorrectly for the research question

`evaluate_return_graph()` currently sets evaluator states from `limits.max_discovered_states` and caps evaluator memory at the constant `kReturnEvaluatorOwnedBytes = 1 GiB`. Main solver RAM alone does not remove these restrictions. Distinguish search states, candidate-evaluator physical states/pairs, strict refinement, compiled graph nodes and final independent evaluation.

**Test:** can the already defined gated candidate be fully evaluated under a safe, explicitly raised checker allowance? Unknown-at-cap is not bad policy. More completed bridge rows are not the test result.

### H3: unused observer actions impose unnecessary policy-search distinctions

The supplied layout report attributes CB08's four persistent tags to `harvest_resist:fire:lightning` and `harvest_resist:cold:lightning`. Current registry source confirms targeted Harvest roll tags are not persistent discriminators, while conversions declare source/target/resistance. The actual leave-one-out class/support savings have NOT been measured.

**Test:** remove that pair only from a private policy-search candidate set, rebuild a fresh compatible layout, and measure the benefit. Keep ordinary acquisition, useful automatic options and all original full-scope proof obligations. This is not permission to remove every action absent from an incumbent.

### H4: empty-item return is the wrong continuation interface for useful dirty progress

The current retained proposal runs once at the first independently verified incumbent, only tries root Exalt, and skips an already-Exalt root. It is not a broad family or later-incumbent search. The current return builder follows frozen old decisions or uses paid Annul at an uncovered ordinary entry. In the successful Ring example it discards a desired suffix to return to the exact empty Rare. That is a legitimate fixed controller, not a theorem that erasing such progress is best. Repeating the old root decision cannot improve the Amulet's identical Exalt controller.

**Test:** allow native acquisition/cleanup choices to retain useful partial progress and end at actual compatible completion entries, rather than force every excursion to one empty anchor. A new boundary is never free and never inherits the root upper just because it has the same goal mask.

- preserve useful goals with an admitted protection/addition operation;
- take a broad reforge under its mandatory retry control;

Do not enumerate every option combination before helping one candidate. Select a small number of materially distinct proposals based on native effects, missing goals, side capacity, blocker semantics and the independent cost accounting. Avoid hardcoded base/action recipes and do not restrict choices to the current incumbent's action vocabulary. More realistic estimates may guide which continuation to complete, but they cannot retire actions or turn unknown values into uppers.

### Use complete local response laws rather than one universal cleanup number

For a fixed native local controller on internal states R and actual boundary entries B, compute by the existing sparse evaluator:

`g = (I-P_RR)^(-1)c`, `H = (I-P_RR)^(-1)P_RB`, `J(v_B)=g+H v_B`.

Solve the systems; do not explicitly form a dense inverse. This is a response to boundary costs, not proof that every dirty item is equivalent. Complete native exit mass, conditional draw laws, legal observations and expected costs remain required. A boundary can be a true goal or a compatible independently executable continuation; otherwise it remains unknown or part of the jointly solved new controller.

Start with a small run-discovered set of useful boundary entries. They may include partial-progress items and the old empty return. Do not create a permanent basin library, a hand-authored recipe inventory, or a second global planner. Extend the current return/continuation owner only where the measured scalar-return restriction matters.

If returns among boundaries are controlled by the new candidate, evaluate the complete resulting controller jointly. Locally terminating components can compose into a non-goal cycle. A goal mask, one materialized representative, old source lower, or root-only upper is not a boundary certificate.

### Choose for final expected cost, not just local motion

For a single complete goal-or-return excursion with cost r, goal probability p>0 and old root J, `Q=r+(1-p)J`; repeating that controller has `J_new=r/p`. Thus `J-Q=p(J-J_new)`. A tiny one-shot advantage can be amplified greatly. The current Ring implementation already exploits this identity; do not rebuild it or treat p=0 as proper.

For competing excursions, compare their evaluated repeated or composed controller costs. A cost-per-debt-reduction or raw one-shot-improvement ordering can rank them differently. Keep the best verified graph independently of the active candidate and preserve it through every failed/capped attempt.

Include dirty-but-complete goals, below-tier blockers, a harmful cleanup of a useful goal, capacity-sensitive blocking, a dirty route better than every clean-first candidate, rare positive loss, mandatory zero-goal retry, nonempty return, incompatible entry, wrong observation timing and changed controller generation.
