1. Legacy default/v1 still gives clean terminal and old compiled goal.
2. Native physical goal, CalcContext goal and emitted effective predicate agree on the selected domain.
3. L/E equality covers satisfying, missing, below-tier, extra, crafted, fractured and rarity/cap variants; E normalisation refuses unsupported overlap/variable-side/any-k claims.
4. R accepts covered extras and does not borrow clean proof values or artifacts.
5. New terminal identity is copied through exact and private calculators, caches, prepared proofs, solver resumption, original-root checking and reports.
6. Wrong root, fake/default success, altered thresholds, forbidden primitives or programme dependencies still refuse.
7. Candidate scope, raw primitive laws and prices remain fixed; goal-dependent programme stopping is rebuilt and disclosed.
8. Two different-goal handles cannot contaminate each other. Cancel, reuse, reprice and resume retain correct generations.
9. Diagnostic accounting is bounded and does not calculate new native kernels on a progress read. Complete losing support is never dropped or renormalised.
10. Proof validation distinguishes valid zero, unavailable lower, invalid vector, open envelope and actual closure.

Use the existing native Calc, Compile, Solve, S8.3/options, proof/refinement and API test owners as affected. Do not execute the broad suite after every small patch. Check the actual current harness selectors before invoking them; this packet does not invent a combined selector.

Keep the fixture's actual parameters and data identity. A distribution result that is unsupported or truncated cannot be labelled zero success.

Legacy L remains the default and should preserve the currently checked Current A5 result. Keep stronger historical A4 and exact Regalia as properly scoped references. Do not silently promote the weaker F4 A4 or erase A3's stop anomaly. A newly encountered bound inconsistency is a blocker for that arm, not a harmless comparison exclusion.

Use actual standard report comparison only for identical or proved-equivalent target semantics. Cross-target R reporting is a separate explicitly labelled contrast. Snapshot ordinary candidate state/action permissions and price identities before all comparisons.

Test losing progress, persistent context, dependency-only actions, unsupported/ineligible entry, incomplete tails, cap/cancel, preservation of the old verified artifact, stale graph/proof generations, and exactness remaining blocked when competitors are open.
