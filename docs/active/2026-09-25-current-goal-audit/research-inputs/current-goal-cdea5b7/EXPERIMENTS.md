# Controlled experimental matrix

## 1. Freeze the actual problem and algorithm identities

For every run retain:

- source/dirty/build and runtime data hashes;
- actual initial item, not only base type and goal slots;
- ordered native family/group/tier requirements, threshold and required rarity;
- resolved terminal contract, semantic normal form, and any L/E equivalence witness;
- permitted primitive descriptors, fixed/automatic grammar and disabled families;
- complete prices/dependency prices, economic Restart versus mechanic-owned replacement, Imprint and goal-progress gating;
- actual Current mode, proof producer profile, optional-retention setting, numerical contract and limits;
- actual native fixed-eight or worker adaptive/compact transport, clocks and observation cadence.

Use the existing resolver/runner and actual ledgers. The normal native A4/A5 reference uses 240-second requested Finish, 300-second native and 315-second host watchdogs, aggregate 1 GiB, 200k discovered/expanded ceilings, 1.215M rows, 10M transitions and 50M logical reforge work. Reconfirm each case: limits are taken from the resolved case, not overwritten from prose if it differs.

## 3. Three levels of comparison

**Predicate equivalence:** small native states and abstract finite signatures establish L=E; show C\T counterexamples for R.

**Matched committed work:** on tractable exact-native fixtures and bounded captured operations, compare raw physical laws and full goal-bound dispositions. For L/E require equal semantic outputs and accounting except labelled diagnostic overhead. Use existing stable semantic IDs, not assumed interning-number equality across unrelated runs.

**Wall-time Current solve:** same host, serial execution, same build and all numerical limits. Report first verification, final cost and typed stops. Reverse a pair only for a material timing claim, not automatically for every identical economic result. The study cannot infer universal runtime monotonicity from terminal-set inclusion.

## 4. Required metrics and populations

Record both the existing totals and their actual definitions: interned/discovered; queued; started expansion; complete expansion where tracked; complete rows; transient admission rows; retained transitions; V1-equivalent logical reforge work; physical/factored work; Bellman work; strict refinement states/pairs/coverage; memory live/peak and original cap/refusal owner.

Add small aggregate counters using the passive assessment, not a giant per-state export:

- `covered_clean` / `covered_dirty` / `uncovered` at relevant existing admission/service sites;
- completed rows from covered-dirty states under L/E;
- returns that lose requested coverage, and paths/programmes that preserve it;
- full-goal and partial-goal masks on actual selected/checked controllers where available;
- whether useful continuation is absent, queued, being built, complete, checked, retained, rejected by actual cost, or censored.

A low count of full-coverage dirty states does not disprove waste in partial-progress acquisition. Do not reduce the audit to that population alone.

Report `L(s0)`, best executable `U(s0)`, numerical reconciliation, absolute and relative gap, actual exactness/coverage disposition, and the terminal identity for each. A zero lower can be valid; an unavailable proof feature is different from a valid zero lower. No-policy/capped/infeasible must not collapse to an infinite-cost sample with unearned meaning.

## 5. One-action Odds control

Freeze a selected choice-free action, root and requested slot(s). Compute `P(C)`, `P(T)` and the difference from one full native distribution. Preserve native marginals separately. Include a support census by occupancy and satisfaction. Positive coverage with zero strict success is expected when every covered outcome has an extra explicit affix; it is not a solver numerical error.

The user-provided ~0.35% example is not numerically reproduced unless its complete request is recovered. A native fixture illustrating the same condition is labelled as a different fixture. Failed construction or truncated output is unknown, never zero.

## 6. Fixed-policy versus reoptimised quantities

A stopped copy of the current clean policy gives its own coverage-prefix cost and post-coverage cost, provided the first-hit boundary is declared and complete. The difference between **optimised** clean and loose values is not generally that fixed policy's cleanup bill: optimal acquisition choices can change.

The old missing compiler-boundary provenance is not permission to infer a stopped policy from node names. Capture a current provenance-bearing artifact through an existing compiler/evaluator owner when available. Otherwise report the fixed-policy decomposition unavailable and proceed with the correctly scoped goal experiment.

Do not make stopped-policy cost attribution an open-ended prerequisite for E3. Do not export STOP graphs as user strategies or checked clean uppers.

## 7. Same-target repair only

If E4 produces a repair, compare it with L/E under the identical clean target. Report the best independently checked root strategy, preservation of the old artifact under cap/cancel, changed service/composition mechanism and all-in resource cost. A reduction only in R does not qualify.

The primary success criterion for this audit is a trustworthy separation of model difficulty and implementation effects, not an arbitrary percentage. A material same-clean-target policy improvement is excellent but not guaranteed. Count increases, nicer gap ratios against a different target and predicate-refactor microbenchmarks are not substitutes.
