## E1 — resolved native diagnostic contract

`GoalSpec::terminal` now carries an extra-explicit policy and optional side-count ranges, with the legacy clean policy as its default. `CalcContext::assess_goal_state` reports rarity, satisfied mask/count, side occupancy, requested coverage, clean occupancy and final truth without adding a history or cleanup phase. `is_goal_state` consumes that assessment. `exact_goal_condition` emits the matching target, while the default L emission retains its existing condition structure. Nondefault terminal constraints enter the solve goal identity; L's hash is unchanged.

The benchmark-private `--native-goal-terminal` mode is resolved before calculator construction. L is the public v1 goal. E first requires every requested slot, a fixed native side for each, pairwise disjoint modifier membership and valid rarity/side capacity. It then **normalizes to the identical L `GoalSpec`**, including original ordered slots, threshold, options and action scope. This is not a new search representation or a product control. R changes only the terminal extra-affix policy on a fresh handle. The worker and corpus runner include the private treatment in resumable input identity. Public JSON and ABI remain unchanged. The first actual A4 E preflight caught a mistaken use of the native per-side rare cap as a total-affix cap; that new check was corrected. Both actual A4/A5 E requests then passed construction and stopped at the deliberately overridden one-state diagnostic cap, with no semantic rejection. Those cap-one files are construction receipts, not solve comparisons.

For all-required disjoint fixed-side A4/A5 slots, each satisfied slot occupies one distinct affix. Coverage gives at least the requested side counts; constraining each side to exactly those counts leaves no unmatched explicit affix. This proves E=L over valid physical items, including crafted/fractured requested members, without assuming one particular modifier tier. A threshold any-k request, overlap, variable side or impossible rarity/side capacity is refused or excluded from that equivalence. The finite two-slot signature test, native positive/negative items, compiler target guard test and independent native handle test exercise the implementation. E construction does no assignment after validation, so its calculator, operators, terminal condition and fixed solve path are L's normal form. A separate E wall run would repeat the same path and is omitted.

For the actual selected cases the fixed-side counts are A4 three prefixes/one suffix and A5 three prefixes/two suffixes. The diagnostic preflights validate those native slots against the live compiled artifact; their deliberate one-state cap stops after construction. This count statement applies to these two case identities, not arbitrary goals or an any-k request.

## E2 — proof and one-action decision

The target change is real: `T = rarity ∧ requested coverage ∧ explicit count = satisfied count` for L/E, while `R = rarity ∧ requested coverage` allows unmatched explicit affixes. The exact one-action fixture starts from a Rare item with its sole requested prefix already present and applies Exalt. Its complete, supported choice-free native distribution has two occupied-side classes with probabilities 200/800 and 600/800. Every exit remains covered and has one extra explicit affix: marginal and joint `P(C)=1`, clean `P(T)=0`, and `P(C\T)=1`. This illustrates the distinction; the user's remembered ~0.35% case was unavailable and is not claimed reproduced.

| Consumer/producer | L and normalized E | R decision |
|---|---|---|
| Native terminal, compiled guard and fresh goal fingerprint | Default authority retained | Assessment and guard are target-aware; fingerprint distinct |
| Raw mechanics and complete one-action support | Same laws and prices | Same laws for the tested primitive; goal-bound programs can change their stopping/routing |
| Universal cover, clean/carrier/identity MDP, terminal debt, strict clean, envelope and native retention (`completion_proof_lower_value`) | Existing scoped producers | No complete new zero-boundary and all-action validity proof; positive clean potentials cannot transfer |
| Operator lower/pruning, phase tables, fixed-point and closure consumers | Existing target and member scope | Depend on compatible producer vectors and target states; unqualified |
| Graph original-root evaluator (`solver_eval_helpers.hpp`) | Reconstructs the ordinary clean goal | Currently reconstructs clean target from graph edges, so a loose graph cannot be certified for R |
| Candidate/row generation and goal-dependent retry/option stops | Native Current contracts retained | Must be rebuilt and compared with an explicit target-specific programme scope |

The common-safe fallback would need to suppress every clean-dependent proof *and* dependent pruning/certification, and make the original-root evaluator target-aware. That correspondence is not established in this chunk. `pc_solver_solve` and stepped `pc_solver_solve_begin` therefore reject R before any work with a typed explanation; R remains a native calculator/compiled-predicate diagnostic only. A valid zero lower is mathematically available, but no R Current closure path is qualified. L and E retain ordinary proof behavior. No R cost, runtime or clean-policy transfer is inferred.
