# Selected design and milestones

## Objective

Implement one **role-parametric continuation family** that works with numerically non-identical goal modifiers. Demonstrate useful native policy coverage or structural reuse, not just a renamed descriptor layer. The [mathematics](02_RESEARCH_AND_MATHEMATICS.md) and [six case intents](evidence/cohort_intents.json) define the scope.

The primary test is heterogeneous armour prefixes; elemental Bow is a parallel control/application, including mixed-side extensions. No stage requires exact Fire/Cold/Lightning symmetry to succeed.

## R0 — Bind the research to actual native data and existing work

Read the current rules/HANDOFF, retain the memory programme's negative disposition, and freeze build/artifact/economy/profiles. Derive six new cases through the existing case/manifest owner. The exact suffix choices are proposed test inputs, not assumed user requirements. Validate and document their side, mutual compatibility and available tier/member partitions before any timing comparison.

Use an existing native descriptor/fingerprint path where possible. Extend it narrowly to retain each goal's full eligible tier/weight list, masks, native conflict/observation incidence and eligible action families. Preserve the full background pool. A total T1 weight alone is not sufficient. Report different-length tier arrays as such; no normalized fictitious common distribution.

Inventory actual `FixedOptionSpec` outputs at a few legitimate diagnostic carriers: missing one role, missing two roles, below-tier occupancy, and one/two suffix requirements. Compare singleton versus existing multi-slot semantics, named role binding, block/protect/cleanup and actual legal return domains. Do not enumerate a whole corpus or materialize every large kernel merely to count specifications.

Find one of the following **before a major patch**:

1. A missing multi-role stopping/continuation family in ordinary service;
2. Repeated structural construction that can be reused before expensive native binding;
3. A useful family exists but its concrete binding cannot reach the existing native service owner.

If the candidate already exists and is served identically, do not add it again. If exact symmetry fails but a structure is shared, continue the heterogeneity investigation. If no substantive delta exists, provide a precise negative; do not ship unused role metadata.

## R1 — Minimal shape/binding separation with a real consumer

Use the existing automatic/private continuation owner. Add only the small internal types needed to describe:

- role set and native binding;
- preserved roles, unresolved target roles, required opposite-side goals and occupancy debt;
- selected native capability/programme shape and exact entry/return domain;
- stopping/continuation alternatives to be completed;
- dependency identities separating shape reuse from bound kernels and evaluated costs.

Keep role-structural ownership outside a general-purpose expansion of `SolveWork::Impl` when a current programme-local object suffices. This is not a permanent recipe registry, template language, generic group framework or second planner. Native actions remain the existing primitives/options; a role operation must not appear as an invented executable currency.

A binding can expose different numbers of tiers and action realizations. Missing targeting capability is a legitimate unsupported binding, not permission to synthesize mechanics. Parameter/observation changes invalidate only the artifacts whose existing contracts depend on them; they cannot reuse a foreign native state ID, row, scalar or certificate.

Where several target queries use the same physical carrier and complete native programme, investigate sharing that complete attempt law before stop/retry specialization. Different goal-hit probabilities are allowed: each query classifies the same joint outcomes differently. Preserve the union of required native observations, and verify that actual action, intermediate stop, cleanup and control are unchanged. First check whether existing outcomes/attempt caches already share it. Cross-binding shape likeness alone never authorizes law reuse.

Materialize an actual small native candidate from at least two unequal bindings and show that numerical decisions can differ. A test that copies fields or prints a schema is insufficient.

## R2 — Pilot: continuation-sensitive progress frontiers

The leading pilot uses the current multi-slot exit vocabulary to avoid committing every repeat proposal to one named goal. For at most three same-side unresolved goal roles, preserve singleton proposals and initially consider pairs of target roles (at most three additional target sets per relevant native follow-up). Bind a permitted acquisition/protection/cleanup programme to that set and route complete native attained outcomes into their actual compatible tails.

This is a bounded proposal opportunity, not a new all-action quotient. It must not assume a single action targets each armour prefix independently. A native shared-tag action can acquire different roles; its full correlated law determines the result. A useful continuation can depend on which role and tier actually arrived.

Keep two distinct choices available where supported: continue the current acquisition/retry, or retain useful progress and attempt the next role. Complete a bounded complementary tail rather than demanding every isolated partial edit immediately lower the old root value. Initially at most two logical completion stages in this family; use existing graph composition, not an unauthorized longer fixed-option programme.

The source's singleton ProtectedRepeat loop is a starting hypothesis. R0 may identify a more direct native owner already performing the equivalent stopping operation; use it. If all relevant set-valued candidates already exist, switch only to the verified structural/binding gap identified in R0, not a second speculative family.

Every positive outcome must receive a legal complete continuation: clean goal, certified compatible old route, or a constructed paid recovery. Keep exact attained subsets plus context, not only attained count. Side loss, below-tier blocking, new junk, surviving setup, replacement and observation order remain native. Do not discard rejected outcomes or normalize a success-only law.

Use actual cost and continuation behavior to compare binding/order/acceptance choices. “Rare role first” and “accept any progress” can order bounded proposals but cannot certify superiority. Do not use an old root upper for an unknown tail. A missing tail stays incomplete and cannot become a published option.

Selected pilot limits must be explicit in the existing candidate owner. Preserve the first verified fallback. Propose no more than one additional family wave per relevant entry generation, with at most three selected entry/binding checks initially, serially and within the same total capacity. Materially distinct later evidence can justify one second wave only if measured, documented and still within the same global budget. Unrelated row growth must not trigger repeated retries.

The aim is useful coverage, not simply a wider queue. Ordinary full-scope action obligations remain open. No mode switch to execution-count, canonical price changes or cap increases are implied.

## R3 — Separate coverage gains from structural reuse

Use three notions of control, not necessarily three full solver campaigns:

- **Existing baseline:** current ordinary generator/search and caches.
- **Explicitly grounded family:** same new concrete candidate set, built separately per binding without the proposed structural reuse.
- **Role-shared family:** the identical concrete candidate set and ordering, built through shared structural logic and bound native specialization.

Small native entry tests compare the latter two before long runs: generated operation identities, complete entry/exit laws, choices, resources, primitive count and concrete decisions. Exact same-target duplicates may be suppressed by existing complete semantic equality; different parameter values cannot be deduplicated merely by shape.

If the role-shared version only adds a parameterized wrapper while enumerating all the same questions at the same cost, call that no measured structural gain. A better policy can still be a coverage result, but it must be credited correctly. If identical family coverage gains from sharing, report avoided structural work, all coefficient-generation/checking costs and peak aggregate ownership.

Do not optimize unrelated hot loops in this arm. Preserve native arithmetic order unless a separately checked algebraic change is selected. A structural optimization that adds expensive copied layouts or large symbolic expressions can lose overall; keep construction, memory and independent evaluation in the outcome.

## R4 — Full original-root qualification

[The validation plan](04_CASES_AND_VALIDATION.md) predeclares how the six case intents are used. A tiny partial-item success is not a root policy win. Root acquisition, restart/replacement, all failure branches and exact terminal cleanup must be charged and independently evaluated.

Primary material objective: at least 20% cheaper verified original-cost policy on one genuinely heterogeneous full-root case under the same product profile, with no loss of a cheaper retained result and a second structural application qualified. This threshold is a proposed goal, not evidence that such a policy exists.

Alternative measured-reuse objective: at least 25% less declared native structural/construction work to the same preselected verified result, with all-in time and peak ownership not worsened outside measured noise. Use a predeclared counter that actually describes the changed work, not a fabricated total of unrelated counters. A symmetric-only or code-size-only improvement does not satisfy the broad-goal programme.

A new finite feasible controller on a previously no-policy case is valuable but is reported separately from percentage reductions. Smaller genuine gains remain accurately reported, not inflated into the material target. Longer searches, wider memory or changed actions are separate profiles, not acceptance.

## R5 — Integrate and stop

Keep the original research once and integrate accepted reasoning with the [canonical documentation map](05_CANONICAL_DOC_MAINTENANCE.md). Preserve each rejected hypothesis and original memory-trial status. Record actual runtime activation and whether the ordinary product, a default-off native mode or an isolated fixture exercised the implementation. A flag existing in source is not product delivery.

Stop after two substantive failed implementation variants on the same premise without a new concrete native witness. Retain neither an unused descriptor layer nor a large symbolic evaluator just to show activity. A well-supported negative should state whether the failure is no missing family, no structural sharing, unsupported native binding, expensive grounding/checking, memory, or no economic gain. Do not automatically revive Ring memory-only changes, a response cache, a learned planner or a lower programme.

## Specific structural debt rules

No giant new all-purpose coordinator method; reuse the native task/compiler/evaluator and existing option vocabulary. No broad refactor first. A new local structure must own a real lifecycle and have a consumer; remove temporary diagnostic logic after preserving evidence. Cache keys must identify whether they describe structure, full native coefficients or evaluated policy economics. Share storage without silently sharing work obligations or undercounting simultaneous parent/child scratch.
