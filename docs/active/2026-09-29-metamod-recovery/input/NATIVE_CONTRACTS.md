# Native contracts and mathematical obligations

## 1. One-lock Scour: set union, not substitution

On the selected exactly-one-lock domain, an affix survives iff it is on the locked side **or** it is fractured. This follows the September 29 owner ruling recorded by Claude [C1]; it is not an externally inferred game rule.

For locked side P, retained count is:

```
count(P) + fractured_count(opposite(P))
```

not `count(P)` and not `count(P) + all_fractured_count`, which double-counts protected fractures. Both goal-family fractures and fractured junk count on their actual side; crafted/fractured overlap and literal member identity remain represented. Native action results, exact rows, abstract applicability and refinement affix flow must agree.

A fractured unwanted affix on the opposite side survives. Therefore a programme that previously appeared to clean the item may now be nonterminal. Do not restore the old result by erasing that affix from the goal check or assuming a cleanup tail. A surviving fractured lock is likewise a real exit condition, not permission to hide it in normalized success.

No-lock behavior remains the established contract. Double-lock Scour is explicitly outside new programme initiation and remains an owner question. A shared helper may be useful, but do not accidentally alter double-lock rarity or no-op rules while fixing the one-lock case.

## 2. Four independent candidate questions

1. Does the original request authorize this primitive/programme and price every resource?
2. Is the programme legal for the complete represented initiation domain?
3. Is its complete native outcome/choice/resource law available?
4. Are its nonterminal exits connected to proper compatible continuations?

A cheap answer to (1) is not (2); coarse `action_legal` is not all-member crafted/group legality. A complete local law is not a complete root controller. `setup_complete`, `cleanup_complete`, residual envelope coverage and actual terminal success are different facts.

When root state is concrete, a deterministic native setup/cleanup can often be checked without constructing a broad reforge. When a coarse state stands for different bench-conflict members, add the necessary observation/refinement or leave the candidate unresolved. Never use one convenient materialization to certify all members.

## 3. Complete programme values and paid recovery

For a fixed finite programme, let tau be its first legitimate exit, including any necessary internal controller memory. Let g(s) be its expected total original-price cost and H(s,x) its complete exit law. If it terminates almost surely with finite expected cost and each exit has compatible continuation value V(x), then

```
J(s) = g(s) + sum_x H(s,x) V(x).
```

Goal exits use zero continuation; unknown or illegal exits do not. Every positive outcome and observed-choice rule remains represented. Native primitive execution count is a separate reward, not one unit per macro.

For deterministic preparation to exact item/control entry s', a complete compatible tail satisfies `J(s)=c_prep(s)+J_pi(s')`. This justifies the audit's Bow composition as an offline witness when its exact entry and full goal checks agree. It does not tell ordinary search how to find the tail or authorize transplanting its scalar value into a different physical/control state.

If a lock of price L is consumed on each independent attempt, an attempt costs L+r, and return probability is 1-p to an equivalent entry, its renewal value is `(L+r)/p`, not `L+r/p`. Where return contexts differ or the lock survives, use the full state equations. A graph jump does not make physical recovery free.

This is the existing options/first-exit framework [S15,P1], not a new theorem or a reason to introduce another macro language.

## 4. Cheap partial admission is not partial probability publication

It is safe to expose completed candidate A while B remains uncomputed, provided the ledger still records B's pending obligation. It is unsafe to expose half of A's transition distribution as a normal row, renormalize its observed successes, or mark the whole automatic family exhausted because only cheap candidates were examined.

Root goal-ending candidates can supply independently checked root-only uppers before the ordinary graph closes. Nonroot rows need actual root reachability and all continuation support before they acquire root-policy authority. A useful complete action can remain an unresolved competitor for optimality.

The early opportunity must function with no prior incumbent. It cannot be provided only by the existing post-incumbent service. Preserve the last immutable graph/context/evaluation tuple across later caps and suspension; newer checked improvements supersede older candidates at adoption.

## 5. Macro scope and lower coverage

If an underlying problem already permits every primitive policy used inside a macro, adding that macro can be a redundant representation of an existing policy. In the product's dependency-only programme grammar, a newly generated sequence may instead enlarge the selectable policy class. Record which situation applies. An unchanged list of primitive names does not prove unchanged policy scope.

A useful sufficient condition for macro lower coverage is available on a common finite native domain: suppose v is bounded, v=0 at goal, and for **each** internal selected primitive/action at every reachable programme state,

```
v(s) <= c(s,a) + sum_x P(x|s,a) v(x).
```

For a proper macro with finite expected duration/cost, telescoping along its stopped execution gives

```
v(entry) <= g(entry) + sum_exit H(entry,exit) v(exit).
```

The stopping/limit step needs the stated boundedness/transience premises. A programme-level original-root upper or a proof only over old macro rows does NOT establish those internal inequalities. Native abstraction, scope, coefficient and numerical acceptance still need their actual bridge. Preserve unknown coverage where that bridge is absent. Never clamp a bad lower to the new policy cost or retain old exact status by default [P2].

The W4 evidence makes this obligation concrete: the recorded old lower (~84.16) exceeds the proposed cleanup upper (0.3741). Do not transfer that vector across the changed programme scope. Adding a new terminal route can lower predecessor values too; clamping only the root or destination cannot certify the rest of the vector.

Audit `solver_phase_lower.cpp`, residual action coverage/operator proofs, clean/carrier/retention producers and strict/refinement paths as affected. New programme kinds must fail closed in unsupported proof switches. Preserve ordinary clean proof for unaffected domains; do not demote every solve globally merely to avoid this mapping.

## 6. Coverage Multimod and crafted cleanup

Terminal truth comes from the resolved goal. Under strict clean semantics, an unrequested surviving Multimod prevents a deterministic finish. Under extras-allowed coverage, it may be harmless. Both use the same actual bench law, costs and capacities. Multimod is one of the crafted affixes, not three extra slots.

RemoveCraftedModifiers removes all nonfractured crafts. A cheap cleanup graph that also erases a requested crafted goal is not a terminal witness. A fractured unwanted craft remains. Cleanup that enables a later programme is a different complete composition from the initial terminal-only W4 family and is not silently assumed.

## 7. Finder occurrence and control identity

Only the trusted compiler may authorize dependency-only operations inside a permitted occurrence. The emitted operations, order, parameters, original prices, entry guards and exit ports must match that binding. Validate every positive-reach invocation; one admission example is not a universal initiation set.

For ProtectedSide, intended_side is the protected side. For EldritchSideIntent, intended_side is the affected side. Do not reuse an opposite-side formula blindly. Preserve all required held goal identities and tiers, not just their count.

A complete original-root generated controller must pay acquisition and its actual recurrence. Passing the local W1 authored oracle does not demonstrate Finder discovery. A controller that locks an unchanged side with unrequested junk cannot finish clean unless a real later operation removes that junk; guard or represent the route, never hide it.

## 8. Failure and cost interpretation

No candidate yet, computation capped, unsupported mechanics, improper policy, target mismatch and a corrupted/lost claimed artifact are distinct. A normal cap may return the last checked incumbent or named no-policy result. A true invariant break is not repaired by catching all exceptions.

Expected applications measure use under a policy, not probability of any use. Cumulative transient construction work is not resident graph size. Recipe setup, kernel, publication and outer elapsed clocks can overlap. A large admission counter or failed setup count motivates attribution; it does not quantify removable time.

Correctness repair changes the native process where the old law was wrong. Freeze that corrected process in both algorithm comparison arms. Do not count a newly preserved unwanted fracture as an algorithm regression, or a change in goal/data/grammar as an unqualified speedup.
