# MM0–MM7 implementation plan

## Programme question

Can the existing solver use complete, paid metamod/cleanup programmes at the valuable item states where they are useful, without first losing the opportunity to expensive unrelated construction? Separate missing grammar, incorrect native semantics, delayed service, incomplete continuation and genuine economic inferiority.

The principal acceptance witnesses are deliberately concrete: W1 already has the two requested natural prefixes but needs opposite-side cleanup; W4 needs one crafted-junk removal; the dirty Bow has valuable prefixes but still needs a requested suffix. Finder's separate obligation is a generated acquisition-and-cleanup controller, not a claim that its general search is now competitive.

## Dependency and advancement

```
MM0 → MM1 → MM2 → MM3 → MM4 → MM6 → MM7
                    └────────→ MM5 ────┘
```

This is a dependency diagram, not permission for parallel agents or timed runs. Work sequentially. The specific Bow follow-through in MM4 is conditional; the original three metamod-plan repairs and narrow Finder consumer are not optional just because Claude preferred a Current-only programme. No native correctness failure may be bypassed. Each causal premise gets at most two substantive repair variants; changing a threshold is not a new premise.

## MM1 — Correct old native semantics and advertised facts

### Single-lock Scour

Implement the recorded owner rule in `actions_basic.cpp::do_scour`: preserve the union of the locked side and all fractured affixes. Update Scour's `ActionRefinementContract` in `solver_registry.cpp`, abstract applicability in `solver_abstract.cpp`, and affected tests. Required state observations include the side of preserved fractures and surviving crafted/metamod identity. Do not double-count a fractured goal or junk affix already on the locked side.

The rarity/no-op rule must match actual native execution. Change only the exactly-one-lock case being corrected; double-lock remains excluded from this programme's new candidates. No-lock controls remain unchanged. Use the native modifier sides rather than hardcoded key spelling.

Audit every affected certificate/projection/cache consumer: exact rows, compiler observation requirements, strict refinement, phase/proof lower and carrier models, persisted graph/replay identities. An old clean-cover domain excluding lock/fracture is evidence for a narrower unaffected domain, not a blanket proof that all lowers survive. Recheck or invalidate changed-law artifacts under the existing compatibility mechanism. No archive/result overwrite.

### Metadata and scope honesty

`ActionTransitionFacts` currently describes renewals, and nonrenewal defaults are copied into solver preservation fields. Add explicit, source-backed solver metadata for audited existing adds/removals. Conditional behavior must not become an unconditional guarantee. Audit consumers of any changed field before changing it; do not automatically broaden the follow-up whitelist.

Correct misleading scope disclosure when goal-relevant/dependency-only grammar is active. Separate actual result status, permitted policy grammar and proof capability. An `exact` result over a restricted grammar is not global unrestricted crafting. Prefer the existing diagnostics/report fields and a tested minimal extension over a new cross-product schema.

Exit: reduced native tests reproduce the old single-lock failure and pass the correction; abstract/refinement/native outputs agree on the selected domain; metadata regressions pass; code/data/semantic baseline is frozen before performance comparison.

## MM2 — Close the three concrete generation gaps

### A. Cleanup-only protected Scour

Move Scour proposal generation out of the missing-opposite-goal iteration. Propose at most the applicable semantic side/programme combinations, deduplicated; do not weaken protected-repeat producibility checks. Use the existing `ProtectedSide` law with actual setup, preservation, losing effects, cleanup and costs. A residual fractured junk affix may make the state nonterminal after Scour; retain that fact.

At W1's original root, compare explicit complete native option with automatic admission. An equivalent already admitted option is counterevidence: do not add a duplicate; trace its service instead.

### B. One-step crafted cleanup

Expose an existing RemoveCraftedModifiers operation through a narrow state-local programme, initially selected by an exact terminal-success witness. It must remove all nonfractured crafts, not just the unwanted one. No blanket promotion of cleanup into all primitive candidate sets or forced exact group layouts is selected.

Use the existing programme machinery; if a new fixed/automatic kind is required, its name is a design choice to implement and cover in all relevant switches, compiler, scope/dependency, proof, resume and telemetry contracts. Do not pretend it is PermanentBench or an unrelated existing kind to bypass validation. W4 supplies the minimum positive; loss of a required craft and surviving fractured crafted junk are negative controls.

### C. Coverage-aware Multimod finish

Retain the clean-mode restriction when Multimod is not requested. In extras-allowed mode, permit the bounded existing Multimod + compatible goal crafts proposal when actual native initiation and the final resolved goal permit it. Reuse the final kernel goal test; enumeration is not terminal authority. One Multimod and up to two other crafts must respect all native capacities and groups.

Natural T1 targets cannot be satisfied by lower-tier bench substitutes. Do not remove Multimod while pretending other removable crafted goals remain. Fixed threshold/all-required variants need their own correct goal checks.

W4 is also the concrete proof regression: its reported old lower is about 84.16, above the 0.3741 cleanup oracle. Once the new programme is in scope, rederive/check every consumed affected lower and predecessor constraint. A root-only clamp is not a valid repair. Reuse an independently valid unaffected producer or zero only with an explicitly qualified scoped capability when a producer cannot be repaired; do not silently weaken all ordinary clean solves.

Exit: all three explicit/automatic differentials pass with mirrored and negative fixtures. Both sides are tested by native semantics, not base-specific dispatch. Scope/proof coverage for any added programme form is established or visibly remains open with a valid bounded result; unsupported coverage cannot earn exactness.

## MM3 — Service cheap complete work before the expensive batch

The existing `prepare_state_expansion` prioritizes permanent deterministic finishes before broad Chaos, but defers state-local compound admission. Extend the existing cheap-finish/early-assertion mechanism to consume the MM2 candidates without running every protected repeat first.

This is especially important before any incumbent exists. The default-off post-incumbent selective service is not a suitable sole entry point: W1's failure is having no checked policy at all.

Choose the smallest faithful integration: a bounded cheap-family admission stage, with complete per-programme publication and residual family obligations, or the existing direct root-assertion route coupled to the same native programme constructor. Do not build a second solver or expensive secondary search. Exact root preparation can use the real item; nonroot abstract sources require uniform semantics or native refinement, not an arbitrary representative.

For a completed root-terminal programme, compile/check and retain its actual graph early. For a nonterminal preparation such as the dirty Bow, append the complete row and preserve its exact successor/tail obligation; its local cost alone is not a root policy. Mark other automatic families pending until serviced or validly closed. Parent and child ownership, cancellation and cumulative charges must stay consistent. No partial law can enter a normal cache.

Test a forced cap immediately after cheap publication but before the expensive family. The last checked policy must remain usable; partial candidate ownership must be released. Existing first-policy/discovery service must continue after the checkpoint.

Exit: Current produces a checked W1/W4 policy without relying on completion of broad admission; unfinished expensive families remain correctly open; no spurious optimality flag.

## MM4 — Fix demonstrated stop failures and follow the Bow opportunity

First, reduce the reported strict-Finish and uncaught-work-cap exceptions using existing native harness hooks. Distinguish (a) never owned a verified policy, (b) a valid owned policy exists, and (c) the solver claimed one but lost or mismatched it. Cases (a) and real resource exhaustion need named outcomes; (c) remains an integrity failure and must not be hidden by a catch-all. Preserve existing failure/validity fields separately.

Then trace the dirty Bow root through: cheap preparation proposed → completed native row → compatible successor → finite complete continuation → candidate construction → independent check → retention. Its prefix lock/Scour is already a permitted acquisition-preparation form; MM2's missing-goal-loop fix alone does not explain or solve its service failure.

If a bounded existing-owner scheduling, exact-setup rejection or routing omission is the first demonstrated failure, implement one treatment with a reduced regression. Complete native lock setup can be prechecked cheaply when the represented source proves its applicability; coarse `action_legal` flags alone do not prove crafted-count/group uniformity. Preserve already valid retry/kernel sharing.

If the cheap prefix is serviced but no complete usable tail is constructed, record the exact missing tail. One complete existing-owner composition experiment may be used; it must obtain its tail through ordinary same-run/native construction or be explicitly offline diagnostic. A supplied saved tail is not evidence of automatic discovery. Do not build a generic local planner, arbitrary metamod Bellman expansion or response cache here.

Admission counters are cumulative transient work; do not equate them with retained bytes. The current parent reforge allowance excludes admission by explicit contract. Do not silently reinterpret that cap as a new combined ceiling. A separate admission-cap/profile redesign is deferred unless essential to safe implementation, in which case propose it explicitly rather than hiding it in timing comparisons.

Exit: the two observed error classes have precise dispositions; the Bow first failure is identified, and the selected small repair is qualified or a concrete larger dependency is documented. No repeat of the 13-run audit.

## MM5 — Complete the original narrow Finder consumer

Extend `compile_finder_control_json` and the reached-programme validator for **ProtectedSide with Scour only**. Preserve the existing Eldritch path. Do not accept all fixed options by removing an enum guard.

A protected-side binding's intended side is the held side, whereas EldritchSideIntent's is the acted-on side. Keep that distinction in binding validation. The actual occurrence must retain paid bench/Scour parameters and dependencies, observation timing and all exits. No decorative JSON permission grants; validate every positive reachable initiation item.

Generate from-root acquisition→guarded cleanup controllers for applicable single-side goals using actual native sides, held masks, craft capacity and persistent state. A clean target's untouched side cannot retain unmatched junk; a guard/fallback must handle that possibility. Re-entering the acquisition node does not reset the item. Do not skip paid setup on retries unless native state proves the effect already present and that programme is separately supported.

Use a private grammar/configuration through existing experiment controls. Preserve eight attempts and one checker; reserve at most one attempt for this family, with displaced candidates recorded. A generated original-root fixture must positively execute a crafted side lock. An authored advanced-root W1 graph, an Eldritch replacement or an unreachable branch does not pass.

Exit: actual consumer, complete original-root policy, reached-entry validation and legacy grammar controls. General protected-repeat, Annul, Harvest augment and composite Multimod/lock/NoRoll grammar remain deferred.
