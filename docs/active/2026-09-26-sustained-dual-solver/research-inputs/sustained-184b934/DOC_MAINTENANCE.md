# Canonical documentation and structural debt

## Principles

The programme must leave maintained source contracts, not only a ZIP in an archive. Keep one living record/HANDOFF and the canonical owners. Update them beside the corresponding implementation. Preserve old measurement hashes and negative results; do not rewrite a prior report to match new behavior.

The user values the mathematical work. Preserve the accepted conditional arguments once in the appropriate chapter with their actual native assumptions and implementation correspondence. A source inspection, a toy example, a focused fixture, a cold full-graph check, a benchmark and a universal theorem are different evidence levels.

## Required capability table

For each relevant combination, report implementation, native unit/fixture validation, real original-root measurement, release-WASM build, actual worker qualification, public exposure, default state, positive lower capability and exact-closure capability.

Rows include ordinary clean Current, neutral clean Current, neutral coverage Current, existing clean Finder, coverage Finder, selective-retention Finder, and Current shared-proposal service. A compiled feature is not necessarily exposed. Finder checking does not qualify Current proof. Shared native data/model changes may affect both; a new Finder generator is not automatically a Current improvement.

## Debt selection

Repair encountered duplication that prevents correct profile or shared-family ownership. Prefer a small native profile semantic owner, a single existing-control adapter and narrowly extracted checked-artifact handoff. Keep the core evaluator lifecycle and established oracle translation-unit conventions. Do not split files based only on an old line-count report, migrate every JSON string operation, or create a permanent graph response cache.

The candidate factory must have two real callers before a neutral naming/generalization is credited. Avoid dead interfaces built for hypothetical ML/GPU use. Retain old reference paths when they remain needed for independent law and work comparisons.

## Claim histories

No new broad claim ID just for renaming elementary zero-lower, first-exit or fixed-policy equations. Link existing claims when their assumptions apply, record new native premises precisely, and leave broad open correspondence claims open. Knowledge lint validates references and status discipline; it does not certify numerical/native correctness.

Final disposition must say separately what is implemented, what was measured, what was negative, what is blocked, and what has not been exposed publicly. No blanket "dirty states fixed" or "symmetry disproved" statements.
