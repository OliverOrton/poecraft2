# Long-running execution protocol

## Scope and agency

Execute this selected programme sequentially through its defined checkpoints. Follow current AGENTS and applicable local rules. No subagents, no pushes or public actions unless Oliver requests them. Preserve unrelated edits and root `0` without inspecting it. Commits remain local and use the required co-author trailer.

The user requested a substantial long-running plan. That authorizes sustained implementation and the predeclared conditional paths, not limitless benchmarking, unreviewed mechanics changes or permanent default promotion. Do not stop at the first routine failure or economic negative. Do stop a dependent branch when proceeding would require inventing native mechanics, suppressing a real counterexample or weakening a required invariant. Continue independently safe work where appropriate.

## Session start

1. Inspect the actual main/ref and working tree, excluding protected content. If HEAD differs from the reviewed ref, summarize the relevant delta and update source anchors.
2. Verify the packet manifest. Read CODEX_PROMPT, REVIEW and MASTER_PLAN plus the documents for the active checkpoint. Do not re-read all history as ritual.
3. Resolve the project interpreter/build and existing experiment owners. Inspect command help only for flags actually used.
4. Establish the current checkpoint state and outstanding changed files. A finished programme's old HANDOFF does not mean its uncommitted changes still exist.

## Development work versus experiments

Implement a vertical slice and focused native tests before an expensive comparison. Routine compile/test failures should be debugged within the active milestone. A new semantic failure gets a reduced native fixture and source cause. Never suppress an assertion, widen epsilon, raise a cap or silently remove a native action to obtain a pass.

Use one living programme record. Keep full raw evidence on disk. A compact source map, experiment table and measured failure witness are preferable to dozens of repeated status documents. Update canonical mathematics when its corresponding contract changes, not only at the end.

Do not launch a timed native run merely because a build completed. Its preflight must identify the question, variables held fixed, intended difference and decision informed by the result. Independent cases may be scheduled as a deterministic serial batch. Use existing blocking/event-driven supervision and longest supported waits; never build another polling daemon or LLM-driven watchdog loop. A returned session ID is not completion or permission to relaunch the same process.

## Checkpoint state

`IMPLEMENTATION_STATE.example.json` is a specification for a compact handoff, not a new workflow service. Store actual state in the living record or the existing metadata convention; no requirement to create a second source of truth. It should include:

- pinned source/data/config identity and last coherent commit;
- active milestone, completed tests and actual failures;
- existing active process/session handles and where their ledgers live;
- next two concrete actions and the condition for advancing;
- known unimplemented or unqualified lane/profile combinations;
- recorded spent real-run budget and graph/candidate identities;
- exact unresolved question if a user decision is genuinely required.

A code-context reset should not cause the next session to rerun prior expensive cases or forget a negative. It should resume from the next uncompleted checkpoint.

## Phase advancement rules

- **Safety/semantic failure:** block dependent integration until fixed or reduced to an explicit unsupported combination. Preserve last good artifacts. Never continue by weakening acceptance.
- **Known engineering coupling:** implement it. Listing the previously known U3 lower consumers is not a new gate that ends P1.
- **No economic improvement:** record it and continue the remaining predeclared family/consumer/qualification tasks. Do not run unlimited variants.
- **Cap or timeout:** classify as censored/resource-limited, not infinite cost or proof of impossibility. One justified resource-owner diagnosis may be performed within the existing allowance; no cap increase disguised as an optimization.
- **Current-specific difficulty:** does not cancel shared clean/Finder work. Finder grammar limitations do not cancel Current profile work.
- **Unavailable exact native mechanic or product decision:** ask a single specific question with the necessary evidence; do not guess. Independent tasks may continue first.
- **Economic promotion:** requires its own matched source/runtime/scope evidence. Engineering success alone stays experimental.

## Failure budget

At most two substantive follow-up variants for one causal premise. A new premise must name the new native observation and why it changes the treatment; changing a threshold or renaming the same rejected rule does not count. The 24 timed-native-run ceiling in EXPERIMENTS is global, including invalidated runs and repeats. Tiny tests are proportionate but do not become a giant artificial benchmark campaign.

The branch sequence for a selective candidate that fails is: inspect exact refusal/first uncovered context; repair legitimate initiation or missing native law if already supported; recheck; if still semantically unsupported, retain a scoped refusal and advance the other lane/qualification. A more expensive but valid controller is not fixed by altering the goal, prices or first-success definition.

## Checkpoint summaries

After each coherent milestone, record what changed, exact tests run, what remains unimplemented, and the next action. Do not terminate the entire assignment with a polished "scoped audit complete" message while mandatory engineering is simply not attempted. A necessary handoff is explicit about unfinished work and contains executable next steps.

Final response to Oliver should lead with actual capabilities and same-target economics, then numerical/proof/public status, original limitations, test and artifact paths. It must not say "both solvers improved" when only one consumed the feature, or "exact solver fixed" when only neutral bounded R was added.
