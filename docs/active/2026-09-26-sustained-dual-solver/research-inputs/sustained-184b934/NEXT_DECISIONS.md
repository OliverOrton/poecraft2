# Decision map after the selected programme

These are ranked next decisions, not automatic extra implementation beyond P0–P9.

## 1. If Current neutral R runs

Use its actual profile-controlled results to decide whether terminal semantics materially explain the observed search difficulty. A weak neutral L establishes how much the proof/guidance profile itself matters. Do not compare ordinary L with neutral R and attribute the entire difference to the goal.

Then choose whether to qualify one existing target-specific positive lower producer. Start with its current finite relation and native action coverage, not a new model simply to obtain a nonzero number. New target states and their predecessors must satisfy the proper inequalities. Full global closure also requires all-action/native correspondence and cannot be inferred from a lower component alone. Ordinary clean exact support remains valuable regardless of this outcome.

## 2. If selective completion improves Finder but not Current

First determine whether the difference is acquisition cost, live checking capacity, candidate service or an inferior continuation. The appropriate next move may be to place the shared continuation at a real Current decision rather than replace its superior acquisition prefix. That requires actual compiler provenance, compatible complete ports and root evaluation; it is not value transplantation.

If P6's predeclared local placement condition is met, that bounded experiment is already authorized in the selected programme. A broader local planner or arbitrary portfolio import remains a later decision.

## 3. If the new family is economically negative

Retain a sound used interface where justified; remove dead experimental branches. Choose the next family from the actual recurring cost/return structure or a missing admitted action, not a new raw occupancy threshold. A large count of repeated states is not evidence that a structural cache would save substantial work.

## 4. If shared target support is useful to users

Design an explicit versioned or backward-compatible opt-in goal interface with extras policy and real occupancy/open-slot constraints. Keep old v1 clean semantics and saved graph identity stable. A proposed default of extras-allowed is a separate product decision requiring user approval and actual solver capability labels. Do not expose neutral R as an exact-capable coverage solver.

## 5. Learning and parallelism

Only after the finder can generate meaningful native families and has trustworthy candidate records should a simple ranker be compared against handcrafted ordering. Keep exact source identity beside any lossy role features. Training loss is not the product metric. A model cannot select a strategy absent from the grammar.

One serial owner and checker remain the first design. Concurrent independent evaluations require aggregate admission and an audit of mutable/lazy native contexts; a GPU port or shared live solver threads are not implied. Use a relevant existing runtime only after its total feature/transfer/inference cost is measured.

## 6. Research posture

The possible contribution is a verified, budgeted connection among original-request target contracts, optional proof capabilities, native programme construction and two different search consumers in an implicit SSP. Zero potentials, options, policy iteration and programme sketches are established ideas. The new native method and measured evidence, not those names, would justify a novelty claim.
