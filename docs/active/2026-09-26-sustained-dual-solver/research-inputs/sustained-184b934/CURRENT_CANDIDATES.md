# Current consumer: root-only executable-upper proposals

## Purpose

Current must benefit from useful shared construction without being replaced by Finder or compromising proof. The first integration is a bounded, private service that asks the shared producer for complete original-root controllers and runs the existing request-bound checking/adoption path.

This is not a general public policy-import API or a concurrent hybrid. It is reuse of native construction code by two separate owners.

## Existing seams

Current already owns early candidate certification, retained graph/certificate lifetimes and root-only independently checked artifacts. `try_dirty_continuation_candidates` and return-bridge paths construct and check alternatives and retain them through `retain_certified_incumbent`. `compile_dirty_continuation_strategy_json` handles genuine local domains when those are needed. [S13, S14]

Do not instantiate the full old dirty execution-guided root programme to invoke the new family. Do not use serialized graph substrings as permission. Do not require a source-level private ID from another calculator. The new first family is a full-root controller, so the unavailable old donor's intervention provenance is not a prerequisite.

## Service contract

- Private/default-off activation, with immutable target/proof profile, family configuration and limits in treatment/resume identity.
- At most one wave per solve and initially at most two complete candidate checks.
- Begin at an existing cooperative safe boundary after an independently checked usable incumbent exists, before Finish and before resource exhaustion. Do not trigger from an unverified scalar or mutate a suspended selected-row graph.
- Existing checked policy keeps priority at Finish. Generation/checking uses only remaining cumulative reforge work and aggregate memory. A complete source recipe may be started early only if original first-policy qualification shows no starvation.
- Record queued, admitted, generation started/completed, checking started/completed, refused, censored, deduplicated and retained separately.
- A no-headroom admission is not evidence the candidate is expensive or absent. It is a capacity outcome.

The initial service does not change Current's ordinary ordering, action-envelope retirement or selected-value computation. It offers another whole controller. If its result improves the root U, the ordinary proof machinery may legitimately use that valid root incumbent where its existing scope allows; do not synthesize compatible statewise upper arrays elsewhere.

## Candidate and validation ownership

One owner holds the generation cursor and graph/control/occurrence bundle. A completed candidate is passed to the shared checking contract. Its original root, exact implicit flags, goal, scope and price identity must match Current's invocation. Reached programme-entry validation remains necessary; a matching graph success predicate does not prove internal programme authority.

Move complete checked artifacts into the existing portfolio. Do not copy only `J_pi` or assign `proper=true` because generation succeeded. Refused/capped checking retains no executable flags. Old best is not discarded until new evidence is accepted, and a newer incumbent installed while the check is suspended cannot be overwritten by a stale worse candidate.

If a tiny adapter is required to turn the shared checked bundle into Current's existing root-only artifact, extract the exact validated construction from its current owner. Do not duplicate a 2,000-line coroutine or fabricate source policy rows/solver convergence metadata.

## Fixed-policy information versus MDP proof

The result proves feasibility and cost for one controller, not the optimality of its sketch family or the whole MDP. The controller may use only a subset of admitted mechanics; that is normal for an upper. Omitted alternatives remain in Current's full proof obligation.

A root-only artifact cannot authorize arbitrary continuation values. A later local repair would require exact control/item entry domains and the appropriate continuation certificate. It is out of this first integration unless needed by an explicitly selected, reduced native fixture.

## Meaningful completion

A mocked callback receiving a graph is not enough. The actual Current work lifecycle must request a candidate from the same producer as Finder, check it, report its economic result, and retain/reject it correctly through an actual cap or Finish. A synthetic cheaper example establishes the acceptance path; a real A5 run establishes whether it can be serviced and whether it is useful there.

If Finder's best shared-family controller is still costlier than Current, Current may reject it. That is expected behavior, not an integration failure. The economic verdict determines promotion, while the structural result is recorded honestly and kept only if the maintained path is justified.

## P6B: predeclared local-placement branch

This limited branch is selected only when a complete shared-family root candidate is economically inferior to Current **and** a current-run checked donor supplies a genuine compiler-declared decision with the relevant held-side context. It is intended to preserve Current's superior acquisition prefix while testing the new completion, not to launch a general local planner.

Inspect at most three actual donor entries using the existing graph-local evaluator contract. A policy node name, coarse state number or representative item without the required provenance is not a safe intervention boundary. Select at most one complete local candidate for a second check within the original two-check wave. The first root candidate and this local candidate together do not obtain an extra budget.

Bind the shared completion's entry and all exits to actual physical/control identities in a fresh native context. Use the existing local-domain compiler/composition owner. The candidate either stays within its complete local domain, reaches the original goal, or returns to a specifically compatible old-controller continuation; unknown ports are not zero. Preserve mandatory programme execution and handle recurrence on reentry explicitly. The entire composed original-root controller is independently checked.

A complete donor can exist without an eligible nonterminal holding; report that and skip P6B. A supported holding without a cheap compatible tail can also cause a bounded refusal. Do not fabricate old provenance, construct a universal snapshot importer, broaden the target, or rerun the previous zero-entry family. Missing P6B evidence does not cancel the root/Finder/shared-profile results.

This conditional placement plus the complete-root caller exhausts P6. Wider entry sets, arbitrary imported policies, iterative local policy optimization and multiple waves require a subsequent explicit decision.
