# Optional multicurrency simulation contract — owner review only

Nothing in this proposal is activated. Oliver requested Lock support; the native
fixed-request slice has no multicurrency or solver claim.

A future model would retain one unchanged original item/session identity and a
map from complete normalized native currency requests to observed outcomes.
Repeated requests and synonymous serialized spellings that resolve to identical
native parameters must address the same observation. Changing essence, influence
or Eldritch tier changes request identity. Observation never pays the currency,
changes the item, samples again for the same request or refreshes the Lock. A
successful actual item action consumes foresight, including equal visible output;
refused actions and decline retain it. Any donor-dependent preview needs its own
complete donor identity and supported native law. Bench, Harvest, resonators,
Bestiary, recombination and unsupported item projections require separate scope
decisions; they cannot become previewable by UI naming.

The existing native marginals do not specify the joint distribution across
requests. Two possible explicitly labeled simulation assumptions for Oliver's
review are independent cached marginals per normalized request, or a specified
shared opaque random-source coupling across native primitives. Both can preserve
the individually unlocked laws yet disagree on conditional/adaptive decisions.
A shared seed alone is not an authoritative game correlation model. Request
aliases must never produce independent draws. No RNG seed/state may be exported;
checkpoints expose only observations already obtained. Neither option is
recommended as an exact game law without authoritative evidence.

Oliver could approve one versioned simulation assumption, keep multicurrency
unavailable, or supply a supported joint law. Acceptance of an approximation
would not authorize ordinary Calculator/Current/Finder action admission. Exact
adaptive value requires a full information-state transition law, complete
request/resource scope, observation/payment/consumption events, root goal
identity and an executable checked upper policy. None currently exists. The
future archive's free-decline expression does not establish these obligations.
