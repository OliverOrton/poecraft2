# Native design: diagnose dirty progress without changing the problem

## 1. Separate four data products

**Problem identity:** original exact physical root, session/data, goal slots and threshold, terminal schema, admitted actions/programs and prices. This is unchanged in every economic comparison.

**Search observation:** a source carrier/row in a particular solver namespace, generation, scheduler epoch and lifecycle stage. “Discovered”, “selected”, “started”, “complete”, “checked” and “published” are separate events.

**Policy economic observation:** an entry or first-hit event in one complete proper controller under its actual item/control chain. This is not the same population as all search carriers.

**Proposal description:** a possible continuation or ordering feature. A descriptor may be useful before a kernel exists, but it is not a proven cleanup law or a bound.

Do not fuse these into one scalar `junk_score` or one graph-independent cache.

## 2. Proposed bounded observation record (not an existing API)

Use the existing native attribution owner, not full per-step JSON. Field names below are proposed and must be adapted to actual types. Initial sample ceilings are 128 unique selected carriers and 32 seed-choice records, with deterministic stratification and omission counters. Bounded aggregate histograms may cover more events cheaply.

```
problem/run/build identity
source semantic key + namespace + graph generation
satisfied requested mask, required threshold, requested rarity match
prefix/suffix occupied counts and native actual capacities
missing requested prefix/suffix masks (mixed-side slots remain explicit)
non-satisfying/below-tier/temporary-crafted counts, by side where native-known
blocked missing goals, with provenance; no inferred exact blocker from a MAY effect
held fractured/crafted goals, lock/eldritch/influence/control context
strict_terminal, diagnostic_requested_coverage
first_policy_gate, output_candidate_present, independently_verified_present
actual scheduler owner/mode/epoch, full original key
first discovery / queue / selected / started / completed work positions
observer time separate from native source time
counterfactual key and position on the SAME frozen eligible set
selected operator, complete rows, missing continuation/choice-route count
cleanup evidence grade and identity (unknown/descriptor/complete law/complete tail)
```

Record first **service** separately from successful completion; cap/scope refusal is not late completion. Missing samples and unserved-at-Finish are censored. Do not compare all state IDs across independent divergent runs. Compare compatible semantic contexts, and use a frozen-list unit test for the controlled key change.

Group summaries must control for goal mask, source rarity/persistent context, prior protection, branch weight where known, and available complete support. A low-visitation state with a costly repair can rationally receive late service. Marginal correlation between junk count and delay is not a causal witness.

## 3. Native obstruction/cleanup interpretation

A raw occupancy difference is not a cost. Distinguish:

- **Immediate capacity/group conflict:** prevents a named next operation or missing-role acquisition in this actual state.
- **Possible obstruction:** a coarse descriptor says the relation may matter; exact applicability/support is not yet built.
- **Complete preserving law:** every required native branch and reward of a specific program is known, including goal loss and setup costs.
- **Complete executable continuation:** that law's exits are all resolved with correct control and proper original-goal behavior.

Junk can be harmless relative to one operation and obstruct another. A protection craft may occupy a needed slot itself; below-tier requested members can block their satisfying replacements. Opposite-side junk is not automatically removable or cheap. A fractured non-goal mod or persistent context can make the usual cleanup inapplicable.

Use the existing native action/refinement/program contracts. Do not use the MAY-survive mask as a proof that a held mod always survives. Do not assign zero future cleanup cost unless an actual compatible no-cost law establishes it. No per-base tests such as “armour => cheap Eldritch cleanup”.

## 4. Cheapest useful first-acquisition diagnostic

### Preferred route: stop an unchanged prefix, rather than export the entire Markov chain

Existing compiler/evaluator infrastructure already admits private STOP-boundary diagnostics [R13]. It does not already implement the following general acquisition probe; this is a narrow new diagnostic using those owners.

Take one complete checked donor and the separately resolved original request. Compile an **observation-only coverage condition**: original requested rarity plus the original goal-slot threshold, without the unrelated-explicit-affix equality. Its name and type must distinguish it from the final success predicate. Do not infer the request from every target slot in an evaluator layout: that layout can also contain slots required by intermediate conditions.

Create a diagnostic copy that is identical to the donor until the first declared eligible complete-decision boundary whose physical item satisfies that condition. There, take a diagnostic STOP. Keep separate labels for dirty coverage and already-clean coverage when cheaply supported. Preserve all operations, ordinary routing priorities, resources, root context and hidden control before that point. No new success terminal is introduced for dirty states.

Evaluate the stopped copy with the ordinary **generic diagnostic** evaluator, not finder acceptance. Require complete absorption/cost and no unexplained mass, unpaid action or illegal/no-edge behavior under that diagnostic's explicit terminal meaning. Its STOP probability is expected and is not a valid finder policy. It must never be inserted into a portfolio, saved as an improved crafting result, or given proof authority.

Then compare original root cost `J` with stopped prefix cost `J_prefix`:

`J_post = J - J_prefix`.

Under the coupled-prefix contract in MATHEMATICS.md this is the expected original-policy bill after first coverage, including later loss and reacquisition. It avoids exporting a huge matrix merely to compute one scalar. Use the original full-controller check receipt and native numerical tolerances. The arithmetic identity `J - prefix - (J-prefix) = 0` does not verify the transformation. Test a never-cut control (same cost and behavior), an immediate-root cut (zero prefix), and independent first-hit equations on a small recurrent native fixture. Preserve every old prefix edge and action under the no-cut guard. A small negative from inconsistent evaluations is not clamped silently; reconcile it or report an interval/unknown.

### Observation boundary is part of the result

Initial implementation observes only **compiler-declared decision boundaries after mandatory programs**, with safe physical/control identity. It measures `first_decision_boundary_coverage`, not the first fleeting appearance inside every primitive microstep. Include the original root if it is an admitted boundary and include eventual native success in the stopping set.

If the donor lacks sufficient provenance, derive a faithful complete primitive-level diagnostic with the existing engine only when legal/affordable and label it separately, or report unavailable. Never infer a safe intervention point from a node name. A diagnostic cut inside a mandatory program, even when semantically measurable, does not authorise replacing that interior. Costs/primitive counts crossing a macro must be split using actual native rewards; assigning the macro's whole bill to both sides is wrong.

Some stop nodes can be contracted by the evaluator. Make sure the requested first-hit classification survives the existing observer contract; if not, use the existing exact query/entry owner or retain only the reconciled scalar. Do not add a new full-chain export framework for the distribution.

### Equivalent route when the complete chain is already owned

On a retained exact item/control chain, solve the substochastic outside-coverage system and accumulate first-hit mass. It may be cheaper than graph-copy checking if those arrays and exact observation requirements are already available at an existing seam. Do not reconstruct it from truncated node-visits JSON or copy a source-state vector into evaluator state IDs. Both routes must agree on the same small fixture.

### Limits and interpretation

At most two diagnostic donor checks initially. Diagnostic memory belongs to its declared profile; a separate offline check is not evidence it fits concurrently with a live solver. If the required exact check is capped, return an explicit unknown. A sampled trajectory's truncated completion cost is not a substitute.

Report first-hit mass, clean/dirty split when available, prefix cost, post-hit cost, original cost and residual, native primitive-count split, observation boundary, no-hit/omission status and actual runtime. Do not convert post-hit cost into guaranteed savings or a lower bound on cleanup.

## 5. Exact ordering experiments

**O** reuses the original comparator except one term: for active IncrementalLegacy, after all original earlier keys, omit `unrelated_occupancy` and use the original final stable state tie. No modified mask order or new global priority. Test frozen candidate multiset equality, stable ordering, quota/interleave retention and no row/value changes caused by merely reading scores.

**S** modifies only the gated `advances` heuristic: old debt decrease OR increased native satisfied count. Preserve actual goal tests and every chance branch; the heuristic's count of an offer event follows the current code, while the executed choice remains independently checked. A generic least-debt or acquisition potential must not be installed in `result.values`, `global_lower` or certificate storage.

Both can change which future rows get built; identical final state counts are not required. The immutable problem and probability law of any corresponding action remain identical. Genuine new computations still consume logical work and memory. No rearming the same optional work solely because time or an unrelated generation changes.

## 6. Candidate-coverage branch G

The current finite control is sufficient to route test/run/terminal structures, but its native programme vocabulary is not yet the desired retention policy. Add only a real family selected by the evidence. A coverage test should branch toward acquisition versus completion, not success. A native obstruction test should be parameterised by the bound missing role/side and actual capacity, not the fixed count 4.

Use occurrence-scoped programme provenance for any dependency-only primitive: its selected program identity, exact internal sequence/control and allowed entry/exit must be checked. The public primitive action set is unchanged. If all needed steps are already standalone admitted, do not build a dependency framework just for appearance.

Generate from the original root. Hold a checked incumbent during suspended candidate work. All exits must lead to strict goal, a proper compatible base continuation, or another fully defined stage; a partial coverage state is never an executable terminal. Frozen old-policy tails need precise item/control identity. Repeated patches must be evaluated as repeated, not priced by a one-use formula.

All parent/private/program/evaluator/graph storage is admitted simultaneously to the existing aggregate cap. A moved graph remains charged to its new owner. Finish/cancel use existing sealing and release, and a stale candidate must not overwrite a newer cheaper winner.
