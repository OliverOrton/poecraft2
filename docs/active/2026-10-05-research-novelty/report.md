# Cold-derived compositional continuations for poecraft2

Research lane: novelty · 2026-10-05 · documentation-only investigation

## 1. Decisions first

The most defensible small direction is a **bounded frontier of complete, native-entry-bound continuation responses**, generated cold from the current request. Its first screen should be deliberately narrow: compare complete paid first-exit laws at identical observable boundaries, and discard a generated alternative only when another alternative provably dominates its cost and non-goal return probabilities. This screen can work without a statewise continuation table. Retain incomparable alternatives for the existing complete-controller checker, or for a later boundary solve with independently established port values.

This is a potentially useful implementation direction for this particular SSP, not a claim of a new general algorithm. Options, local-policy decomposition, exact compositional expected-reward checking and Pareto caching are established prior art. The repository already derives first-exit response equations, boundary elimination, graph-local interventions and complementary decisions. The new question is whether **complete response vectors rather than one local scalar or role signature** can cheaply preserve the useful alternatives at the current producer/checker boundary. No reviewed evidence establishes that this implementation would beat the existing path. [M1–M4, L1–L5]

Three decisions follow.

1. Let the separately owned checked-graph eligibility extension finish its own qualification. A new response mechanism must consume its actual compatible checked artifact; it must not duplicate or modify that owner's scheduling, sticky statewise rejection, fallback or test work.
2. Prefer a cache-free, same-request prototype. Derive a few native alternatives, retain their complete interfaces only for that proposal batch, and flatten/check the selected controller through the existing authority. A persistent exact cache is an optional second milestone after measured repetition and all-in savings.
3. Do not select a new Conquest root run from this report. The first useful future experiment is a small semantic and cost-attribution comparison against complete graph grafting. Missing ports, unexpressible native predicates, numerical uncertainty or unattributed matching costs are stop conditions, not invitations to raise memory or weaken admission.

The strongest newly derived sufficient condition is useful but restrictive: for a common finite boundary graph, replacing a proper incumbent's macro rows by complete transient fragments with componentwise no greater non-goal boundary probabilities and no greater expected paid costs preserves properness and cannot increase cost. It gives a graph-bound screening route without arbitrary statewise values. Most growth-versus-reroll tradeoffs will be incomparable, so this condition must not be sold as a general solution to continuation discovery. Section 6 proves it and identifies exactly what native evidence is still missing.

No engine/product edits, builds, tests, solver/Simulator runs, dependency installs, data/price refreshes, deployment or main writes occurred in this task. All mathematical examples below are hand-derived illustrations, not native receipts.

## 4. Prior art and honest novelty boundaries

**Options.** Sutton, Precup and Singh define temporally extended closed-loop actions with initiation, internal policy and termination, and consequence models containing accumulated reward and termination-state predictions. This is prior art for a crafting word's cost/exit interface. Their discounted planning theory is not a substitute for poecraft2's undiscounted proper SSP, native support or paid setup/cleanup. The option concept does not prescribe a curated recipe bank. [L1, §§2–3]

**Local-policy decomposition.** Dean and Lin parameterize interactions between regions and combine local policies through abstract planning or iterative parameter refinement. Their paper already makes downstream interaction values central to selecting a local policy. Region-based composition and tail-sensitive local competition therefore cannot be called new. Choosing a useful native region and preserving actual controller memory remain additional obligations here. [L2, §§1.3, 3–5]

**MAXQ.** Dietterich's value decomposition works within a supplied task hierarchy and gives conditions for safe abstraction; recursive optimality is a hierarchy-relative notion. It is useful as a warning against assigning one universal value to a role-level subtask. A fixed hand-designed hierarchy is a poorer fit to Oliver's cold-start preference, and no hierarchy-relative optimum closes this solver's full permitted programme scope. [L3]

**Exact compositional expected rewards.** Watanabe, Eberhart, Asada and Hasuo explicitly develop expected-reward decomposition for open MDPs, carrying exit reachability along with rewards. Their Remark 2.1 assumes almost-sure termination under every scheduler for their framework; poecraft2 permits improper candidate controllers and must check the selected composition instead. This paper decisively rules out a broad novelty claim for exact expected-reward composition. [L4, §§2.2–3]

**Pareto caching.** Watanabe, van der Vegt, Junges and Hasuo reuse component verification across weighted exit queries. Their CAV 2024 algorithm is approximate weighted-reachability verification with sound error bounds, not an exact paid-SSP endpoint or native crafting implementation. The relationship to a response frontier is close enough that claiming discovery of Pareto reuse would be wrong. The exact bounded list proposed here adopts only the interface/competition idea; it does not import approximate answers as exact values. [L5, §§2.3, 3, 5–6]

The claim this report leaves open is narrower: **a cold-derived, graph-bound response frontier, with a strict support-monotone screen that can operate when only a checked root graph exists, may preserve or cheaply compare useful compositions in this exact native SSP.** The cited literature does not establish performance or novelty of that integration. The literature scan is targeted, not an exhaustive novelty search or a patentability assessment. No absence-of-literature claim is made.

The closest in-repository prior art is already `policies.md#boundary-response`, `#graph-local-boundaries`, `#bound-role-ports`, the private leaf verifier, and the complete-graph grafting experiment. The proposed delta is **a bounded consumer and semantic screening contract**, not a new derivation, quotient, lower theorem, general compositional solver or cache framework. [M1, S4–S6, N6]

## 5. The proposed object and its native obligations

Call the object a continuation response. It contains a fixed finite internal controller, an exact admitted entry domain, explicit observable exit ports, complete positive native rows, expected resource rewards and its semantic identity. It remains a candidate computation until the existing original-root publication/checking chain accepts the flattened graph.

The state is `(native item, operation/controller phase, persistent execution context)`. An exit port is not just a goal mask or a compiled node number. It identifies the native item/control entry and the compatible continuation it invokes. A native routing condition must express that distinction. A physical diagnostic entry cannot stand for all members of an abstract class without a whole-member relation. [M2, M3, S4]

Cold discovery should enumerate a small number of already permitted native action/programme descriptors at an actual reached decision boundary. It may stop at native goal, exact compatible incumbent reentry or a complete paid recovery endpoint. It must not stop inside a mandatory word merely because the intermediate item looks good, or invent a descriptor keyed to Conquest, a historical state ID, fixture hash or saved strategy.

The following obligations are inseparable from the object:

1. Original root, exact goal, cleanliness/extras semantics, thresholds and tier/member requirements agree with the caller.
2. Native mechanics artifact, complete modifier universe, exact item identity and persistent flags are bound; same projected occupancy is insufficient.
3. Every primitive and programme dependency is admitted under the actual caller scope. An action-owned paid replacement is different from discretionary economic Restart.
4. Actual observation and choice timing is preserved, including Unveil offers, saved checkpoints and phase memory. A before-observation rule cannot use a later offer.
5. Every strictly positive native outcome remains in support, however small; unresolved probability is not dropped or renormalized.
6. Setup, Multimod/blockers, influence/tier preparation, cleanup, removal, recovery and reacquisition are represented where actually paid. Repeated setup is charged repeatedly when execution repeats it.
7. All missing prices, unsupported actions and unexpressible predicates refuse the relevant candidate; a default route cannot fabricate success.
8. A proper local exit law and finite internal reward are established for every admitted entry. A numerical equation solution alone is insufficient.
9. Each non-goal positive exit has a real compatible continuation or stays unknown. Root cost is usable only at the identical root and controller phase under a proved return contract.
10. Whole composition has almost-sure native goal completion and finite cost; local properness does not supply this.
11. The flattened complete controller passes the existing independent evaluator and all demanded positive programme-entry admission checks. Existing numerical acceptance and reconciliation remain unchanged.
12. Resource consumption, primitive executions and price-weighted cost reconcile separately. A price key quantity is not a count of primitive operations.
13. Shared payload, borrowed census, child cursors, scratch, copies and retained certificates have valid lifetimes and are charged to the parent aggregate. Cache hits still verify their semantic admission.
14. Candidate/refusal/cap results are typed separately. A capacity refusal is not a semantic impossibility and cannot become a permanent negative cache entry.

A screened or ranked response supplies no Current lower, optimality closure, hybrid handoff, authored-runtime activation or WASM qualification. These obligations are the existing SSP contract applied to the proposed interface, not a relaxed new policy language. [M0–M4, S1–S6]

## 6. Mathematics: exact interfaces, a narrow screen and its limits

All propositions in this section concern complete finite mathematical models. Numeric implementation must separately satisfy section 8's coefficient and acceptance contract.

### 6.1 A fixed local controller has an affine tail response

Fix internal states I and external non-goal ports Z; a goal port has continuation zero. Let Q be the nonnegative internal substochastic matrix, H the complete probability matrix to Z, and G the goal probabilities. Assume `Q*1 + H*1 + G*1 = 1`, Q is transient, immediate cost c is finite/nonnegative, and decisions are fixed at their legitimate observation points. Then

\[
v(u)=(I-Q)^{-1}(c+Hu)=g+Tu,
\quad g=(I-Q)^{-1}c,
\quad T=(I-Q)^{-1}H.
\]

Proof: expand the nonnegative convergent Neumann series. The nth term is work or exit mass after n internal steps. Summing over all n gives accumulated cost and first-exit probabilities. Equivalently solve the fixed-policy equations. This is the existing stopped-response argument, not a new theorem. [M1]

For resource k with immediate expected quantity vector `r_k`, use `g_k=(I-Q)^-1 r_k`, not a prepriced aggregate if later price-only reuse is contemplated. Expected primitive executions require their own reward. For branch/resource evidence, retain

\[
W_{i,z,k}=\mathbb E_i\left[\sum_{n<\tau}R_{n,k}\;1_{S_\tau=z}\right].
\]

Its sum over exits equals `g_k(i)`. It is an unconditional joint resource mass, not conditional cost at an exit. The native leaf verifier already represents these quantities. Constant-price expected cost needs the total resource expectation; exit-conditioned reporting or further joint composition must not substitute an unconditional average for W. [S4]

No equation here grants a value to an unknown port. Nor does it make two entries equal. Each entry retains a separate response row unless complete native equality has been proved.

### 6.2 A strict dominance screen that does not need tail values

Compare two complete local alternatives a and b at the same exact entry and exactly aligned ports, both transient internally. If

\[
g_a\le g_b,\qquad T_a(z)\le T_b(z)\quad\text{for every non-goal port }z,
\]

then `g_a + T_a u <= g_b + T_b u` for every finite nonnegative tail vector u. This is simple monotonicity. It does not estimate u and is valid when no statewise table is available.

For repeated composition, stronger global premises are needed. Contract a complete proper incumbent onto a finite common boundary set B, retaining goal absorption, with expected per-macro cost vector d and substochastic boundary matrix K. Replace only some macro rows with locally complete transient alternatives, retaining unchanged outside routing. Require for every replaced row `d'<=d` and `K'<=K` componentwise; unchanged rows are equal. Then the new contracted controller is proper and no more expensive.

Proof: `0<=K'<=K` implies `(K')^n<=K^n` by induction. Properness of the old finite boundary chain gives `K^n->0`, hence `(K')^n->0`. With finite nonnegative costs, termwise comparison gives

\[
V'=\sum_{n\ge0}(K')^n d'\le\sum_{n\ge0}K^n d=V.
\]

Transient fragment interiors and finite internal costs lift boundary properness to the finite flattened controller. Strict root improvement additionally needs a strict negative advantage at a boundary reached with positive expected visits under the new controller; mere strictness at an unreachable boundary changes no root cost. The published graph still goes through independent native evaluation.

This route requires no scalar continuation transfer, but it requires **complete aligned native boundary laws** and a proper incumbent composition. A checked root artifact alone does not supply those laws automatically. It can be the executable object from which the old response is constructed. If a new alternative reaches an off-incumbent port with positive mass, `K'<=K` fails at that port; no old scalar fills the gap.

The condition is intentionally conservative. If neither controller has direct goal exits and both first-exit distributions sum to one, componentwise dominance forces equality of their entire exit distributions. Meaningful domination then comes from lower paid cost under equal exits, or from shifting some non-goal mass to verified goal absorption. A growth option that exchanges one dirty exit for another will usually be incomparable. Removing a redundant paid Annul before an erasing reroll could be eligible only after native whole-kernel/routing equality; that concrete question is already in P4, not newly discovered here.

### 6.3 A frontier retains tail-sensitive alternatives

For a finite generated set O of complete local controllers, at a fixed known compatible tail vector u the best entry response is

\[
\phi_i(u)=\min_{o\in O}\{g_{o,i}+T_{o,i}u\}.
\]

This is the lower envelope of finitely many affine **policy costs**, relative to O. It is not a lower bound on the unrestricted crafting optimum, and not an exact closure claim. Choosing one controller at a genuinely observable entry is executable; independently taking minima at hidden internal states is a different controller and needs fresh rows and checking.

Illustration: two alternatives exit to a non-goal tail costing u. A costs 1 and exits there with probability 0.9; B costs 4 and exits there with probability 0.2; the other mass is verified goal. Their one-shot responses cross at `u=30/7`. At u=2, A costs 2.8 and B 4.4; at u=20, A costs 19 and B 8. No common role signature or cheapest-internal-cost rule chooses correctly across these contexts. This is a hand-derived finite example, not a PoE law.

If every port value has a legitimate finite interval `L_z<=u_z<=U_z`, a box suffices to prove a limited dominance statement. With `delta=g_a-g_b` and `w=T_a-T_b`,

\[
\max_{u\in[L,U]}(\delta+wu)
=\delta+\sum_{w_z\ge0}w_zU_z+\sum_{w_z<0}w_zL_z.
\]

A nonpositive result establishes dominance on that box only. If an upper is unknown/infinite and the corresponding w is positive, the screen cannot pass. TargetNeutralZero supplies the allowed global lower zero under its nonnegative-cost premises; it does not supply finite upper values at arbitrary ports. An approximate copied table with sticky rejection cannot define this box. Properness of the selected recurring composition remains separate unless the strict matrix-dominance argument applies.

### 6.4 Feedback must be solved, not priced as fixed old tails

If a fragment returns to its own entry with probability q and costs g per complete excursion, its repeated controller costs `g/(1-q)` for q<1, including every paid recovery in g. At q=1 it does not reach goal; a zero-cost loop may satisfy a Bellman equation yet is improper.

For several recurrent ports, assemble the actual selected boundary matrix K and reward d, then solve `V_B=d+K V_B` only after proving K transient. Eliminating transient interior states is a Schur complement; the repository already gives its exact form. Local exit with probability one does not prevent two components from alternating forever. [M1]

One-shot scores against the old root value do not rank repeated policies. With old cost 10, a complete excursion having goal probability 0.9 and repeated cost 8 has one-shot response 8.2; an excursion having goal probability 0.01 and repeated cost 1 has one-shot response 9.91. The first scores better once, but the second is cheaper when repeated. Those figures follow from `(g,q)=(7.2,0.1)` and `(0.01,0.99)`. This known counterexample is already recorded in policy mathematics.

The deterministic bridge/tail example is equally relevant: incumbent `r->goal` costs 10, `t->goal` costs 100; alternatives `r->t` cost 1 and `t->goal` cost 1. Bridge alone costs 101, tail alone leaves root cost 10, joint changes cost 2. A frontier may retain ingredients for a joint controller, but it must carry the real t continuation and check the assembled graph. Existing full-domain policy iteration need not have this bounded-proposal failure. [M1, P1, P2]

### 6.5 Counterexamples that delimit the proposal

| Invalid shortcut | Counterexample or failing premise |
|---|---|
| Equal goal masks imply equal ports | Two same-mask items differ in below-tier member, secondary group exclusion, crafted blocker or persistent tier; next action legality/law changes. |
| An exact leaf proves an exact class | One leaf is valid, another member has no legal cleanup. The first leaf covers neither the second member nor an executable common selector. |
| Proper fragments imply proper composition | One exits from x to y, another from y to x; no goal ever reached. |
| Drop a tiny-positive recovery/trap exit | A positive trap, however small, destroys almost-sure goal completion; renormalizing success changes the problem. |
| Borrow the root cost at a dirty port | Same visible goals but different item/controller phase has a different continuation; the root-entry certificate does not apply. |
| Dominance at the sampled representative | A second member's exit probability reverses the inequality; universal domain comparison was absent. |
| Cache a best decision after price change | The fixed response may remain valid, but the selected minimum and old paid cost change. |
| Small residual certifies dominance | Near q=1, value error is residual divided by `1-q`; an uncertain comparison can reverse. |
| Matching descriptor digest is equality | A digest locates candidates; canonical fields and native equality still establish the relation. |
| Retry after free repair | A reset returns a similar root while retaining different persistent context, or omits paid acquisition; the renewal equation is for another controller. |

### Cache-free first

The initial batch owns its few complete responses, exact port maps and fixed controllers until selection/checking or refusal, then releases them in dependency order. There is no cross-request solved policy bank. This gives a cold-start comparison and limits invalidation to ordinary request-local compatibility checks. Same-batch deduplication by exact complete law remains allowed, but it must be compared against deduplication the current native owner already performs.

A cached second version uses an **exact semantic dependency key**, not a role-name signature. It can reuse a fixed controller's immutable transition/resource response only when its entry member domain, mechanics, programme scope, goal/terminal, control observations, action vocabulary, row/port map and numerical semantics agree. It keeps fixed response validity separate from price-dependent rankings, tail-dependent choices and publication evidence. A cache hit never asserts that the fixed controller is optimal.

| Change | May retain | Must invalidate/recompute |
|---|---|---|
| Price vector only, fixed controller and complete resource response unchanged | Transition and resource response under a proved price-independent contract | Paid scalar cost, all price-based ranking/dominance, best-controller selection and final reconciliation. |
| Tail cost changes, exact port continuations unchanged | Local fixed response | Tail-specific ranking/envelope query and any joint feedback solution. |
| Continuation graph, routing or phase changes | At most independently valid local primitive rows whose dependencies are unchanged | Port bindings, composition certificate, entry census/properness and global result. |
| Goal/threshold/tier or clean/extras semantics changes | At most goal-independent primitive law with its own contract | Goal exits, stopping rule, member domain, response identity, policy validity/ranking. |
| Runtime data/mechanics/count law changes | Nothing dependent without native equality/version proof | Kernel support/coefficient/reward evidence and all downstream certificates. |
| Allowed programme/action scope changes | A feasible fixed policy only if every dependency remains admitted | Admission, scope-bound identity and any scope-completeness/optimality assertion. |
| New member or observation distinction | Previously valid individual entry objects | Universal class equality, shared selector/port map and domain-wide certificates. |
| Append-only unrelated graph growth | Complete frozen rows under existing compatible prefix identity | Any mutable locator/reference not covered by that identity contract. |
| Capacity/deadline refusal or eviction | Immutable successfully completed artifacts if independently still owned | Incomplete cursor state; refusal is retriable resource status, not semantic absence. |

### Complexity and the actual bottleneck hypothesis

Let n be internal product states, e positive transitions, z exits, k resource channels and f retained local alternatives. Complete native expansion costs at least the existing kernel/materialization work plus O(n+e) traversal/SCC work. A dense fixed-policy factorization is O(n^3) time/O(n^2) memory, then approximately O(n^2(z+k)) for multiple right-hand sides. Sparse cost depends on fill and conditioning and can approach dense cost; it must be measured, not described as automatically linear. Retaining joint exit-resource responses can add O(nzk) work/storage unless a justified structure reduces it.

At one exact entry, pairwise strict dominance on already materialized response rows costs O(f^2 z), plus resource pricing. Multi-entry coverage costs multiply by the actual admitted entry domain. Computing an exact complete frontier over all local policies can require exponentially many alternatives; this proposal uses a bounded generated set and claims only its best checked feasible output. It never enumerates a full Pareto set in production by default.

The flattened checker has its own operation/item product, global observation union, entry census and programme admission work. A smaller response summary does not automatically reduce that checker carrier or peak. Similarly, a saved frontier can add memory overlap while the old fallback, generation context and checker are simultaneously alive. The existing aggregate 1 GiB limit is retained; no new separate response budget multiplies parent headroom.

Thus the most plausible benefit is **fewer full candidate checks or fewer repeated tail-sensitive selections after a complete response is already available**. The least supported benefit is acceleration of primitive native kernel construction or universal state compression. This distinction is the new materiality premise and must be measured before implementation broadens.
