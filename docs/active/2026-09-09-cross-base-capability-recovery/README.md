1. **CB06/08 first-policy frontier delivery.** Both stop after 32 expansions,
   no incumbent and no unresolved alternative rows. Their selected Scour route
   reaches an unexpanded empty normal state. The forced incremental refinement
   fallback returns before consulting that selected fringe. Delayed action
   obligations remain open (384 Ring, 512 Amulet). This is the earliest reproduced
   shared owner and selects the one repair experiment.
2. **Admission resources before useful assembly.** CB07/09 report native
   `max_owned_bytes` during admission under the 1 GiB solver request. Their
   recorded retained-memory peaks do not identify the refused scratch reservation:
   `CalcContext::require_reforge_scratch_bytes` can refuse memory before allocating
   it. No redundant-byte or cap-scaling claim is established. CB05 preserves a
   policy but loses the required named-stop classification. These are separate
   unresolved limits; a longer time allowance does not resolve the memory stop.
3. **Strict continuation and partition size.** CB04 spends about 181 seconds in
   extraction, with 13,741 selected kernels, only four alternative kernels and no
   completed first partition. CB10 hits its strict-state cap. These later limits
   do not supersede the earlier cross-family no-policy failure. Repeated scanning
   of selected-closure byte estimates is a code lead, not measured avoidable work.
4. **Ordinary work allocation.** CB03/11 use the finish allowance without strict
   proof. CB03 records many tiny steps and Bellman reconsiderations, but counts
   alone do not establish repeated compatible semantic work. No completion cache
   or diagnostic handoff is selected on that evidence.
