## H1 — Give the existing finder an executable conditional control representation

**Deliverable:** a minimal finite control graph inside the finder/compiler interface, using existing native conditions and ordinary strategy output.

Required constructs:

```
Test(native predicate, true successor, false successor)
Run(native primitive or supported bound program, continuation ports)
GoalTerminal (owned by request-bound assembler)
FailureTerminal (allowed in proposals; positive reached mass rejects)
Hole (search only; cannot enter checking or output)
```

Persist actual control in graph nodes. Share no probabilistic value merely because two role features match. A minimum positive fixture must make two different *nonterminal progress outcomes* select different next native operations. A final-goal check versus retry does not satisfy this criterion.

Add exactly one native program family through the existing option/program compiler owner. Its setup, conditional steps, retry semantics, prices and cleanup must survive. Use complete native program specification/provenance to permit mandatory dependencies; never globally admit dependency-only primitives or blindly concatenate an option's primitive list. If the family cannot be faithfully bound, report the specific source/contract gap.

The emitted graph must demonstrably require this representation: more than the old two-operation limit and at least one tested partial-progress guard. No new public strategy language, generic scripting VM or all-purpose framework is selected.

**Done:** independent native evaluation agrees on a small complete program fixture; removing a guard or setup produces the intended rejection/change; two numerically different goal bindings are represented without value sharing. The representation has a real caller before further scaffolding is added.

## H2 — Search the representation, not a fixed list of primitive loops

Separate live frontier, immutable candidate history/dedup identities, completed check outcomes and best checked artifact. The beam bound applies to live retained proposals, not permanently to every candidate ever generated. The checker-attempt limit, native cumulative work, wall budget and memory are separately enforced.

The proposer must:
- fill actual control holes and bind native operations/predicates;
- permit incomplete combinations before any local economic improvement is known;
- construct at least one deeper child/grandchild lineage;
- deliberately preserve useful partial progress where the selected native program allows it;
- route every failure through an explicit complete continuation or leave the candidate incomplete;
- use check outcomes to drive a declared next expansion/selection opportunity, rather than only update a scalar winner and stop.

Keep handcrafted deterministic ranking. Initially retain the current nominal live-width/check limits as a controlled starting point, with at most one documented calibration if richer grammar demonstrably needs it. Increasing them alone is not an implementation result. No model training or broad tuning grid.

**First family selection:** native progress-retaining acquisition → supported completion/protection → paid recovery. Choose a small existing native family whose contract is available on A3/B3, not a base-name rule. A valid detailed fixture may use staged cleanup or preservation; it must not simply alternate Chaos and Annul blindly again. The native descriptor/program source, not guessed PoE rules, determines legality and scope.

**Done:** from the original root, without legacy solving or an archived controller seed, two heterogeneous development contexts reach independently checked conditional candidates. At least one requires different responses to incomplete goal progress. A supplied fixed graph may be an expressiveness oracle, but generation must not read its node choices.

Preserve Current's stronger known results and distinguish final delivery from first cheap fallback. Do not pad an exhausted finder to four minutes to appear anytime. Return a named exhaustion/cap/finish status without an optimality claim.
