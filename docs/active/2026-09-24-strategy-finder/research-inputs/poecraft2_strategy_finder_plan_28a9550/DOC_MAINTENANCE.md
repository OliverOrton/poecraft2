# Documentation and research integration

## One current record, one implementation map

Create one living programme record for the finder and one short HANDOFF. Import the supplied direction/research once, preserving provenance. Do not copy the full packet into every canonical page. Do not edit generated research state by hand.

Use existing research questions/claims if their propositions match. A new experimental search algorithm or API does not need a new theorem ID. Where a theorem is used, preserve its preconditions and proof once; fixture passes do not discharge broader native validity.

## What not to carry forward as current truth

The old giant-function audit contains approximate then-local counts, not current static analysis. Earlier negative micro-reuse experiments do not prove heuristic role guidance ineffective. The N2 graph's0.04439% improvement is a diagnostic result, not an ordinary deployed lane. Historical wide-profile Ring/Bow figures do not become product baselines. Current knowledge lint checks traceability, not all runtime mathematics.

## Implementation handoff format

Keep HANDOFF short: source/checkpoint, actual supported mode, next dependency, tests and known failures, active artefact locations, and no-push status. Put detailed theory in its canonical owner and experiment details in the living record. This keeps a newly started implementation model from relying on obsolete chat memory.
