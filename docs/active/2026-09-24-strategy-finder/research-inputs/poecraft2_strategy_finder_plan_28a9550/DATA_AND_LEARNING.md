# Data, heterogeneous roles, and the learning roadmap

## 1. The model we own is valuable but not uniformly cheap

Native one-step mechanics and macro construction can label selected examples exactly under their supported native/numerical contract. They do not imply that enumerating all outcomes, all states or all macro bindings is cheap. A primitive simulation, full exact outcome enumeration, a state-local macro kernel, and a whole-controller check are different workloads. The latest ~45-second candidate service is inclusive and cannot be equated with one transition label. [R03–R04, R06, R10–R12]

Existing natural-T1 tooling chooses deterministic native-feasible targets, records its acceptance/rejection funnel, and assigns entire strata to development/validation/frozen test. It is not an arbitrary-item generator or a strategic optimal-Q dataset. Reuse its cases, semantic validation, identities and partition machinery. Do not overwrite canonical corpora or their historical receipts. [R16]

## 2. Four data tiers

| Tier | Examples / labels | Cost and interpretation |
|---|---|---|
| D0: descriptors | native families, tiers, side, actual cost keys, supported program shape, applicable feature schema | usually cheaper than distributions, but synthesis/preparation still measured |
| D1: complete native selected law | legal/supported status, every joint outcome, resources, expected macro primitive count, native progress/loss | full enumeration can dominate time/storage; exact for this context, not a strategic value label |
| D1s: sampled trajectory | concrete native sampled outcome, action count, elapsed/stopping cause | sample label only; no zero-probability inference from non-observation |
| D2: candidate/check | complete/proper status, request-bound original-root cost, incumbent comparison, checker/build expense and failure reason | expensive but strategically relevant; feasible-policy value, not optimum |

D1 and D1s must never share an undifferentiated `exact_outcomes` field. Missing support is unknown, not an empty distribution.

Record time/bytes for setup, cached/cold descriptor/law access, candidate construction, checking and serialization. Report medians, high quantiles and failure/cap rate by action family and support size, not one average “examples/second.” Estimate a larger dataset only from a representative mixture including failures and cold work. No millions-of-labels claim follows from Simulator actions/second.

F4 uses existing reports first plus a bounded stratified calibration batch only for missing categories (up to 128 descriptor/law requests initially, at most 32 expensive new macro requests, with the SAME declared aggregate test budget). These are maximum diagnostic requests, not a requirement to generate that many costly kernels. Candidate labels come from the real search; do not repeat 45-second checks merely to fill a count.

## 3. First feature representation

A record has three blocks, all keyed back to its actual source:

**Goal-role set (at most the current native slot limit):** side; desired native tier threshold; absent/below/satisfied status; satisfying and below-tier weight summaries with available-mask; tier-count/vector reference; fixed/crafted/fractured status; required-count contribution; relevant native tags and blocking relations.

**Item/control context:** rarity; counts and open slots by side; non-goal and below-tier occupancy; active locks/filters/crafts; fractured information; influence/Eldritch state; artifact/session/level; actual programme stage, offer/checkpoint presence and supported-domain flags; goal-debt and suffix/prefix completion context. Do not replace a persistent field with zero when absent from the exporter.

**Candidate/program context:** native family and parameter references; targeted/preserved roles; ordered setup/attempt/cleanup; cost and execution-count features kept separate; intended return/stage structure; known compatible tail information; graph size/checking-cost predictors; proposal lineage and stage of available information.

Variable tier lists should be preserved in native metadata and can use padded+masked vectors, summaries or shared set encoders in ML. Different numbers of tiers are not a failure of the representation. Different denominators and competing pools remain informative; the target's weight alone is not success probability.

Include role-to-role relationships (same side, blocking/exclusion, competing targeted action observations) where the native metadata supplies them. A simple flat feature vector is acceptable for the first handcrafted/GBDT interface. A Deep Sets/attention encoder is a later way to obtain permutation-aware generalization, not an initial dependency. [P06]

## 4. The exact permutation and the approximate transfer are different

Reordering the request's goal records while also reindexing every slot-based action/condition is a bookkeeping permutation: corresponding ranking outputs should reorder consistently. This can be tested.

Replacing a cold family by a differently weighted armour family is NOT that symmetry. The feature model can learn a related construction preference, but native probabilities and evaluated policy values remain binding-specific. Do not sort away the numerical parameters or build a backend cache keyed only by goal counts.

Keep an exact physical/control record or stable resolvable reference alongside the role features. Report feature collisions with different native labels. Such collisions can be intentional approximation; they are not permission to merge the targets, and model uncertainty should reflect insufficient information.

## 5. Label integrity

- A completed controller value is `J_pi(problem)`, not `V*(state)` and not an optimal action label.
- A lossless native one-step row is a transition label, not an exact Q value unless its entire continuation is specified.
- A failed/timeout/capped build is computationally censored, not proof of an expensive or impossible strategy.
- A semantic refusal is separately tagged (e.g. uncovered branch or invalid observation); it is not mixed with runtime exhaustion.
- A smaller original-root candidate cost is meaningful only against the compatible frozen/current incumbent context and original prices.
- Imprint, economic Restart, start rarity and different root items are distinct problem features. No merging across these by a base-name key.
- Retain negative and rejected candidate records, not just winners; otherwise the ranker never learns which plausible proposals wasted its budget.
- `predicted_cost`, `sampled_cost`, `native_policy_cost` and `certified_lower` are distinct typed fields.
- Cost/count rewards and construction/checking seconds are different units. Optimizing checker throughput cannot silently become the crafting objective.

## 6. Splits and leakage

Existing A/B six-case research targets are development/exposed tests, not new held-outs. Use generator roles and new predeclared untouched strata for validation/frozen testing. Split by request/base-family/goal-family and derivation lineage, not random row. A candidate and its tiny edits, a graph and all its physical entries, or relabelled/permuted siblings must not straddle folds. Repricing variants and held-out numerical parameter ranges should be explicitly grouped or separately declared generalization tests.

Do not expose node IDs, old strategy hashes, case labels or whether a fixture is the known winner as semantic input. Retain those only for audit joins. Source-value discrepancies must be aligned to the same controller before becoming calibration labels. A 4000× root discrepancy is not a universal correction factor.

## 7. Learning sequence and its gates

**L1 — No model:** produce a functional native finder, handcrafted ranking and bounded complete candidate labels. Compare equal end-to-end budgets. This is F0–F4.

**L2 — Small supervised ranker:** after data show repeated decisions with both successful and unsuccessful completions across distinct requests, compare a regularized simple/pairwise or GBDT ranker with the fixed heuristic and a simple uninformed control. Freeze feature schema and train/test split. Keep candidate grammar and checker allocation comparable. No automatic dependency installation selected by this packet.

**L3 — Small role-aware neural model:** only if representation/cardinality/generalization evidence exceeds the simpler model's capacity and enough distinct labels exist. Measure in-solver batch inference plus feature construction. The learned component ranks proposals or predicts strategic/checking outcomes; it does not supply native transition authority.

**L4 — Expert iteration:** collect new search/evaluator feedback using the improved ranker, retain exploration/negative data, and retrain offline in versioned rounds. A stronger planner is the teacher of feasible strategies, not an omniscient optimal-value oracle. ExIt is useful precedent, but its Hex results do not establish this SSP's performance. [P05]

Full offline RL is deferred: even with a native model, bootstrapped out-of-distribution values and unavailable labels are meaningful issues. CQL is evidence for the problem and one conditional approach, not a source of native-certified lowers. Its reward lower-bound language must not be imported into this cost-minimization proof system. [P07]

A training run earns no product promotion from lower loss alone. The gate is better checked-policy cost versus time/work on untouched requests, with unchanged numerical/semantic checking.
