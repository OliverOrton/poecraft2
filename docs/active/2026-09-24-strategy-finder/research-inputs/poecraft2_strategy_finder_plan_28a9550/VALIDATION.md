# Validation and experimental acceptance

## 1. Mandatory native contract matrix

| Test | Required result |
|---|---|
| Wrong-goal zero-action SUCCESS; weakened tier/rarity; omitted goal guard | request-bound checker refuses even if graph's own success mass is 1 |
| Easier partial root or changed persistent context | original-root identity mismatch/refusal |
| Unpriced/disabled operation or dependency promoted to independent action | native scope/pricing refusal |
| Rare positive-mass failure, unhandled output, action not applied | not accepted; no renormalization or sample-based zero |
| Same features, different weights/blockers/flags/tiers | backend keys remain distinct; laws/choices may differ |
| Goal-slot permutation with indices remapped | same semantics and corresponding search output on controlled test |
| Crafted/fractured status, Eldritch, extra/below-tier affix, opposite-side constraint | native context retained, not ordinary-default substitution |
| Mandatory macro interior / choice timing | programme cost and every observation remain intact |
| Finite try-once stage vs recurring router | different expected values where appropriate; control represented |
| Globally improper cycle of locally terminating blocks | refused, including zero-cost traps |
| Partial controller/fake low score/fake certified flag | cannot become `CheckedPolicyArtifact` |
| New cheaper incumbent during suspended old check | adoption compares current compatible winner, not stale donor |
| Price/artifact/model/goal/mode change during invocation | frozen current request; stale work rejected; next request separate |
| Cap before row/candidate commit, checker timeout | previous checked result survives, failure censored and charged |
| Cancel/Finish in seed, build, check, publication, export | actual owned work released; no early acknowledgement/no half-published candidate |
| Default/old options, unknown mode, unavailable WASM capability | legacy default retained; unknown/unsupported rejects |
| Finder proof-handoff and per-state exact query | unsupported where absent; no fake lower/optimality result |
| Invalid/NaN learned-score stub | deterministic ranking fallback; checks unchanged |

Use existing native action/compile/evaluator fixtures and a few new targeted integration tests. The packet's toy tests are not replacements. A valid stale graph payload must be tested with incompatible context, not only malformed JSON.

## 2. Evidence ladder

Do not collapse these outcomes:
1. Descriptors available.
2. Partial controller constructed.
3. Complete emitted candidate.
4. Independent original-target native checking succeeds.
5. Checked candidate is cheaper than the compatible reference.
6. From-root finder discovers it within the actual budget.
7. Actual source-matched Calculator run delivers it.
8. Generalization beyond development cases.

An offline saved-seed success reaches at most the appropriate checking/economic step. A synthetic complementary-choice fixture establishes expressibility, not native economic improvement.

## 3. Comparison arms

**Primary:** current solver versus standalone heuristic finder, same exact original problem, original prices, action/program scope, resource profile, native build/platform and wall envelope. Algorithm/config identity differs intentionally.

**Ablation:** finder heuristic versus simpler/uninformed ranking with the SAME candidate grammar and maximum checking budget; record actual candidate cost/work, not merely equal counts. Later learned ranker uses this same interface and frozen held-out split.

**Seeded-repair diagnostic:** may load a saved checked graph to test code, but keep separate from from-root arms; account acquisition/checking time when reporting a combined runtime.

**Later portfolio/hybrid:** not part of initial default. Two lanes each receiving a full budget is not an equal-budget portfolio comparison.

All online compute counts: request resolution, context creation, descriptor enumeration, features/model inference, speculative laws, compilation, check, failed attempts, retention/export. Report offline training budget separately and model digest. Memory includes parent/child/checker/model/beam simultaneous storage; per-check limits do not create extra allowance.
