## 2. Audit of the advisory note

Its central caution is correct: failure to amortize one bucket/exclusion template
is not a refutation of heterogeneous decision-structure reuse. Nor is it positive
evidence that the latter is large. The cost and repetition of the proposed later
work have not been measured in the G0 receipt.

The source does NOT universally expand every non-self successor of every complete
reforge. `append_sparse_row` initializes `enqueue_fringe = !focused_mode`, suppresses
repeated shared-kernel fringe insertion, then enqueues nonself successors where
applicable. Queue identity deduplication is another layer. In focused mode, the
selected-policy fringe is collected later, using lower/upper work, quotas and
bounded per-class service. Complete support still exists in its native
representation; work scheduling may defer its expansion. [R6, R9–R10]

Consequently the pipeline has distinct populations:

| Population | What it establishes |
|---|---|
| Native outcomes/support represented in a complete row | Probability coverage for that action, not expansion of every continuation |
| Interned/discovered state | Identity exists in that calculator namespace |
| Enqueued state | A work obligation is scheduled, not completed |
| `expanded` flag in the outer loop | The state has been popped and its expansion started; inspect row completion separately |
| Complete state/action row or automatic program | Its own law/work completed, not every alternative at that state |
| Selected-policy/verified-policy reachability | Relevance to a specified controller, not all possible better controllers |

The distinction is operationally important: the outer flag/count is set before all
state-local rows finish. A cap can occur while that expansion is in flight. [R7]

## 3. Existing work that the new proposal must outperform

1. Exact preserved-base/action reforge caching already handles wiped-only
   differences. Complete output laws and sidecars remain native. [R15]
2. Identical sparse payloads and successor-effect summaries are already shared,
   with distinct row and priced-variant ownership. Variant pricing is incremental;
   a later candidate is not charged an avoidable full old-variant rescan. [R6, R13]
3. Focused scheduling already groups states by a signature retaining literal goal
   masks, family/blocker/crafted/fractured masks, capacities, influences/Eldritch
   state, four junk-count vectors and goal-member tokens. This preserves diversity;
   it is explicitly NOT state equivalence. A role-canonical diagnostic would be a
   different projection, not discovery that the solver has no grouping. [R10–R11]
4. Large choice-free sparse rows already use a transition-offset-keyed expected-
   value cache (at least 1,024 transitions in this path), with binding-specific
   finite/infinite value handling and updates. Do not propose another identical-row
   dot-product cache. [R12]
5. Candidate-local continuation, selective action service, observed-choice control,
   strict refinement and complete graph checking already have owners. They are not
   replaced by a new sketch interpreter merely to count role shapes. [R16]

Thus a naïve “same goal count -> reuse Bellman answer” is wrong, and a naïve
“same loop shape -> faster” is unproved. `cost + dot(probabilities, values)` is
already one shared implementation. New computational reuse must omit a measured
repeated construction or safely represent repeated subexpressions—not just call
that same routine through an additional wrapper.

## 4. Selected question

For actually served native work after outcome generation, are there repeated
multi-action or multi-state continuation computations whose shape can be obtained
once and rebound to unequal native goal assignments *before* the expensive
structural operation is repeated?

The initial task is a work-weighted, stage-aware recurrence study followed by
ONE guarded native pilot if warranted. It is not an unlimited search for a good
signature and not a mandated cache implementation.

A useful family must establish all of these:
- two or more genuine unequal native bindings in an observed computation domain;
- an identifiable repeated structural operation after existing reuse;
- a cheap pre-work guard grounded in native action/observation dependencies;
- full inverse action/state/resource/port mapping, and actual coefficient input;
- enough real recurrence, including the later phase, for measured break-even;
- a result consumed by the existing search/evaluation owner.

If frequency exists only among unserved frontier states, report a *potential*
future domain, not current saved computation. If the repeated cost is retrying the
same incomplete binding or rebuilding the same generation, report that separately
from cross-binding reuse. If the cost is mostly independent weighted output, say
so. The programme cannot turn one of these facts into the desired answer by
renaming it.

## 5. What larger symbolic methods suggest—and do not establish

SPUDD performs Bellman operations over a factored ADD representation, sharing
identical subfunctions rather than merely counting similar state descriptions.
Its discounted-MDP convergence argument and its assumed factored transition input
are not the native SSP contract. Its relevance is methodological: genuine
structure sharing must survive the numeric operations. The paper does not justify
an ADD rewrite or promise speedups for heterogeneous poecraft2 rows. [P1]

Parametric Markov-model work separates a common symbolic structure from its
instantiated coefficients and explicitly treats graph-preserving parameter
regions. If an edge vanishes or the legal menu changes, the structure may require
new guards or a different specialization. This is the appropriate analogy for
unequal tier/weight bindings, not scalar value equality. [P2]

Relativized options are precedent for relative policy schemas and context-dependent
transformations. Approximate transfer is not an exact native-law proof. A copied
schema must either have a justified specialization or remain an untrusted proposal
checked by the full native controller evaluator. [P3]

BRTDP is a reminder that complete transition semantics and selective work are
compatible when suitable statewise bounds/policies exist. The native code already
has its own focused search, so “add focus” is not selected. Its statewise fallback
premises also rule out substituting a root-only policy scalar at arbitrary exits.
[P4]

None of these sources proves that the current downstream workload has a compact
representation. That is the central native evidence gate, not an obstacle to be
assumed away.

## 6. Capability and structural outcomes

Prefer an existing-owner continuation construction/decision-region plan where
substantial structure is repeated. Numerical symbolic ordering or selection-graph
reuse is a secondary mechanism only when its actual setup cost is large enough.
Do not choose it because every matrix has a sparsity pattern.

Keep a familiar expensive row as an explicit boundary when necessary. This pilot
need not eliminate the first reforge distribution to improve later work. Conversely,
it must not report that distribution's creation cost as saved when it is unchanged.

A new symbolic all-state solver, global response cache, global graph-isomorphism
search, approximate merge, family-average value, new greedy successor filter or
role-diversity scheduler is outside this programme. If the measured opportunity
needs such a fundamentally different mechanism, return a precise separately
costed design decision.
