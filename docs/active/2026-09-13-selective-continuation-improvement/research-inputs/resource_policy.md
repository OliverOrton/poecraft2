Reuse the already derived requests and native activation rather than constructing a fresh world or interpreting `long240` in a case filename as its effective timer.

Do not assume a parent resource increase reaches every child owner. Do not loosen epsilon, numerical acceptance, full mass, price, observation or terminal checks.

## Authorized targeted follow-through

1. **400M shared reforge work at the same clock/memory** is selected when the actual candidate loses its opportunity to cumulative work exhaustion. Preserve a current-main control at the same allowance when claiming code improvement. This is not 400M per child: all child/evaluation work remains cumulatively debited.
2. **900-second requested finish / 1140-second native / 1170-second outer** is a conditional time-only diagnostic for a materially advancing selected candidate. It is not a mandatory fifteen-minute cohort. If a fixed candidate is completely evaluated and expensive, stop; more time will not improve that fixed policy.
3. Raise memory or a different state/pair/output cap only after a new named refusal and safe host admission. Existing 8-GiB / 4-GiB is not a permanent ceiling, but the last Ring protection problem did not demonstrate a RAM shortage. A 16-GiB aggregate / 8-GiB checker/28-GiB reservation must fit actual physical and commit pressure before being considered. Do not force swapping or assume the earlier machine's free memory still exists.
4. Preserve old profiles as separate default/product evidence. A capacity-only gain is useful and must be labelled; it is not a same-resource algorithmic result. User authorization to change caps is not authorization to change prices, goal, action restrictions or failure semantics.

A candidate's 9.14M limit in the last receipt is its inherited remainder of 200M, not the top-level request. Telemetry should report initial/global allowance, used-before-candidate, candidate-used and remaining. A failed allocation can be refused before appearing in peak retained memory; keep requested scratch and actual ownership distinct.

## One batch, not one model turn per job

Current AGENTS already requires deterministic long waits, typed preflight and batching. Preserve that implementation. Timed jobs, builds and sampling remain serial unless concurrency itself is the declared treatment. The model selects the independent batch and returns for its compact result or a genuine adaptive decision, not a 30-second status check.

Use existing runner preflight before expensive work: compiled artifact, target/economy, native flags, selected mode, all effective limits, binary identity and typed values. New programmatic watchdog values use the existing canonical floating representation. Do not edit old receipts or waive strict mismatches. The existing reporter does not automatically enforce every bounded-cost and stop-contract regression: add small explicit checks over its results.

Reuse retained input/metadata and independently verified results only under their real compatibility contract. A bundle does not restore a live solver; a candidate checkpoint is not automatically a cross-version cache. No new orchestration service, session-cost dashboard or full strict checkpoint programme is selected.
