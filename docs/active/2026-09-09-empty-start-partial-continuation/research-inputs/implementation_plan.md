## 1. The goal and the correction

Make useful partial-item knowledge improve an actual empty-start five-goal solve through the existing carrier ladder and proof owners. Pursue exact closure; demonstrate the connection before calling another partial-item improvement an empty-start success.

Oliver's intuition is correct: the value of a state is the cost of completing the same requested craft from that state. Improving such continuations can improve predecessors and ultimately the empty root. The current issue is not that partial-item work is inherently irrelevant. It is that some newer proof capabilities are attached to the external starting-item preparation, while executable continuations, current search states, retained incumbents and strict proof have distinct ownership and coverage.

Do not replace the ladder. Do not build a permanent fragment library. The required flow is:

```
empty-start request, original final goal and full caller scope
  -> actual partial states encountered by the existing search/proof
  -> compatible lower evidence and/or executable continuations
  -> complete predecessor action/choice relations
  -> ordinary ladder assembly and lower propagation
  -> retained policy snapshot and strict proof
  -> compiled, independently evaluated root result
```

Intermediate accomplishments are checkpoints, not programme completion. Continue through root propagation, a causal comparison, and one measured follow-through on the remaining obstruction. Do not stop after adding telemetry, fixing one snapshot fixture, building a donor, or raising a local value.

Use Codex `/goal` if supported by the current client. Set the outcome in `goal_prompt.txt`; this file is the governing detailed plan. A goal may pause on actual permission, environment, usage or owner limits. Do not mark it achieved when the outcome remains unmet. - a new valid exact closure of the primary empty-start request within its unchanged declared resource envelope;

- at least 20% less end-to-end time to the same predeclared verified policy/gap target, with no weakened lower, scope or correctness contract;

Preserve that result honestly and perform the measured follow-through rather than relabeling it. If no supported route meets the root goal within available resources, finish with a coherent checkpoint and a specifically falsified/blocked goal; do not pretend the task succeeded or keep launching identical runs indefinitely.

## 5. Mathematical contract for reusing partial work

### 5.1 The subproblem is the same completion problem

For a semantic partial state `s` (item plus necessary checkpoint, program position, observation and retry restrictions), reusable final-goal evidence has the form:

```
L(s) <= V*(s; original final goal and caller scope) <= J_pi(s).
```

Past expenditure is sunk: continuation cost starts at `s`. Mandatory setup still owed by the calling action is not sunk and must be charged exactly once. A separately solved partial fixture is reusable only after its semantic mapping is established. Do not mix root IDs, same-looking items or current prices from different requests.

A subgoal-only policy stops too early to be an upper for the final goal. A subgoal-only lower is usable only with an explicitly optimistic terminal/action/policy relation. In this project's junk-free semantics, deleting some requested requirements while keeping a new junk-free test may reject full-goal items; that is not automatically a relaxed terminal set. Prove the inclusion instead of assuming 'fewer goals' is always easier.

### 5.2 Propagate lowers through every branch and alternative

For a complete native predecessor row:

```
lower_Q(s,a) = c(s,a) + sum_t p(t|s,a) * L(t)
```

is an action lower. A state lower must cover the minimum over every permitted competing action, using complete exact/optimistic rows, valid family floors or true inapplicability. Unsupported successors retain an independent safe lower, not omitted mass. Missing families do not vanish.

Use the existing finite-region/quotient proof when dependencies are cyclic. Do not sum independently priced 0-to-3, 3-to-4 and 4-to-5 optima. Actual actions can destroy progress, and favorable branch conditioning changes probabilities and recovery cost.

Improving `L(t)` by `delta` changes a fixed complete row's RHS by `p(t|s,a)*delta`; the root can remain unchanged while another action still owns the minimum. For observed-choice groups, the post-observation minimum must also be recomputed.

### 5.3 Compose upper witnesses, not just upper numbers

A proper continuation from `t` can be connected to a prefix reaching `t`, provided every positive-probability prefix outcome receives a compatible executable continuation and the combined controller is proper. Preserve program/observation memory. Two individually terminating options can form a nonterminating cycle when composed.

Reuse normal ladder row completion, policy assembly, compiler routing and independent evaluation. A copied value or a count-matched vector extension is not an executable continuation. Lower improvements do not magically synthesize an upper.

### 5.4 Construction anchor and certified domain are different

Inspect whether the current prepared potential proves values over an unfractured subdomain under the original full scope, with correct first-exit handling for other fractures, junk, filters and restore states.

If that proof already covers a requested state, construction from another exact anchor need not imply the actual run has taken that anchor's path. The certificate must explicitly prove this; constructor success alone is insufficient.

If the proof only applies after a specific reached fracture, reuse it there and propagate through complete preceding alternatives. Do not force the real policy to fracture in order to make the proof useful. A route avoiding those states must remain in the lower comparison.

### 5.5 Scope-correct data flow must be durable

A compatible lower increase should invalidate or refresh the affected lower-row caches and proof queries through existing generations/dependencies. Preserve old independently valid lower witnesses where their identities remain valid. Do not conflate changing an estimate with invalidating a fixed executable policy. Semantic row, action, price, member-domain or control-state changes do require their respective revalidation.

Every proposed native transfer must satisfy the existing complete-member guard or remain exact-keyed. Never broadcast a representative's large lower to an entire class.

The accompanying `mathematical_delta.md` supplies arguments and counterexamples for integration into existing chapters. It does not register new accepted claims automatically.

## 6. Implementation sequence

### A. Repair demonstrated continuation ownership on the root path

Trace the selected policy from ordinary ladder assembly through incumbent retention/restoration to strict lift, starting with the primary 0-to-5 run. Use the known 3073/2882 witness as a small reproducer for the shared mechanism, not an assumption about the user's run.

Classify a missing partial entry as:

1. **Lost compatible evidence:** it belonged to the same validated candidate/dependency snapshot and was discarded or omitted.
2. **Newer/different evidence:** it belongs to a later candidate or different scope/generation.
3. **Genuinely unavailable continuation:** no completed compatible selected row exists.

Only case 1 is directly fixed by preserving ownership. Case 2 needs explicit compatible extension or a newly evaluated candidate; case 3 must return to the existing continuation work owner.

Prefer existing immutable/shared row evidence, correctly indexed semantic snapshots or bounded deltas. Account for retained capacity, temporary copies and coroutine lifetimes under current caps. Do not simply copy the entire growing graph, resize policy arrays with current-greedy values, or remove the strict mapping guard.

Keep resource failures distinct. Ensure cooperative and synchronous fallback paths preserve the existing selected-row and exact alternative contracts. Reevaluate the actual returned graph after candidate changes.

Qualify the old-code negative and one current-run root trace. A snapshot repair is a checkpoint: continue to the next blocked consumer rather than ending the programme there.

### B. Admit useful partial lower work within an empty-start solve

Separate **unsupported initial request** from **no later compatible proof query can ever exist**. The current once-only preparation guard must not become a global 'never try partial evidence' result.

Choose the smallest justified route after the baseline:

**Route 1 — query an already valid broader domain.** When the current potential's jointly checked unfractured region truly covers root/partial entries under the original scope, expose that domain through a typed query/constructor contract. Retain full revalidation, unsupported exits and input-specific eligibility. This is not deleting `fractures != 1` and hoping the old proof survives.

**Route 2 — prepare from a relevant reached partial entry.** If valid evidence requires a concrete anchor, request it at a root-relevant partial state encountered by the existing ladder/proof. Build one run-local view using the original final goal and scope, then reuse it over every proved-compatible entry in its domain. Don't perform a full independent solve or a 25-second preparation for every state.

**Route 3 — add the smallest unanchored projection actually needed.** If the run's minimum-owning paths never enter the existing domain, prove a native-valid unfractured first-exit model by reusing the current probability/proof owners. Keep genuinely unsupported fracture outcomes on independent lower boundaries. Specialize only a measured blocking distinction; do not generalize every fracture/filter class upfront.

Prefer Route 1 if its proof is already available; otherwise Route 2; Route 3 is an authorized follow-through when the prior routes demonstrably miss the real root population. The choice is evidence-driven, not a requirement to implement three architectures.

Admission is by query relevance and current proof need, not by goal-count alone. Reuse or extend existing obligations/queues; no permanent library, external service or second planner. Initially allow one live extra prepared view; increase only after measuring reusable benefit and accounting total ownership. Use the existing proof sub-budget and total solve cap. Do not add a new user-facing collection of tuning knobs.

No unbounded preparation from `completion_proof_lower_value()` or another hot lookup. A query can return current safe fallback and request bounded cooperative work through its existing owner. Check cancellation between safe units and preserve fallback when preparation cannot finish.

### C. Make the new evidence reach predecessors and the root

After a certificate is installed:

- perform exact-key/uniform-domain lookups through the existing proof manager;
- notify existing reverse dependencies or mark affected lower queries dirty;
- recompute complete predecessor action/choice lower expressions;
- preserve valid placeholders for unmaterialized actions and every residual family;
- propagate within the existing cyclic lower query or existing bounded Bellman envelope, not only one root-row refresh;
- apply maximum composition with other independently valid native lowers;
- refresh relevant strict alternative margins against a genuinely compatible continuation upper;
- report the resulting change to the root result, candidate ranking or valid retirement.

The supported native relation is required at every abstract row being lifted. A current search-state count and matching scalar are not enough.

If the contribution is consumed but the root minimum does not move, retain the exact blocking action/family and its value ceiling. Refine that owner only when the work could change the root. Do not present successful transport as successful exact closure.

### D. Make upper continuations flow through the same existing ladder

Use the completed ordinary rows and preserved candidate snapshot to assemble better final-goal policies from partial states. Keep this separate from lower certification while sharing compatible identities/evidence where the current owners permit it.

If a useful partial policy is known but never offered to joint assembly, repair that specific handoff. If it is offered but rejected, identify legality, missing exit, properness, observation, pricing, member-domain or stale-snapshot refusal. Generate missing run-local continuation through the ordinary ladder when justified. Do not insert historical strategy files as search seeds.

For a trial deviation, an exact fixed-policy continuation value is upper-side evidence. When it improves the incumbent, construct and reevaluate the combined strategy. It does not retire all competing actions by itself.

Retain the best already verified root strategy when a later optional proof/refinement attempt runs out of budget, using existing publication authorities. A raw incomplete graph is never that fallback. Do not let new proof preparation consume so much time that no completed artifact can be returned within the pinned watchdog.

### E. Obtain early useful certificates without discarding the user's solve budget

The existing checked-subsolution endpoint demonstrates a sound distinction between native-valid feasibility and auxiliary optimum. Use it where needed, but do not hardcode the anchored test's threshold 280 as a universal policy.

Prefer the cheapest complete certificate that can improve the requesting consumer. Candidate selection or scheduling is heuristic only; final native coverage/minimization/checking still supplies authority. Reuse the existing preparation budgets/step boundaries. If full preparation is too expensive, use a fully checked checkpoint, defer preparation, or fall back; never use an unchecked partial vector.

Record total preparation, incremental work after first useful evidence, wall time to first verified root policy, and finalization separately. Reuse proven value-independent support; rebuild value-dependent minima and allocation for every accepted vector. The rejected projection-lookup cache and completed numerical/coverage optimizations are not reopened without changed evidence.

With partial evidence now reaching the empty root, inspect the surviving cheapest alternative, missing continuation, strict frontier, policy publication refusal or finalization bottleneck.

Authorize at least one further discriminating implementation cycle on that owner. This may be a narrow retention/probability refinement, a proof-consumer correction, or a missing executable continuation. It is not permission for another generalized solver, learned system or speculative portfolio.

## 8. Focused correctness and causality fixtures

Reuse and extend decisive fixtures. Do not write a new generic testing framework.

1. A partial completion lower raises a predecessor through weighted complete outcomes, including a destructive/reset branch.
2. Another cheap alternative pins the root; raising the non-minimizing branch alone is not claimed as root progress.
3. A two-state retry/recovery cycle propagates correctly and agrees with the existing tiny rational reference.
4. A partial policy is executable only after a control/observation state; reuse at the same item with different memory is refused.
5. An original five-goal terminal would fail a naively truncated junk-free subgoal predicate; the invalid relaxation is rejected.
6. The initial empty request cannot prepare the anchored producer, yet a later relevant partial query can supply a valid current-run certificate without restarting the whole solve.
7. Querying a proved unfractured domain is separate from changing the actual start to a fabricated fractured item; unsupported alternative exits remain covered.
8. A missing incumbent entry caused by lost compatible evidence succeeds after repair; a truly new/unvalidated state still refuses or schedules ordinary work.
9. Updating a lower refreshes the necessary predecessor/query generations without invalidating unrelated fixed-policy evidence or using stale probability allocations.
10. Source/class collisions, changed prices/goals/scope, unsupported junk/filter members, canceled preparation and memory refusal preserve safe fallback.
11. Upper composition has complete stochastic exits and global properness; two locally proper continuations forming a non-goal loop cannot publish.
12. Existing verified root artifact remains available when optional later proof work is interrupted; unverified candidates cannot replace it.

Synthetic examples prove the fixtures' mathematical distinctions only. Native tests establish the specific implementation contracts. Neither substitutes for the empty-start acceptance run.
