# Gate 7 — Proof Consumers And Action-Envelope Reduction

**Status:** passed on 2026-08-25. Gate 6 proof values now have two explicit
consumers. No ordering value or executable-planner estimate gained proof
authority.

## Retained consumers

`identity_clean_mdp` is now available through the ordinary completion-proof
API for states that retain the start carrier's exact protection, Fracture,
junk, influence, and Eldritch identity. A changed identity falls back locally;
generic-clean states retain the existing clean-pattern owner. This makes the
fixed-identity value participate in focused fringe gaps and independent lower
composition without changing executable-policy authority.

Unmaterialized primitive and automatic obligations may now close as
`incumbent_dominated` in `ActionEnvelopeLedger` when all of the following are
present:

- an exactly optimized, proper restricted-policy upper for the same carrier;
- a complete immediate-price authority (one primitive or the exact automatic
  option resource vector);
- that action's proved may-survive/reach successor pattern; and
- a strict lower-greater-than-upper separation including the configured
  numerical tolerance.

Authored conditional fixed programs remain excluded because their production
operator lower still charges only the guaranteed first step. A successful
descriptor proof retains the exact carrier/operator identity and named ledger
authority, uses no row index, and removes only that obligation from scheduling.
It does not create an executable row, renormalize an outcome, close an unknown
family, or turn a restricted optimum into a public lower.

## Qualification

On the fractured owner four-to-five case, the identity consumer was selected
2,310,673 times. It reduced exact work from 40,676 to 40,670 rows and from
119,861 to 119,852 transitions while preserving the independently evaluated
upper, compiled graph, and policy hash.

The required observational descriptor prototype then found 79,799 strict
separations among 96,105 unmaterialized obligations with certified carrier
uppers. Production integration reproduced all 79,799 separations and changed
the requested action envelope as follows:

| Measurement | Gate 6 | Gate 7 |
| --- | ---: | ---: |
| Remaining action envelope | 109,100 | 29,339 |
| Ledger `incumbent_dominated` | 139 | 79,938 |
| Ledger `unresolved_named_stop` | 102,775 | 22,976 |
| Evaluated upper | 2,698.8747960143623 | 2,698.8747960143623 |
| Compiled graph | 215 / 563 | 215 / 563 |

Independent exact evaluation still converges with success probability one,
complete cost, zero off-policy mass, and total expected cost
`2698.8747960143623`. The policy hash remains `0651db94d0847a7d`.

The clean zero-to-five run had no certified carrier upper while its descriptor
calls were active, so it recorded zero descriptor separations. It retains the
Gate 6 lower `36.4885317287664`, upper `14454067.42607058`, 514 / 1,788 graph,
and matched independent exact evaluation. Its bounded-wall work window varied
by less than one percent and is not treated as deterministic improvement or
regression evidence.

## Rejected consumers

Two narrower activations were measured and removed:

- adding the identity pattern to the carrier-action Bellman comparison
  produced zero strict prunes on clean and owner controls; and
- activating the authored fixed-program automaton in production operator
  lowers produced zero strict prunes and no earlier verified incumbent.

Both changed bounded scheduling without reducing work. Their reports remain
in the raw experiment directory; their source wiring is absent.
