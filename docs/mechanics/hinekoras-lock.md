# Hinekora's Lock

The native Emulator slice previews one complete configured currency request per
paid Lock. The native allowlist is `pc_hinekora_lock_currency_supported`; Lock
consumption is the separate `hinekora_lock` key. Creation reserves the existing
native currency law and marks the original item as foreseen. Unsupported or
inapplicable creation does not sample, mutate or charge. The cached item includes
all numerical rolls, native metadata and item properties within that currency's
existing projection. This inherits each currency's limitations, including the
approved affix/implicit Vaal projection and ignored sockets.

Observing the same configured request is stable and free. Declining preserves
the live foresight. Committing the selected request returns the cached outcome
and consumes both the Lock and the actual currency on their separate events.
A successful use consumes foresight even when every visible field stays equal;
a refused action preserves it. Deterministic Scour/remove-crafted changes can
invalidate it. A different applicable stochastic request refuses while foresight
is live: its distribution conditioned on the observed request needs an unknown
cross-currency joint law. Raw authoring changes invalidate the preview, including
restoring earlier fields after an observed modification. Handle cleanup grants
neither a fresh preview nor a free Lock.

The value-copyable item marker is insufficient information state. Native pool
queries, ordinary Calculator, Current/Finder roots, abstraction, authored
Simulator input, Bestiary operations and multi-item resources refuse foreseen
items. A clone carries the marker without acquiring the original native address
identity. Imported marked items without a matching checkpoint remain unavailable.
No Lock action is admitted to the ordinary solver or strategy vocabulary.

Versioned `fixed-currency-lock-v1` checkpoints preserve an Emulator's already
paid selected outcome and no-refresh record across replacement, reload and
history. They pin runtime hashes, base, level, every real item field and resolved
request. Restore is atomic and does not draw, spend or expose an RNG seed/state.
The public transport validates all live slots, rolls and properties; native
checkpoint storage additionally restores exact unused slot fields. Such imported
editor/history state is not a reachability, probability or exact-policy
certificate. Ordinary solver ingress continues to refuse the information state.

Multicurrency previews, donor-dependent previews and adaptive Lock valuation
remain held. The old free-decline Bellman sketch is not an accepted model.
