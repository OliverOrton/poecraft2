# Configured cluster jewels

Native C++ owns cluster crafting. The frozen catalogue supplies three size
bases, their count bounds and stable passive entries. A configured session
selects base, item level, passive key and total added-passive count; it does not
roll any of those fields. Large admits 8-12, Medium 4-6 and Small 2-3.
Preserved `old_do_not_use` passive variants are not admitted crafting inputs.

The passive key is an identity, distinct from its selector tag. Attack-block
and spell-block Small configurations share a tag but retain different keys and
canonical stats. Session compilation uses `affliction_jewel`, item-level
eligibility and native full-group exclusions. Generic Jewel `misc` and generic
special explicit rows do not enter this configured universe. An unlinked
catalogue notable, such as Pitfighter, never becomes a rollable modifier.

Installed modifier `adds_tags` contribute to the current pool signature in
addition to fixed configuration tags. Ordered generation rows retain first-match
semantics: the Large/Medium size rows precede `has_affliction_notable = 0`, while
Small falls through that suppression after installing a notable. The native
weight and group tables implement the notable restrictions; no name-based cap
or layout shortcut is added. Every draw sees the current installed modifier set.

Transmute, Alteration, Augmentation, Regal, Exalted, Annulment and Scouring use
the existing native ordinary-currency laws, with one prefix/suffix for Magic
and two per side for Rare. Transmute/Alteration use the existing equal one/two
affix law. Annul samples eligible non-fractured/unlocked slots uniformly. The
Calculator enumerates concrete native additions and removals, retaining all
modifier identities through the action; only terminal goal observations merge.
Work-cap exhaustion fails explicitly and publishes no truncated probability.
Caller-selected action and disabled-family scope remain binding.

The configuration survives crafting, Calculator restart, clone, stable export,
import, saved-resource preview and document Undo. Imported explicit sets are
validated through the native editor. Passive count, raw notable/socket/small
index metadata, installed notable affixes and equipment socket fields remain
separate. No allocation or notable-placement algorithm is inferred.

Full cluster completion is pending the [owner review packet and qualification
receipt](../active/2026-10-02-clusters-completion/README.md). Alchemy/Chaos,
Fossil/Harvest and other unqualified currency laws fail explicitly. The proposed
65% three-affix / 35% four-affix rare community model has not been adopted.
Fixed passive-tree socket counts also await the selected owner law; raw canonical
socket indices are metadata, not a count law. Current/Finder, authored exact
strategy evaluation and legacy continuation-row calculation refuse configured
clusters until a compatible exact state and proof contract is qualified.
No old lower/upper/ordering/closure certificate is promoted by these pool changes.
